# fish 系统能力与限制（实测，含 D-1~D-9 清单）

> 编码：企业智能-261022-04 ｜ 类型：fact ｜ 记录于 2026-10-22T04:55:53Z

## 一句话
事件溯源 + 物化投影。写只追加事件，读从投影算，遗忘按类型分层衰减。

## 记忆类型与衰减（**数值以 `fish.py config list` 为准，不要抄本条**）
- identity 自我解释｜rule 规范权威 → **永不衰减**，进 L0
- lesson 教训（慢）｜artifact 产物（中）｜fact 事实（较快）｜episode 流水（最快）
- 衰减公式 `decay = 0.5 ^ (未访问天数 / 半衰期)`；低于休眠阈值转 dormant（不主动注入，仍可按编码召回），低于归档阈值转 archived
- 硬规则：衰减只影响「是否主动注入」，不影响「是否存在」；`rule`/`identity` 永不衰减

## 工具 11 个
remember / recall / read_body / resolve_code / neighbors / supersede / register / whoami / add_project / inject / healthcheck

## 已知限制（D-1~D-9，只记录不修）
- **D-5**：`recall` 只有 query / limit / include_superseded，**没有 project / tags 过滤** → 按项目检索只能靠关键词，标签不参与检索
- **D-7**：无 `valid_until`，双时态只实现了一半（只有 occurred_at / recorded_at）
- **D-8**：stdio 每会话一进程（实测 4 个并存）→ `session_name` 绑定不稳定，写入可能丢会话归属
- **D-9**：WAL 可能远大于主库，**裸拷 index.sqlite 会丢数据**（备份要三件套或先 checkpoint）
- **D-13 已修**：`--owner` 必须是有效公民 ID，不再默认 `human-anyi`

## 使用纪律
1. 读正文用 `read_body`（resolve_code 只回元数据）
2. `recall` 在 MCP 层支持空格分词 AND，无结果降级 OR；CLI 层不分词
3. 验收用例必须现造，不能锚定易变数据——曾用「fish 反馈」验收，结果这个词就在旧条标题里，新旧代码都命中，测不出真假
4. **会变的数字不抄副本**，只留权威来源（04 文档曾把 episode/fact 半衰期写成 30/90，代码实际 21/60，导致 AI 对外报错）
5. 同主题优先 supersede，不要新增并存条

## 设计意图（为何长这样）
- `kind` 不是物种而是**存在形态**：resident 居民（永久）/ visitor 访客（会话级）/ role 角色（项目级）/ system
- **遗忘是特征不是缺陷**：忘了能找回就行，但「忘过什么」要可查
- **忘是允许的，偷偷改是不允许的**：recall 不改写正文，只记 `last_accessed_at`
