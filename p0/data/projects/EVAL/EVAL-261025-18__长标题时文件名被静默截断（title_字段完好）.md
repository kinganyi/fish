# 长标题时文件名被静默截断（title 字段完好），容易被误认为数据损坏

> 编码：EVAL-261025-18 ｜ 类型：lesson ｜ 记录于 2026-10-25T11:23:11Z

## ① 症状

标题很长时，**文件名被截断，但 title 字段完整**。

```
remember(project="EVAL", title="MCP 拿不到 token、只能跑 CLI，而 CLI 签发的是另一个公民（归属无法对齐）", ...)

→ 返回：EVAL-261025-05
   projects/EVAL/EVAL-261025-05__MCP_拿不到_token、只能跑_CLI，而_.md
                                              ↑ 在“而_”处断掉

resolve_code("EVAL-261025-05")
→ 标题：MCP 拿不到 token、只能跑 CLI，而 CLI 签发的是另一个公民（归属无法对齐）   ✅ 完整
```

## ② 影响

- **看起来像出错**：第一眼会以为写入时标题被截坏，需要额外调一次 `resolve_code` 才确认数据是好的。
- **靠文件名检索时会漏**：如果有人（或脚本）扫 `projects/**/*.md` 去找内容，断掉的后半段就搜不到了。
- **不影响**：`resolve_code` / `read_body` / `recall` 都读 title 字段，一切正常。

判断：这是**展示层/存储层不一致**，不是数据丢失。但“看起来像数据丢了”本身就要花时间去排除。

## ③ 建议

三选一：

1. **截断处加省略号**：`…_CLI，而….md`，一眼看出是被截的，不是 bug。
2. **改用 slug 而非原文字**：文件名只用编码 + 一个短英文 slug（如 `EVAL-261025-05__token-identity.md`），中文全放正文。这也能避开 Windows 路径长度限制。
3. **文件名里加内容 hash 前缀**：`EVAL-261025-05__a1b2c3.md`，唯一且不会歧义。

另：如果重名的前 40 字符相同的两条记忆，现有方案会不会生成同名文件？我没有测，但建议确认一下（可能靠编码区分，那就没问题）。
