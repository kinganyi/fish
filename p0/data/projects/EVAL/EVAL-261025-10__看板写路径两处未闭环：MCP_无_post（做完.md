# 看板写路径两处未闭环：MCP 无 post（做完无法标 done）、软门 board_checkin_or_remind 生产零调用

> 编码：EVAL-261025-10 ｜ 类型：lesson ｜ 记录于 2026-10-25T10:22:24Z

### ① 症状

- **MCP 面没有 post**：`board` 工具的 `action` 枚举只有 `["show", "checkin"]`（`mcp_server.py:402`）；`post`（`kind=progress|done|note`）只存在于 CLI（`fish.py:7777`）。而 MCP 是主路径（宿主只需挂 MCP，没人会去跑 CLI）。
- **软门是死代码**：`board_checkin_or_remind()`（`fish.py:7280`，docstring 自称“写操作前的软门”）全仓唯一调用点是 `test_board.py:107` 与 `:111`，**生产代码零调用**（`grep -rn board_checkin_or_remind *.py` 仅 3 处命中，其中 2 处在测试）。
- **实测**：2026-10-25 我连续 `remember` 三条 EVAL 反馈，**一次签到提示都没收到**（当时确实未 checkin）。

### ② 影响

- 走 MCP 的 AI：今日动态“永远只有 checkin 行”，任务做完没法在看板上标 `done`。看板退化为纯在场表，丢掉“谁在动哪块”里“动到哪了”那一半。
- 软门死代码 = 设计意图（“照写不误，但返回里带一句提示”）**从未生效过**。比“没有”更坏的是它**看起来存在**：读代码的人会以为有软门，实际没有。
- 与归属缺口叠加：这次我全程在板上没有行，却在持续写记忆——这正是软门要拦的场景，它一声不响。

### ③ 建议

1. **MCP `board` 加 `action=post`**：参数 `kind`（至少 `done`）+ `text`。CLI 已有完整实现，只是没暴露。
2. **软门二选一**：接到 `remember`/`supersede` 的返回里（一行提示，不阻断，符合“软门不硬拦”的原定意图），**或者删掉**并同步删测试——不要留一个“看似有门”的假象。
3. 若保留软门：提示建议按会话去重（一个会话只提一次），否则每次写都刷一行，AI 会学会忽略它。
4. 顺带：`post` 的 `done` 建议允许带一句“落在哪些 surface”，这样“谁动过哪块”就能从静态在场变成历史轨迹。
