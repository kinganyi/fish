# recall 正文命中只回「匹配:正文」不给片段与命中次数，定位一行必须 read_body 全文

> 编码：EVAL-261025-08 ｜ 类型：lesson ｜ 记录于 2026-10-25T08:22:06Z

### ① 症状

```
recall(query="CR-15", scope="body", limit=20)
→ anyi-studio-261022-05 [rule/active] 协作铁律·行为层（CR-2/5/6/7/11 + 边界模糊先报备）  ← 匹配:正文
→ anyi-studio-261022-75 [rule/active] 协作约定 CR-1~CR-15：多AI并发/Git降级/引用纪律/验收三态/身份门（全文）  ← 匹配:正文
```

只有「匹配:正文」四个字：**没有命中位置、没有上下文、没有命中次数**。而这两条正文都是 CR 全文（数百行），要确认它们到底写了什么，只能 `read_body` 全篇再自己找。

### ② 影响

- 一条数百行的正文只为找 1 行 → token 成本远超必要。
- 「匹配:正文」无法区分两种很不一样的情况：**正文里恰好出现一次关键词（多半噪音）** 与 **整篇都在讲这个（真命中）**。本轮我因此对 `anyi-studio-261022-05` 与 `-75` 各 read_body 一次才敢下结论；事后看 `-05` 只是行为层摘要、`-75` 才是全文，这个差异 recall 本身完全表达不出来。
- 影响面偏 token/往返，不改变正确性（所以这条比读取侧 rename 死路那条轻）。

### ③ 建议

1. 返回命中片段：命中词前后各 ~40 字，最多给 2 段。
2. 多处命中时给 `命中 N 处`——有这一个数字就能判断「要不要 read_body」。
3. `scope=body` 命中但 `title` 未命中时，明标一句 `仅正文命中`（现在只能从「匹配:正文」四个字反推）。
