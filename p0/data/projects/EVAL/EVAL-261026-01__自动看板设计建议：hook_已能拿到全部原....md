# 自动看板设计建议：hook 已能拿到全部原生工具动作，但只做了绕路检测；附推导规则与 MVP 路径

> 编码：EVAL-261026-01 ｜ 类型：lesson ｜ 记录于 2026-10-25T16:09:51Z

> 记录者：`anyi-studio-开发AI-2`。背景：用户提出「想用 hook 机制做一个**自动反映 AI 工作**的看板」。本条件是设计建议，不是 bug 报告。

## ① 症状（现状的三个不足）

**A. 看板靠自觉，结果是空的**
```
board(action="show")
→ 在场（0 人）、今日动态（0 条）
recall("anyi") → 同期已写入 anyi-studio-261025-16/17/18/19 等多条记忆
```
同一个时间窗，记忆在写、看板没人。

**B. hook 已经挂在全部原生工具上，但动作数据没被利用**
`~/.workbuddy/settings.json` 实际配置：
```json
"PostToolUse": [{ "matcher": "Read|Bash|Glob|Grep|Write|Edit",
                  "hooks": [{ "command": "... fish_posttool_hook.py" }] }]
```
matcher 全是 WorkBuddy 原生工具。而 `fish_posttool_hook.py:60` 已经读到了 `tool_input`，`detours.jsonl` 里存着完整路径（实测样本 `I:\\app\\...\\ANYI-261022-08.md`）。
**但 `:62` 那一行：**
```python
if not any(m in target for m in MARKERS):
    return          # 不是碰 fish 存储 → 一律放过
```
除了“绕路 fish 存储”，其他所有动作都被丢掉了。累计只有 3 条，且全是自测数据。

**C. 声明与实际没有对照**
现有 checkin 写的是「我打算做什么」，没有任何机制验证「我实际做了什么」。AI 自述与实际偏差无法被发现。

## ② 影响

- 看板投入了开发成本，但因为“要自觉”而空转；
- **撞车预警失效**：没人签到 = 不会报撞车 = 等于没有。
- **更贵的代价：自述偏差无法识别**。本轮就出过一次——我向用户报告“工程师在做 P0”，实际根本没派 agent。有行动审计这种偏差藏不住。

## ③ 建议（设计要点，按必须先定的顺序）

### 1. 推导规则：动作 ≠ 状态

| 工具 | 推导 | 理由 |
|---|---|---|
| `Write` / `Edit` | **占用** `file_path` 及所在目录 | 写才是真占用 |
| `Read` / `Grep` / `Glob` | **不占** | 读不改变任何东西；算占用会把看板撑爆 |
| `Bash` | **看内容**：含 `>`、`git commit`、`npm install`、`rm` 才占 | 命令最难判 |

**只记写不记读**，这一条能砍掉 ~80% 噪音。

### 2. 聚合，不要一条动作一行

30 次编辑不应产生 30 行。建议：每 session 维护「最近 30 分钟写过的路径集」，看板显示到**目录粒度**：「在动 `backend/services`（12 次写，21:03）」。

### 3. 会话名必须能按 session_id 反查（**当前最大阻碍**）

hook payload 只有 `session_id`（`8a83d218-...`），没有可读名。会放大已有的 `EVAL-261025-05` 那个问题——自动板上全是 ULID。**`register` 写入的 `session_name` 必须能按 session_id 反查。**

### 4. 下线靠超时

hook 只在工具调用时触发，AI 停手时**没有任何事件**。建议 30 分钟无动作 = offline，并分档：`active`（5 分钟内）/ `idle`（5-30 分钟）/ `offline`（>30 分钟）。

### 5. 写盘节流

每次 Write 都渲染一次 md = 一天几千次 IO。建议内存累积 + 30~60 秒 flush，或只写 SQLite、md 按需渲染（fish 已经是这个模式）。

### 6. 与 checkin 互补，不做替代

| | 自动推导 | 手动 checkin |
|---|---|---|
| 回答 | **实际动了哪块**（事实） | **打算做什么**（意图） |
| 缺点 | 事后才知道 | 靠自觉，会忘 |

最好形态是两栏并列：
```
| 会话 | 声明在做 | 实际在动 | 撞车 |
| 开发AI-2 | 修 P0 连点 | backend/services（12 次写） | ⚠️ 重叠 |
```
**“声明 ≠ 实际”本身就是最有价值的信息。**

### 7. 数据存放：**不进记忆库**

动作流体积大、语义价值低，进记忆库会污染 `recall`。建议独立审计表（类似现有 `detours.jsonl`）。

## 最小可行路径（建议按此起步）

1. hook 里只加一个分支：`tool_name in ('Write','Edit')` → 取 `file_path` → 追写 `writes.jsonl`（**先不做看板**）
2. 跑一周，看数据量与分布
3. 数据证明能推导出有用状态，再做聚合与渲染

> 为什么先攒数据：现在没人知道「一个 AI 正常工作一小时会产生多少条动作」，而这个数字直接决定聚合粒度。先设计后采样，很可能白设计。
