# 看板软门两处判定错位：按「记忆的项目」而非工作项目（跨项目写必误报）、且不查活跃度（签到一次顶一天）

> 编码：EVAL-261025-14 ｜ 类型：lesson ｜ 记录于 2026-10-25T11:15:43Z

### ① 症状

**先看刚发生的现场（2026-10-25 19:16–19:17）**：

1. 19:16 `board(checkin, project="anyi-studio")` → 成功，返回“已签到”。
2. 19:17 `remember(project="EVAL", ...)` → 回执末尾多了：
   `你还没签到——看板上没有你的行。用 ... --project EVAL 登记`

**但我已经签过了，只是在另一个板上。** 软门拿的是 `a.get("project")`（**记忆的项目**），不是会话实际开工的项目（`mcp_server.py:589-590`）。写跨项目反馈（我们是 anyi-studio 开工、往 EVAL 写体验反馈）时，**每次写都必误报一次**。

**第二处：判定比 docstring 宽。**
- `board_checkin_or_remind` docstring 写的是“有 presence 行**且 30 分钟内活跃**”（`fish.py:7568`）。
- 实际代码只有 `if row: return True, None`（`fish.py:7572-7576`），**完全不看 `last_seen_at`**。
- 后果：早上 09:00 签一次，到 21:00 都不再提醒——doing 已经 12 小时没更新，而看板上它仍写着“在做 X”。这与看板“回答此刻”的定位直接矛盾。

**第三处：`status='left'` 不可达。** DDL 里写着 `active|idle|left`（`fish.py:516`），但 CLI `board checkin` 没有 `--status`（`fish.py:8237-8240`），MCP schema 也没有 `status` 字段。想“收工下板”的人做不到，行只能自然变 idle、或等 `sweep` 归档。

### ② 影响

- **误报会训练 AI 忽略软门**：同一条提示写 EVAL 一次弹一次、每次都无关，第三次就会被当成噪音。软门刚刚才从“死代码”接上线，这个最容易把它重新变成背景噪声。
- **签到一次顶一天**：板上会积一堆 `doing` 早已过期的行，而这批行正是 `EVAL-261025-13`（重叠检测掺假）的**成因**——两个缺陷同源：**presence 的生命周期没有任何“活跃/收工”语义在起作用**。
- 无“下板”动作 → 当天完工后行继续挂着，第二天 `board show` 看到的仍是满板旧人。

### ③ 建议

1. **软门判定改用会话档期/工作项目**：优先用 `session_start` 里开的 stint 项目（或 cwd 映射到的工作区），`project` 参数只在无档期时当兵底。或者更简单：**只要今天在任一板上有活跃行就不提**——跨项目写记忆是常态，不该被当成异常。
2. **把 30 分钟判定真正实现**（与 docstring 对齐），并且提示改成两种不同语义：
   - 无行 →“你还没签到”
   - 有行但超窗 →“你的 doing 已 N 小时未更新，重新 checkin 一句”
   后者比前者更有用，也不会让人觉得在重复训话。
3. **补给“下板”入口**：`board checkin --status left` 或独立 `board leave`；MCP 侧加 `status` 可选值。否则 `left` 只是个写在 DDL 里的词汇。
4. 若短期不打算做 2：**至少把 docstring 改正**（改成“今天有行即视为已签到”）——fish 自己就有一份《实现与规格偏离对账》，不应该在新增功能上再欠一笔。
