# PIT 错题本·协作与交付纪律

> 权威源：`notes/error-ledger.md`。场景：多 AI 并行改同一仓库、交付 UI、写加密/凭证、发版。

## 本质

不是技术难题，而是**多人/多会话同时动手时的静默丢失**：后写覆盖先写、重复造已有机制、交付了 UI 但没接线、把密码写进文件。

## 何时该想起

与其他 AI 并行改同一仓库、新建模块/组件、交付前端页面、处理凭证、写定稿文档。

## 关键判据

1. **并发先侦察**：改前看 `active-sessions`，冲突即停（PIT-001）；同一文件并行编辑会后写覆盖先写（PIT-037）。
2. **先查再建**：重复造已有机制是最贵的浪费（PIT-005）；旧路径（model client_router）不要再走（PIT-004）。
3. **导入类必须入库 + 传实体**：只存元数据不存文件 = 假成功（PIT-016）。
4. **文件域划太紧会逼人绕过分层**（PIT-018）。
5. **“已建未接线”是 UI 骨架类交付的常见盲区**：真机可达性必须验（PIT-079）。
6. **定稿文档的未归因变更**：多会话环境下改完必须留痕（PIT-076）；技能类要确认同步到“活位置”而非旧副本（PIT-075）。
7. **凭证绝不落盘**：生产密码明文三处落盘是 SEC-1 级事件（PIT-059）。
8. **用户可见时间必须是本地时区**：UTC 泄漏是反复强调项（PIT-041）。
9. **编排遇 429 要换工重试，不是砍范围**（PIT-057）。
