## 一、五条设计法则

| # | 法则 | 本项目落地 |
|---|---|---|
| 1 | **编号不可变、永不复用** | 一经分配不改号；作废仅标记状态；历史引用永久有效 |
| 2 | **命名空间隔离** | 每体系独占前缀；**跳体系不共享字母序列** |
| 3 | **顺序分配 + 单一注册表** | 读注册表取下一号；一切体系登记于《编号注册表》 |
| 4 | **状态机替代删除** | 生命周期：active / superseded / withdrawn / retired |
| 5 | **域内独立序号空间** | 各阶段/各域序号独立（`S1-T01` 与 `S2-T01` 天然隔离，不需全局连续） |

## 二、自生长流程（新体系加入，任何 AI 可发起）

```
1. 起草前缀 → grep 全空间检验零撞车（含 artifacts/notes/代码）
2. 在注册表登记一行（前缀/用途/权威源/起始号）
3. 从登记的下一可用号开始分配
4. 登记即全局生效
```

**撞号处理**：登记前必读注册表末尾；撞号 = 后写者改用下一可用号 + 条内注「（并发让号）」+ daily 说明。**已分配号永不回收**（即使条目 withdrawn）。

## 四、状态机

| 状态 | 含义 | 转换 |
|---|---|---|
| `active` | 在用，可持续分配新号 | → retired / superseded |
| `retired` | 已满/关闭，不再分配（已分配号永久有效） | 终态 |
| `superseded` | 被新体系取代 | 需注明 successor |
| `withdrawn` | 单条目作废（**号不回收**） | 终态 |

## 五、书写与引用规则（全体 AI）

1. **新引用一律新前缀**（`S3-T01` / `DEC-007` / `CR-3` / `ER-10`）
2. **历史文档零改动**——archive/已发布 artifacts/历史 daily 中的旧编号保持原样，检索靠《编号对照表》
3. **引用需自带语境**：跳文档首次出现写全（「`S3-T01`（阶段3第一批）」），同文后续可简写
4. **禁止发明未登记前缀**——走 §二 自生长流程
5. **daily/台账**：新写内容用新前缀；引用历史事件保留历史编号写法

## 六、迁移策略（三段式）

```
第一段（立即）：新体系启用 + 注册表建立 + skill 发布；新写引用一律新号
第二段（顺办）：collab-rules §〇 改 CR；MEMORY 改 ER；error-ledger 旧引用加勘误注
第三段（桥接）：《编号对照表》旧→新全映射落盘（开发AI 起草 → 主理人审定）
```
**明确不做**：不批量改写历史 artifacts/archive（零收益 + 高破坏面）。

## 七、治理与兼容边界

- 注册表维护：主理人（主AI）；登记请求任何 AI 可发起
- 校验工具：`numbering-system` skill（查询注册表/检验新前缀/生成下一号）
- 修订：本公约修订须经安逸批准
- **取代**：散落的编号惯例；**兼容**：MIG 文件名 / PIT 错题本 / git commit hash；**不涉及**：代码变量名、数据库表名、API 路径
