# PIT 错题本·前后端契约与状态同步

> 权威源：`notes/error-ledger.md`。场景：改前端组件、画布/节点、复制/改名、React effect。

## 本质

不是“写错一行”，而是**契约存在但没人宣它**：组件的间距、节点的引用 ID、改名要联动哪些表、effect 依赖多宽——这些都是隐式契约，改了不发现在于用户那里已坏。

## 何时该想起

动画布/节点/复制/改名、改 React 组件与 effect、改 MUI 样式。

## 关键判据

1. **复制节点必须重写引用 ID**：提示词里的 `[[ref:]]` 与连线要指向同一新节点，否则生成时静默丢失（PIT-032）。
2. **改名是传染的**：`asset_node_map` 不维护 → 副本判定失效 → 改一个名改一串（PIT-033，“名字又恢复了”的真因）。
3. **契约类不变量不能多点各自维护**：同源缺陷会多点爆发（PIT-035）；组件移除/改成前先问“谁依赖它”（PIT-015）。
4. **状态同步三雷**：双副本 + effect 依赖过宽 → 陈旧快照覆盖新值（PIT-050）；触发点迁进早退分支 → 功能不可达（PIT-051）；实例复用 → 懒加载页互切不更新（PIT-063）。
5. **MUI 细则**：`sx` 裸数字会被缩放（PIT-009），要用 `'px'`；内联样式字符串缺单位（PIT-071）；Select children 条件 Fragment（PIT-008）。
6. **布局**：flex:1 在固定列超宽时被压成 0 宽（PIT-020）。
7. **大段 Edit 会导致文件结构重复**（PIT-014）：长文件要小步改 + 读回。
