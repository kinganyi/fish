# PIT 错题本·本机环境陷阱

> 权威源：`.workbuddy/memory/notes/error-ledger.md`（全文 1588 行）。本条只存「索引 + 判据」，正文不搬。

## 本质

本项目大量“诡异失败”不是代码错，而是**本机 Windows + Git Bash + Agent 沙箱**的工具链语义与 Linux 不同。这类错误的共同特征：**不报错、静默、或报一个误导性的错**。

## 何时该想起

命令“明明对但没效果”、进程莫名挂起、文件没删掉、路径不对、输出乱码、测试假红/假绿。

## 关键判据

1. **解释器必须先确认**：用错 Python 会报 NameError/ImportError，掩盖真实原因（PIT-027/082）。
2. **`rm` ≠ 删除**：本机安软删除拦截后是“移入回收站”，**不释放空间**；>9999 文件目录还有 bulk 拦截（PIT-086/101）。
3. **safe-delete 守卫会让 pytest 收尾永久挂起**（PIT-039），临时目录会无限累积（PIT-101 实测 96.2 GB）。跑测试固定 `--basetemp` 到非 C 盘，跑完即删。
4. **路径要当心**：Git Bash 会把 `/i/app/x` 静默解析成 `I:\i\app\x`（PIT-048）；junction 会被递归穿透删除（PIT-069）。
5. **`env` 前缀可能静默空转**（uv shim 遮蔽，PIT-045）；pytest 输出管道在 Windows 下会永久阻塞（PIT-017）。
6. **网络**：GitHub HTTPS 常不可达，本机 7890 代理是可用通道（PIT-056）。
7. **工具版式差异**：GNU tar 的 `--exclude` 必须放在文件列表之前（PIT-080）；sha256sum 跨 OS 版式不同（PIT-081）。
8. **诊断脚本自己会制造副作用**：未关连接致进程挂起（PIT-013）、误连开发库（PIT-074）、异常中断×线程泄漏致退出挂死（PIT-096）。
