1. **CR-2 先读后写**：写共享文件前先读最新版（读→准备→再读→写）。写高风险文件（MEMORY / 看板 / 规则）前，在当日日志写 `[占用]/[释放]`。
2. **CR-5 主体边界**：本空间与量传引擎其它业务线、客户主体数据分离；客户或第三方隐私不进公共面。
3. **CR-6 节流**：并行会话数 ≤ 安逸能及时 review 的数量。宁可降吞吐，不可降 review 质量；台账堆积 = 过载信号。经验值：并行收益区间 3~6 个独立任务块。
4. **CR-7 证据铁律**：每个机制必写「能防什么 / 防不住什么 / 真兜底是什么」；✅ 必须有磁盘证据；未执行一律 ⏳；读数一律带时刻。
5. **CR-11 先探测再承诺**：宿主能力先测再报。测不出写 unknown，拿不到 ≠ 否。虚报级别 = 违规。
6. **边界模糊先报备**：拿不准「这算不算我的活」时，先登记「计划做 X，涉及 Y」，等确认再动手。严禁两个会话同时开工同一事项。

## 底层三现实（决定一切软约束的效力）
1. 并行会话互相看不见——磁盘 + 消息是唯一事实源
2. 人是消息总线——及时性靠转达，可靠性靠落盘
3. 没有拦截点的地方一切机制皆软约束——真兜底 = 版本历史 + 备份
