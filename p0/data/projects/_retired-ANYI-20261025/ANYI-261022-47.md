D-12 访问/遗忘进事件流（决策：01 新增 ADR-004，第 13 种事件 memory.accessed）
 修前：last_accessed_at / access_count / dormant 只在投影里，从未写事件 —— 投影一坏就永久丢，
 与 ADR-001「事件是唯一真相源」冲突。
 改法：新增 fish.record_access() 作为唯一访问入口（CLI recall 与 MCP recall/read_body/inject 共用）；
 一次调用写一条事件 {codes, source, counted}，不按条数展开；counted=false 区分「被看见」与「被查询」。
 重建：「快照优先 + 事件补缺」——快照是累积态，事件补它覆盖不到的条目。
 生产实测：改后第一次 recall 写出 memory.accessed（2 条 code/counted=true），access_count 同步 +1。

occurred_at 兜底顺序（清掉 §7.7 遗留）
 新规则：投影值若晚于记录时间（逻辑上不可能 = 被历史坏重建压平），改用事件时间并计数。
 生产重建：纠正 3 条（20:09:27Z → 20:09:26Z），时间倒置归零。

--occurred-at（兑现 02 §2.3 双时态）
 可回填「过去发生的事」，与「什么时候记的」分离；事件 payload 与投影同时记录。
 坑：第一版校验写在写入段，会消耗编码序号 + 留孤儿文件 —— 测试立刻抓到，已移到分配编码之前。
