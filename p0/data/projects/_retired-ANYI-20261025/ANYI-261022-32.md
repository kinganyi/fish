# fish 反馈：recall 验收用例「fish 反馈」不能区分新旧代码（标题前缀就是查询词）

> 编码：ANYI-261022-32 ｜ 类型：lesson ｜ 记录于 2026-10-21T22:55:59Z

**具体场景**：修复回执第 3 条把验收口径写成「`recall query="fish 反馈"`（之前会未命中，现在能命中 5 条）」。我用旧会话（未重启、确定跑旧代码）实测，**这个查询在旧码上同样命中 5 条**——因为那 5 条标题全部以「fish 反馈：」这四个字开头，旧版的整串子串匹配直接命中。也就是说，**这条验收项无法区分新旧代码**。

**卡在哪**：如果维护方拿它做发布门，一个完全没修 recall 的构建也会通过。我改用真正互斥的口径才拿到阴性对照：`recall("recall 正文")` → 旧码返回「未找到「recall 正文」」，而 `ANYI-261022-16` 标题里 ``recall`` 与 ``正文`` 都在、只是不相邻，新版分词 AND 应能命中。

**期望**：验收用例里避免用「标题前缀」当查询词。建议固定用这对组合（一个负对照 + 一个正对照）：
- 正：`recall("recall 正文")` → 应命中 `ANYI-261022-16`（词不相邻）
- 负：造一条库里确定不存在的词，确认仍返回未命中而不是全量兜底
另外建议：`recall` 命中时若能输出「匹配模式=AND / OR降级」，验收者就能直接从回包里判断新旧，不用靠猜。
