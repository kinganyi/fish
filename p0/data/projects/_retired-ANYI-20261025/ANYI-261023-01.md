## 机制（权威出处）

- `docs/subsystems/mcp.zh.md` + `packages/mcp/mcp-client/README.zh.md`：一台服务器 = 一条 Cordis patch 条目。
- **关键坑**：`docs/user/guide/mcp-memory.zh.md` §接入其他 MCP 服务器 明确要求包在 `- insert:` 里：

```yaml
- insert:
    - id: mcp-fish
      name: '@deepseek-ai/dsh-mcp-client'
      config: { serverName: fish, transport: stdio, command: ... }
```

  我第一版写成顶层 `- id: mcp-fish / name: ... / config: ...`，是**配置覆盖**形态，对不在插件树里的 id **静默无效**（不报错、不生效）。

- **生效条件**：`packages/boot/plugin-manager/README.zh.md` 第 14 行——「未启用 HMR 时，运行中的组合保留到重启」。
  本机 desktop profile 未启 HMR，所以改完必须重启宿主。

## 顺带查实的一件事

既有配置 `mcp-anyi-studio`（2026-10-14 加入）用的是**顶层形态**。同一次重启后，它**没有任何 `mcp__anyi-studio__*` 工具**；
而用 `insert:` 形态的 fish 同一次重启就生效。同机、同 profile、同一次重启的对照 → **顶层形态确实是无效的**，
即 anyi-studio 的 37 个平台工具从未在桌面端真正可用（其 10-14 注释里的"实测 25 个 callable"应来自另一条路径，如 `--patch` 临时传入）。
