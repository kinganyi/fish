# fish 反馈：同项目同主题被两个会话各记一条 rule，没有合并/覆盖/废弃手段

> 编码：ANYI-261022-17 ｜ 类型：lesson ｜ 记录于 2026-10-21T22:26:26Z

**具体场景**：同一分钟内，主AI 会话写入 `ANYI-261022-12`「fish 使用约定（anyi-studio 主AI 会话工作方式）」，我写入 `ANYI-261022-14`「fish 记忆库工作方式」，两者是同一件事的两份 rule。`remember` 落库时不提示「同项目已有高相似条目」。

**卡在哪**：两份 rule 都是「永不衰减」，会永久并存。工具集只有 register/whoami/remember/recall/resolve_code/neighbors/inject/healthcheck，**没有 update / merge / supersede / delete**。唯一能做的是再写一条「订正」（`ANYI-261022-15` 就是这么来的）——但订正条目本身也永久存在，条目数只会单调增长，同主题内容越滘越碎，最终没有任何一条是权威全文。

**期望**：
1. `remember` 落库前对同 project + 同 mem_type 做一次相似度检查，回显「疑似重复：<编码> ▸ <标题>，是否合并？」，允许调用方带 `supersedes=<编码>` 直接覆盖。
2. 提供 `supersede` / `merge` 接口：新条目声明替代旧编码，旧条目自动置 `superseded` 并指向新编码（而不是靠人肉在正文里写「以哪条为准」）。
3. 若出于审计考虑不允许删，至少让 `recall` 默认不返回 `superseded` 的条目。
