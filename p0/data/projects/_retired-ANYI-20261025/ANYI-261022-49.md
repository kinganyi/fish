# fish 使用规程：写什么类型 / 检索边界 / 会话归属 / 迁移期约定

> 适用：anyi-studio 系列会话（主AI / 开发AI / 开发AI-2 / 审查AI）。依据：fish 系统 `00~07` 号文档（2026-10-22 版）。

## 一、写什么类型（选错会导致该记的被衰减掉）

| 类型 | 用在哪 | 衰减 |
|---|---|---|
| `identity` | 自我解释、我是谁 | **永不** |
| `rule` | 规范权威、约束、纪律 | **永不** |
| `fact` | 被采纳进当下的事实、当前状态 | 较快 |
| `episode` | 一次具体发生了什么 | 最快 |
| `lesson` | 从事故里提炼的教训、判据 | 慢 |
| `artifact` | 交付物、文档、交接说明的载体 | 中 |

判断口诀：**“以后还会不会被当成规则用” → 是就 `rule`；“这是一次经历” → `episode`；“这是教训” → `lesson`。**

## 二、检索的真实能力边界（实测）

1. **`recall` 只搜标题与编码，不搜正文、不搜 tags**（D-5）。所以：
   - 想以后能被搜到，**关键词必须出现在 title 里**；
   - 按标签统计用 CLI（`fish.py`）或直接问维护方，不要指望 `recall`。
2. `recall` 默认 **不返回 `superseded`** 的条目；要看历史加 `include_superseded=true`。
3. 拿到编码后，**正文用 `read_body`**（`resolve_code` 只回元数据）。

## 三、会话归属不可靠（D-3 / D-8 已知限制）

- `session_name` 只存在 **MCP 进程内存**，stdio 下每会话一进程，**进程重启即丢**。
- 所以：**写完一条，看返回尾部有没有“，会话 XXX”**。没有就是丢了，重要记录里自己把会话名写进正文。
- 不要为了归属反复调 `register`（无效且浪费）。

## 四、硬约束

1. **不直接读写 `p0/data/` 与 sqlite**——一律走工具（那是绕路）。
2. **编码由系统分配**，不自编。
3. 附件传**本地绝对路径**，系统会复制进 `blobs/` 并按 SHA256 去重。
4. 同主题不要写两条——先 `recall` 看有没有人做过（**双 AI 并行时尤其重要，已发生过一次双写**）；已有则用 `supersede` 而不是再写一条。
5. 发现工具不好用 → 记 `fish-feedback`（`tags=["fish-feedback"]`），**只写具体场景 + 卡在哪 + 期望**，不写“建议优化体验”。

## 五、本工作空间迁移期的约定（2026-10-22 起）

- `anyi-studio` 的关键结论优先进 fish（可搜索、可衰减管理），**不再只写 daily**；
- daily 继续写，但降级为“流水”；**可复用的判断、约束、教训 → fish**；
- 交接文档类（长 Markdown）可作 `artifact` 正文，或把原文件当附件挂上。
