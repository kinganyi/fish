# 两个坑：argparse 变量覆盖根 parser（CLI 全崩）+ 交接清单三处失准

> 编码：ANYI-261025-09 ｜ 类型：lesson ｜ 记录于 2026-10-24T18:49:39Z

## 坑一：argparse 循环变量写成了根 parser 的名字

**症状**：给 `fish.py` 加 `alias` 子命令后，22 条 CLI 判据全红；`fish.py --help` 显示的是 `fish alias list` 的用法，所有子命令报 `unrecognized arguments`。

**根因**：`main()` 里 `ap = argparse.ArgumentParser(...)`，结尾 `ap.parse_args()`。我新增子命令时把循环变量也写成 `ap`：

```python
ap = asub.add_parser("list", ...)   # ← 覆盖了根 parser
```

三行之后根 parser 被覆盖成 `alias list` 子命令，于是它拿根参数去解析。

**为什么值得记**：
- 所有**单元**判据都发现不了它（它们直接调函数，不走 argparse）；
- 只有**真起子进程**的 CLI 判据能逮住。这次是 22 条红才暴露。

**规避**：子命令循环变量用 `alp`/`sub_parser` 这类专用名，永不复用 `ap`/`parser`。

## 坑二：交接清单是"意图快照"，不是"事实快照"

第一棒的 25 号清单里有三条与代码实况不符：

| 清单说 | 实况 |
|---|---|
| T8 待办 | **早已完成**（写清单当天下午就做了，清单没回写） |
| T4 待办（缺 host 显示） | `host` **早就查出来了**，只是没渲染——是"缺一行"不是"缺数据" |
| T6"完全不查重" | `add_project` **有**精确查重，缺的只是相似度 |

**教训**：接手任何待办清单，**先逐条对代码核状态，再排期**。照单做会重做已完成的活，也会误判难度（把"改一行"当成"动数据模型"）。
