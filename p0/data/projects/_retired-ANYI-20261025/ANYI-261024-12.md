## 根因（证据链，逐环可核）

| # | 事实 | 出处 |
|---|---|---|
| 1 | hook 经 `ctx.shell` 执行，请求中**不带** `sandboxPolicy` | `packages/hooks/hook-protocol/src/runner.ts:77-84` |
| 2 | 不带策略 = direct call → 回落 `ctx.sandboxPolicy.resolve()` | `packages/shell/bash-sandbox/src/index.ts:86` |
| 3 | 无 session 时 → 取部署级 `defaultMode` | `packages/sandbox/sandbox-policy/src/index.ts:167` |
| 4 | 该默认档 schema 缺省 = `read-only`，本机 profile 未配此键 | `sandbox-policy/src/index.ts:113` + profiles/desktop/cordis.patch.yml 无 sandbox-policy 段 |
| 5 | Windows 以受限 token + ACL 实现隔离 → 写盘被拒 | `packages/sandbox/sandbox-windows-acl` |
| 6 | SQLite 开 WAL 需写目录/文件 → 报 readonly | `p0/fish.py:491-492` |

对照组：AI 的 pwsh 工具调用**带 session**，走 permission preset `defaultPreset: danger-full-access`，因此可写。这解释了「同机 shell 成功、hook 失败」的全部差异。

**重要**：目录 ACL 完全正常，属**预期内的沙箱隔离**，不得以修 ACL 的方式「修复」。

## 三态声明

- **绿（已确证）**：T2/T3/T4/T5/T6/T7。
- **跳（SKIP）**：无。
- **判不到**：hook 子进程运行时的**实际** sandbox mode 数值——该值无直接运行时读数，`_probe()` 报出的 `dir_writable=NO(PermissionError)` 是间接证据。取得确切读数的方法：设 `FISH_HOOK_DEBUG=1` 后重启桌面端，读 `p0\data\_audit\hook-dsh.jsonl`。
