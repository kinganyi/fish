> 编码：大肥鱼生命系统-261025-10 ｜ 类型：fact ｜ 记录于 2026-10-24T18:49:49Z

审查报告（`大肥鱼生命系统-261025-06`）判 T1「未确认」，并指出"`fish_dsh_hook.py` 里无「未分类」逻辑"。

**这句话是对的，但它不是缺陷——实现点本来就不在 hook 里。**

## 真实链条

```
DSH SessionStart
  → fish_dsh_hook.py（只做：读 payload、拿 session_id / cwd、调 CLI、输出 additionalContext）
    → python fish.py session start --cwd <payload.cwd>
      → fish.py::cmd_session_start
        → resolve_project_by_cwd(conn, cwd)       # 命中 workspace_map
        → 未命中 → fallback_project(conn)          # ← T1 的落点
        → projects=[未分类] → 开档期
```

hook 是**薄壳**（它自己的注释就写着"调 session start（P1-b 已冻结的实现，只喂不改）"）。把项目判定塞进 hook，等于把"cwd→项目"这条证据链复制成两份——那正是 E-06（两份实现漂移）的源头。

## 我的表述错在哪

我沿用了第一棒清单里的措辞"**hook 落「未分类」**"，于是看起来像"hook 里应该有一段代码"。**清单的措辞描述的是效果，不是落点**——而我在交付文档里没有把这个区别说清楚，导致审查者去 hook 里找实现，找不到。

教训：**转述待办时，要把"清单里的效果描述"翻译成"代码里的实现落点"**，否则下一个人会去错地方找证据。
