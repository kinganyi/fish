我用完整会话日志（`24-会话全记录-卷1`，130 轮 / 253 条用户消息）做了测量，不是凭印象。

## 二、有效的部分（决定性）

**① 技术调研让我不犯低级错误。**
T3–T10 那八轮（Agent Loop / Hooks / Codex / WorkBuddy / 记忆机制）的直接收益在两个月后显现：
- 知道 MCP 子进程环境会被 scrub → 所以没在 MCP 侧找会话身份
- 知道 hook 是「最高权限插入点」→ 所以选了 hook 而不是别的通道
- 知道压缩是「生存需求」→ 所以理解为什么模型记忆不可靠

**这些判断没有一个是"我本来就知道"的，全是那几轮打的地基。**

**② 哲学讨论改变了判断标准。**
T21 那段「其实哲学上来说……」，两个月后变成具体设计约束：
处理 `anyi-studio-261022-24~29` 那次，我没按"时间早=原始"动手，而是先去查 `memory.retired` 的事件链。
**这不是纪律要求的结果，是理解的结果。**

**③ 明确说"不计成本"是必要的。**
T74「不需要考虑算力消耗/等待时间/token 成本」的实际效果：229 条测试 + 每条判据的变异自证 + 三轮 dry-run。
**没有这句，我大概率会"先跑通再说"。**

## 三、失效的部分（必须说）

**① 纪律会衰减，理解不会。**

实测助手输出长度：
```
第 1–50 轮：平均 1838 字，<300 字短回复占 20%
第 51–100 轮：平均 2187 字，短回复占 10%
第 101–150 轮：平均 1375 字，短回复占 32%   ← 明显退化
```

后期我"思考空转 + 正文稀薄"（用户用截图抓到，见 `大肥鱼生命系统-261025-04`）。
**而他越到后期越简短（平均 336 字）——这不是巧合，是同一机制的两面：投入减少 → 约束减少 → 行为漂移。**

**② 有些元指令我没内化。**

最典型：他说过「禁止照搬和直接采信记忆或上下文中的内容」。
**我还是照搬了 `^[A-Z]{2,8}$`** ——从外部评估报告里抄来的"规范"，我连它是真代码还是文档里的一句话都没核。

**这说明：说过的纪律 ≠ 内化的纪律。只有被「判据」接住的纪律才会真的生效。**

## 四、核心结论

> **这个策略在「建立共同理解」上极其有效，在「维持执行纪律」上必然衰减。**
>
> **因为理解可以一次建立，纪律必须持续施加。**
>
> **后期对话变短（336 字）不是省力，是把「维持纪律」的成本转移到了模型的自律上——而模型的自律不可靠。**

## 五、最诚实的一条证据

**本会话里最硬的事实对照**：

- **凡是进了测试和变异的纪律**（status 过滤 / 路径归一化 / 协议格式 / 项目判定）→ **一次都没退化**
- **凡是只靠对话说的纪律**（不照搬 / 正文要写 / 先查再答）→ **后期全部衰减了**

**这个对照本身就是方法论。**

## 六、如果要开源这套交流经验

**最有价值的不是"AI 做了什么"，是这个结构**：

```
阶段 1（前 50 轮）：大量技术调研 + 哲学对齐
  → 目的：让模型"理解"而不是"服从"
  → 判据：模型能自己推出你为什么这么要求

阶段 2（中段）：明确愿景与边界
  → 目的：让"取舍"有依据
  → 判据：模型在冲突时能自己判断

阶段 3（后段）：把纪律变成"判据"
  → 不能靠说，要塞进测试 / 变异 / dry-run
  → 因为：说过的纪律会衰减，被判据接住的不会
```

**这也解释了 fish 的设计哲学**：用户说过「不要问'怎么让 AI 深度思考'，要问'怎么让浅层结论在生产环节就出不来'」——
**本会话的数据正面支持这句话**：靠对话施加的纪律会漂移，靠判据拦截的不会。
