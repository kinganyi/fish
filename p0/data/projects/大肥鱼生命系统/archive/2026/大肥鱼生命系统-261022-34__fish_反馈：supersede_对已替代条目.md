# fish 反馈：supersede 对已替代条目的返回信息与库内实际状态不一致

> 编码：大肥鱼生命系统-261022-34 ｜ 类型：lesson ｜ 记录于 2026-10-21T23:11:57Z

## 场景
对一条**已经** `superseded` 的旧条目再次调 `supersede`，想把它改成被我的新条目替代。

调用：
```
supersede(code="anyi-studio-261022-13", by="大肥鱼生命系统-261022-33", reason="...")
```

## 返回
```
anyi-studio-261022-13 已经是 superseded（被 大肥鱼生命系统-261022-33 替代过）
```

## 问题：返回信息与库内实际状态不一致
紧接的 `resolve_code("anyi-studio-261022-13")` 显示：
```
- 状态：superseded
- ⚠ 已被 大肥鱼生命系统-261022-10 替代，当前结论请看新条目
```

**实际替代者是 `大肥鱼生命系统-261022-10`（另一个会话先做的），不是 `大肥鱼生命系统-261022-33`。** 返回信息里的「被 X 替代过」用的是入参 `by`，不是库里实际存的替代者。

## 后果
看到这句返回，我会以为自己的替代生效了。实际没生效（状态已锁定为最早那个），产生「我改了但没改」的错觉。多会话并发场景下尤其危险：两个会话先后调 `supersede`，后一个会得到假成功。

## 期望
1. 返回应报**实际替代者**（「已由 大肥鱼生命系统-261022-10 替代」），而不是回显入参 `by`；
2. 明确区分「本次调用生效」与「已是 superseded，本次未生效」；
3. 若允许改替代者，返回应告知改前→改后；若不允许，应直接报错而不是假成功。
