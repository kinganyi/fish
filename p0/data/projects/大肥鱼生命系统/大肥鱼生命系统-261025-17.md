# hook stdout 编码根治：GBK 写出 + UTF-8 读入，收敛 hook_io.emit + 8 条守护测试

> 编码：大肥鱼生命系统-261025-17 ｜ 类型：lesson ｜ 记录于 2026-10-25T15:04:04Z

## 症状

用户真实看到乱码推送（`fish 提示：…工具后推送，每 10 次调用最多一条`），英文正常、中文全乱。来源 = `fish_push_hook.py` 的 `_emit`（PostToolUse 工具后推送）。

## 根因（2026-10-25 QA 实测更正了此前表述）

**不是「DSH 按非 UTF-8 解码」这么半边。完整机制：Python 在 Windows 管道下 `sys.stdout.encoding = gbk`**；`ensure_ascii=False` 时中文以 **GBK 字节**写出（`D6 D0 CE C4`），消费方（DSH / WorkBuddy）按 **UTF-8** 读入 → 乱码。

结构性根因：同一个编码决策被 **4 个 hook 各实现一遍**（4 份 `json.dumps`）。2026-10-24 在 `fish_dsh_hook.py` 修过一次，其余 3 个仍错 —— 同一决策点多份实现必然漂移。

## 修复（2026-10-25 根治轮）

1. 新建 `p0/hook_io.py`：stdout 唯一出口 `emit(event_name, text)`，`ensure_ascii=True` 硬编码（ASCII 化是与解码方式无关的不变量）。
2. 四个 hook 全部委托：`fish_dsh_hook.py` / `fish_push_hook.py` / `fish_posttool_hook.py` / `fish_session_hook.py`；文件日志（detours/hook-dsh/hook-calls.jsonl）保留 `ensure_ascii=False`（写 UTF-8 文件，不是乱码源）。
3. 新建 `p0/test_hook_encoding.py` **8 条**守护：5 行为（各 hook 真实出口 → `str.isascii()` + 解码后含中文）+ 3 静态（禁 `False))` stdout 形态 / 每个 hook 必须含 `hook_io.emit` / 禁 `sys.stdout` 与 `print(` 旁路）。
4. 文档：依赖说明第 9 条改写 + 新增 #11 `hook_io.py` / #12 守护测试 + 失效提示；依赖索引同步 12 条。
