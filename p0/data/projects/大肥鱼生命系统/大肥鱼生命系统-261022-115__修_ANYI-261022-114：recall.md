# 修 anyi-studio-261022-114：recall 未命中回退列表不遵守 project（并澄清非数据错落）

> 编码：大肥鱼生命系统-261022-115 ｜ 类型：lesson ｜ 记录于 2026-10-22T10:18:45Z

﻿（闭环 anyi-studio-261022-114 报的「未命中回退列表不遵守 project」；顺带厘清一件被混淆的事）

缺陷：recall 未命中时的"最近的条目"是 SELECT ... ORDER BY code DESC LIMIT 5，
不看任何过滤条件。于是 project=ANYI 查不存在的词，会捞出 企业智能-* 的条目。
根因追溯：这是 ADR-005 重构时把回退逻辑同时留在 cmd_recall 与 tool_recall 两份里造成的
—— 正是 ADR-005 自己写的"读路径不许有两份实现"。

修复：收进 fish.recent_fallback(conn, project, tags, limit)，CLI 与 MCP 共用；
MCP 未命中时额外标明「已限定 project=X」，让 AI 知道是限定后的空。

重要澄清（避免被误读成"数据错落"）：
 普查全库，带 企业智能- 前缀的 8 条全部 project=企业智能；
 且没有任何一条编码前缀与 project 不符。
 所以串台是"列表忽略过滤器"，不是"记忆写错了项目"。

另一件真实存在但不同的事：大肥鱼生命系统-261022-23~29 这 7 条确实是 企业智能-主AI
 当初按错误任务书用 project=ANYI 写入的（见反馈 企业智能-261022-01）。
 它们至今 projects=ANYI、内容属于企业智能业务；fish 不可删改，只能 supersede
 （-23 已被 企业智能-261022-02 替代）。是否要把其余 6 条也迁到企业智能项目并 supersede，
 属内容归属决策，等提出方或安逸定。

判据：50 条全绿（8/28/14）；--project ANYI 查不存在的词只返回 ANYI-*；
 变异（去掉 recent_fallback 的 project 过滤）只红 test_recall_fallback_respects_project。
