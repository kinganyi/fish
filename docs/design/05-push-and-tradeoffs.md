# 05 · 推送与取舍

> 一句话：**推送是记忆系统的"神经元"——它决定系统在什么时候、以什么方式打断你。**

## 1. 判据：收益 − 成本

```
benefit = 相关 × 新颖（你不知道） + 紧迫（时效）
cost    = 误报概率 + token 成本 + 打断成本
推送 ⟺ benefit − cost > 0
```

早期版本只算收益（相关性×新颖×紧迫×可解释）——**没有成本项**。补上成本后，"沉默"第一次成为一个合法结果。

## 2. 候选池（六类）

| 类 | 来源 | 典型形态 |
|---|---|---|
| 规则 | 档期 / 未闭合 / 看板 | "你有个未闭合项" |
| 联想 | `links` 邻居 / 知识遗漏 | "别人读过 3 次，你没读" |
| 态势 | 同项目高频动作 / 冲突 | "这块 10 分钟内改了 4 次" |
| 意外 | 两跳跨项目 / 冷门 | "这条跨项目关联你可能想不到" |
| 看板 | 看板变更快照 | "板上有人刚完成" |
| **提示词** | `UserPromptSubmit` | "你提到 X，这里有 3 条相关" |

## 3. 时机与频率

| 时机 | 触发 | 频率 |
|---|---|---|
| 开场 | SessionStart | 每次会话一次 |
| 工具后 | PostToolUse | 每 N 次工具调用最多 1 条 |
| 提示词 | UserPromptSubmit | 命中才推 + 去重 |
| 即时 | 真实冲突 | 立即 |

## 4. 度量（防静默失败）

`push_log(candidate_id, channel, reaction, latency_sec, ...)`：

- "推了没读" → `daily_report` 判 `ignored`；
- "推了读了" → 调 `read_body` / `recall` 时回填 `accepted`；
- 度量进"再巩固"：没被读的候选降权。

**为什么必须度量**：没有反馈的推送系统会退化成噪音源——而噪音一旦被学会忽略，就再也叫不醒。

## 5. 陈旧性

- 用**内容年龄**（`occurred_at` / `recorded_at`）打折，不用 `last_accessed_at`（会被展示刷新）。
- 已作废/已替代的条目**不进候选**（查询必须显式带 `status='active'`）。

## 6. 关键取舍（被否决的方案）

| 方案 | 为什么否决 |
|---|---|
| 纯文件记忆 | 并发靠纪律、单文件会爆、编码无法原子分配 |
| 向量检索优先 | 不可解释、引外部依赖；编码坐标系 + FTS 已够用，语义检索单独立项（ADR-006） |
| 只做 MCP 不做 hooks | 模型不调 = 没有；"强制"做不到 |
| 双份实时快照 | 会漂的真相；快照只做投影 |
| 主键按"公民"压扁多会话 | 同公民多窗口互相覆盖、撞车自己撞自己（本仓修复的现场） |
| 自写 matcher 校验（正则镜像） | 与宿主方言脱钩 → "看起来通过、实际整份被拒" |
| 每条判据只测"存在/不出现" | 变异自证一碰就穿：外层断言抓不住语义 |

## 7. 边界

- 推送是**建议**不是命令：永远不会替模型做决定。
- 单机 SQLite：无分布式、无多租户（产品边界，见 [06](06-verification-and-boundaries.md)）。
- 语义检索/画像/UI/服务器：**明确后置**，不假装已经做了。
