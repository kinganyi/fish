# 01 · 记忆模型

> 一句话：**记忆是"发生过什么"的不可变记录，加上一层随时能重建的"现在的看法"。**

## 1. 为什么用事件溯源

四个需求同时成立，传统「当前状态存储」一个都满足不了：

| 需求 | 事件溯源怎么满足 |
|---|---|
| 记忆无限增长，上下文永远有限 | 磁盘层（事件，无上限）与 token 层（注入包，有预算）**分离** |
| 任何写入可追责 | 每个事件带 `actor / ts / cause` |
| "删除一个公民 = 它突然失忆" | 墓碑事件 + 重放跳过；物理数据可留 |
| 要能回答"当时是什么状态" | 事件流按时间重放即可 |

**代价**（不藏）：写入比 CRUD 复杂、重放会慢、投影一致性需要纪律。
**缓解**：快照 + 从快照重放、冷事件归档、投影是纯函数可 `rebuild`。

## 2. 六种记忆类型（"不可折叠"是硬约束）

借鉴 Mikoshi 论文的五条主张（身份连续性靠**因果路径**而非状态相似；历史/规范/采纳/自我解释/谱系**不可折叠进单一路径**），fish 把记忆分成六类：

| 类型 | 回答 | 半衰期 | 例子 |
|---|---|---|---|
| `identity` | 我们是谁 | 不衰减 | "我是 fish-主AI-3"（每个 AI 一条实例） |
| `rule` | 什么是对的（规范权威） | **不衰减** | "声称验证必须留痕" |
| `fact` | 世界是什么样 | 60 天 | "库在 `p0/data`" |
| `episode` | 发生过什么 | 21 天 | "今天合并了三分支" |
| `lesson` | 踩过什么坑 | 365 天 | "展示列不能进判定" |
| `artifact` | 交付了什么 | 180 天 | "41 号实施方案" |

**为什么不能合并成一张表**：历史（episode）、规范（rule）、采纳（fact）、自我解释（identity）、谱系（artifact）如果混在一条记录里，改一处就同时改了五种语义——审计就失效了。

## 3. 编码坐标系

`<项目前缀>-<YYMMDD>-<NN>`（如 `ANYI-261026-07`）。

- 前缀注册后才可用（不鼓励裸写）；序号由事务分配，**不回收**。
- **为什么不用 UUID**：编码本身携带"哪个项目、哪天、第几条"——人和 AI 都能直接读；排序天然按时间。
- 代价：项目改名要做映射与迁移（一次真实教训：`cdql → CDQL`、`ANYI → anyi-studio` 的别名治理）。

## 4. 遗忘：按类型衰减，不静默改写

- **衰减是必要的**：否则长跑 agent 的记忆会被等权重污染。
- **按类型分层**（typed decay）：`episode` 最快、`rule` 永不衰减。
- **回忆 ≠ 改写**：`recall` 只记录"被想起过"（`last_accessed_at`），**不修改正文**。
  要改必须走 `memory.revised` 事件——**忘是允许的，偷偷改是不允许的**。

## 5. 关联边

`links(src, dst, rel, source, weight, evidence, ...)`：

| rel | 含义 |
|---|---|
| `supersedes` | 新替旧（伴随 `memory.superseded` 事件，双写） |
| `derived` | 由谁产生（`cause` 字段） |
| `related` | 正文提及/语义近似 |
| `precedes` | 结构上的先后 |

`source ∈ {auto, manual}`，自动建的边可撤销；`weight` 随"被一起使用"再巩固。

## 6. 检索

- **FTS5 + bigram**（中文子串可用），按编码/标题/正文三档打分。
- **不引入向量库**：编码坐标系 + 关键词是**可解释、零依赖、可审计**的选择；语义检索在 ADR-006 里单独立项、条件触发。

## 7. 边界

- 投影坏了要能重建（`fish rebuild`）；重建本身是判据覆盖的重点。
- 历史事件不可改——所以**写错了只能追加"作废/替代"事件**，不能回滚。
- 大库的全文检索会随规模变慢（当前是单机 SQLite，无分布式计划）。
