# 06 · 判据与边界

> 一句话：**"测试全绿"不等于"真的对"——除非每条判据先证明它会红。**

## 1. 变异自证（本项目的核心纪律）

每条关键判据配一个**真源码变异体**：

```
基线绿 → 把实现改坏（变异）→ 指定判据必须红 → 其余判据不许新红 → 逐字节还原 → 复绿
```

**为什么**：判据是"实现者写的"。写成"某串不出现"这种外层断言时，它会**永远绿**——
哪怕功能已经坏了。变异体是唯一能证明"判据在测那件事"的办法。

**代价**：工作量翻倍（每批都要写变异脚本）。**收益**：它抓住过多次"全绿但功能是空的"。

## 2. 三态分明

| 态 | 含义 | 处理 |
|---|---|---|
| 绿 | 判据通过 | —— |
| 跳（SKIP） | 环境/条件不满足 | 明确写"跳"及原因 |
| 判不到 | 缺证据（拿不到读数） | **不算通过**，要给"拿到证据的确切命令" |

**缺证据不是通过**——这是最容易被"看起来做完了"吃掉的一条。

## 3. 外部真值

判断"配置对不对"必须用**宿主出厂的 parser**，不能用自写的正则镜像。

> 真实事故：自写校验连续两轮打绿，宿主却**整份配置拒收**（一个 hook 都没注册）。
> 修法：安装器只认"纯字面备选"形态，并用宿主方言契约校验；`--check` 对坏输入必须红。

## 4. 不要锚定易过期数字

- 文档引用读数一律带**命令 + as-of**（"截至某时刻"），不写"固定 1355 条通过"。
- 代码指纹（sha256 前 16 位）比行号稳；行号只当加速器。
- "全量只增不减"：判据数量可以涨，但不许为了变绿删判据（删要单独说明）。

## 5. 从真实事故里长出来的教训（精选）

| 教训 | 现场 | 现在怎么做 |
|---|---|---|
| 展示列 ≠ 判定列 | 用相对展示串反推绝对路径，撞车判定对实际动作失明 | 判定只吃事实列（`path_abs` / `dir_abs`） |
| 写入磁盘的字节要溯源 | 审计日志把命令原文（含 token）写进文件 | 匹配字段与落盘字段分离；只留摘要/哈希 |
| 修复要单调收紧 | 契约判据先松后紧，缺陷换个入口回来 | 只许收紧；每次修都补一条"只有这层能守"的判据 |
| 离线判据 ≠ 线上能力 | 单元全绿，但宿主里那个事件从没触发过 | 验收四层：代码 / 配置 / 离线 / **线上心跳** |
| 证据要落盘可解析 | 结论只在会话消息里，事后无法复核 | Gate 产物固定路径，缺文件 = 未通过 |

## 6. 已知边界（不装样子）

| 边界 | 说明 |
|---|---|
| MCP 不能强制 | 只调才有；主动能力必须走 hooks |
| 观不到模型思考 | 只观得到工具与提示词 |
| 单机 SQLite | 无分布式/多租户；服务器部署是明确的后置项 |
| 方言碎片化 | 每个宿主的 matcher/超时/输出 schema 不同，必须逐宿主校验 |
| `fish.py` 仍在瘦身中 | 知识库子系统已拆为 `fish_kb.py`（121 名原样再导出、零循环导入、行为逐字节对拍）；推送/看板待第二轮 |
| `board_seen` 仍按公民 | 同公民多会话互相吞推送（漏推，不误报）——**已修**（会话维度三列主键）；此条保留作历史记录 |

## 7. 路线

| 目标 | 现状 |
|---|---|
| **G1 认得清**（是谁/在哪/第几次会话） | 机制达成（token + host_session_key + 档期） |
| **G2 找得到**（≤3 层找到项目/记忆/知识） | 目录门面已落（`fish-home`），全景图与知识库目录服务持续补 |
| **G3 送得对**（开场送该知道的 + as-of） | 五段注入 + as-of + 推送候选已落 |

**明确不做**：服务器/多租户（先本地做好）、语义检索（ADR-006 观察期）、UI（P4）、
未经授权的"替真人换声口"。等真实使用数据说话，再决定下一批。
