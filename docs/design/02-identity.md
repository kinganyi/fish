# 02 · 身份与会话

> 一句话：**"我们是谁"只有一个来源——token；其余（名字、档期、宿主）都是标签。**

## 1. 四层身份

```
设备 device（本地阶段留空）
  └ 宿主 host（dsh / workbuddy / codebuddy / zcode / codex）
      └ 账号 account（跨会话聚合锚点）
          └ 会话公民 citizen（一会话一公民，30 天可归档）
              └ 子 agent（共享父身份，各自可区分）
```

- **一会话一公民**：并发归属清楚（每个会话有自己的记忆归属与看板行）。
- **账号**是"同一个 AI 的历史"的聚合锚点（跨会话），公民是"这一次会话"。
- **归档**：30 天不活跃 → 归档；owner 读路径走 `citizens_all` 视图（永远不悬空）。

## 2. 凭证：token 是唯一归属

| 证据级别 | 来源 | 用途 |
|---|---|---|
| `machine` | 宿主签发（hook 知道真实 `session_id` / `cwd`） | 归属权威 |
| `self-reported` | AI 自报（`register` / `session start --alias`） | 起名、跨宿主聚合 |

**为什么**：AI 会遗忘、会记错、会在多条通道里漂移。**凭证 = 归属**，名字只是标签。
**凭证纪律**：库里只存 `sha256`；令牌轮换时旧凭证吊销；`end` 即失效。

## 3. 一次真实的身份事故（值得公开的教训）

**现象**：看板上出现"我们在写我们自己"的撞车提醒，且提醒对象是 `fish-主AI-3·dsh#2`、`#3`——都是自己名下。

**根因**：为了"让某个会话用指定身份"，加了一个**工作区级身份锚**（`fish_identity.json`）。
但锚是**工作区级**的——同一工作区的**所有**会话启动时都会读到它，于是全被换绑到同一个公民；
多会话共享公民后，撞车检测按"公民"区分，分不清"自己"和"别人"。

**修法（两层）**：
1. 锚加**会话白名单**（`sessions: [...]`）：只对列出的会话生效，其他会话按 `host_session_key` 正常归属；
2. 撞车/看板判定升级到**身份键 `(citizen_id, session_key)`**（见 [03](03-board-collision.md)）。

**教训**：**"让某个会话变成谁"绝不能靠全局文件**——它需要**会话粒度的白名单**，且必须验证"锚里的公民在**当前库**存在"（测试/临时库没有该公民时要自动回退，否则注入直接失败）。

## 4. 判据（怎么防退化）

- `test_identity_p1a/p1b/p1c`：身份解析的每条路径都有断言；新增"读 citizens 的函数"必须登记（精确集合比对）。
- `test_session_*`：会话行、token 生命周期、`host_session_key` 优先级。
- 事故后补：锚的白名单语义 + 临时库回退（否则 42 条新判据全绿也漏掉这一条）。

## 5. 边界

- **MCP 面不允许签发 machine 级凭证**（评审结论）：MCP 只能自报；machine 只能由宿主 hook / CLI 签发。
- 凭证丢了不 panic：重跑 `session start` 换新凭证，公民不变。
- 多宿主同账号的聚合是"软"的（靠 `account_id`），不承诺跨设备强一致。
