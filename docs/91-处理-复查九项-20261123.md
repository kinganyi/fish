## 5. BUG-2（🟠 已修机制）画像提问 pending 与计数

### 读代码确认设计意图

- `bump_question_counter()`（`fish_profile.py:362`）：每次成功写记忆 +1，**无条件**。
- `question_due()`：`since >= profile.ask_every`（缺省 10）。
- `raise_question_if_needed()`：已有 pending 就**复用**（不刷表）。
- `reset_question_counter()`：回答/延期时把 pending 收尾并**清零**。
- 结论：旧语义是"距上次**回答/延期**"，与函数名/文档写的"距上次**提问**"不一致——提问挂起期间计数继续涨（实测 245 → 256），`trigger_count` 与实际待答问题脱节。**是设计不一致，不是数据损坏。**

### 改了什么

- `p0/fish_profile.py:362-378`：`bump_question_counter` 在存在 pending 时**冻结**（返回当前值，不 +1）；回答/延期后 `reset_question_counter` 清零并恢复计数。
- 新增判据 `p0/test_profile.py:406 test_P1_9f_counter_freezes_while_pending`：
  - 到点 → 留 pending → 再 bump 3 次，计数不变；
  - defer → 归零 → 再 bump → 1。
  - 变异：删掉 `_open_pending_question` 守卫 → 计数仍涨，本条红。

### 怎么验的 / 修前修后

- `test_profile.py + test_system_fix_batch1.py` → **43 passed**。
- pending 现状：`raised_at=2026-11-22T16:16:52Z`，实际挂起 **3.16 小时**（不是报告说的 8 小时——报告把 UTC 当本地算了）；`trigger_count=245`；`docs_since_ask=256`，修复后不再增长。
- **这条 pending 本体我没有替你答/延期**：回答内容涉及主人本人，不能由 AI 编。处理命令：
  `python fish.py profile ask --answer "..."`（回答）或 `python fish.py profile defer`（本轮不回答，留痕并清零）。
- 另：`docs_since_ask` 的递增**不进事件流**是设计（`set_event=False`），所以 91 之后没有 `config.changed` 记录——报告看到的 77→91 是更早的少数带事件写入，不是全部增长。
