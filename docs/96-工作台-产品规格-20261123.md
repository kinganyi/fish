## 一、一句话主张

**现场（工作台页签）是 fish 的行为仪表盘：把"AI 对系统做了什么"和"系统对 AI 说了什么"铺成一条改不了的时间线，让主人扫一眼就知道今天这套东西有没有在动、动在哪、谁在动。**

这句经得起替换测试（SP-1）：换掉 fish、把公民/宿主换成别的行业词就说不通——它写的是"多个 AI 在自己家里干活、主人要看得见"。它也排除了三种产品：不是消息中心（不做未读）、不是审计日志（不按人按时间检索）、不是管理后台（无设置入口）。

导出三个决定：**构图**——四栏：52px 顶级页签窄条 + 200px 左栏过滤器 + 中栏 ≥55% + 右栏 320–400px（右栏一宽，"看单条"就篡了"看整体"的位置）；**字体**——等宽只给机器标识（路径/编码/命令/时间列），正文无衬线（时间列与路径要滚动对齐不跳，等宽给中文正文读起来像日志）；**交互**——点一条 = 选中 + 切页签二，但页签一不销毁（"从单条回整体"是最高频往返，做成导航层级就要每看一条回一次头）。

## 二、任务清单（B3 三产物之一）

单位声明：交互单元 = **一条行为**；折叠/批量同时报覆盖条数。

**主任务 A · 判断"系统今天有没有在动、动在哪"。** 角色：主人。场景：早上开机或随时切回（旅程 6、U-07）。动线：打开（窄条上「现场」已是当前页；窄条现有两页：现场 / 设置，设置贴底）→ 扫中栏最近约 20 条 → 看右栏页签一"在跑/最近来过"与"工具使用" → 下结论。成功标志：**不点、不滚**，5 秒内说出"几个会话在动、最近一次动作何时、动在哪个项目"。不做会怎样：这页只剩一条能翻的历史，与翻日志无异。

**次要任务 B · 查一条行为的前因后果。** 场景：一条写着"改了一处"，不知道是谁、哪台、哪个项目 → 点开右栏页签二。成功标志：一次点击后答出四字段（谁、哪台、在哪个面、还在不在跑）。

**次要任务 C · 只看一个项目的动静。** 点左栏项目块 → 中栏被过滤。成功标志：抽 3 条 `project` 都对，且能点回"全部"。

**次要任务 D · 回看"我推的东西他看了没有"。** 找推送条目或看"热推内容" → 看反应字段。成功标志：说出最近 20 条推送几条有反应。注：一期只到"看字段"，百分比回填率口径待后端定（92 §5.2 R-16），本规格不发明。

## 四、数据边界

用户说"数据都是现成的"。**八成成立**：五类行为里四类今天就能从 `index.sqlite` 直读，不改 hook。但四条口径必须先钉。

**口径一：宿主没有单一真相，三个来源各说各的。** 流水条目的宿主取 `session_key` 前缀（`codebuddy` 27,026 / `dsh` 697）；公民档案取 `citizens_all.host`（`dsh` 255 / `cli` 62 / `workbuddy` 11 / `codebuddy` 7，长尾 `zcode`、`ZCode`、`codex`、`dsh-desktop`、`unknown`、空值各 1——大小写还不统一）；`tool_activity.host` 列**不可靠**：它写的是 `workbuddy` 27,025 / `dsh` 697 / `codebuddy` 1，与 `session_key` 前缀的一致率只有 **2.5%**（698 / 27,723），hook 侧写串了值，不作真相。界面显示几个宿主名由数据决定——不做白名单、不做"其他"桶，但大小写归一后显示（`zcode`/`ZCode` 合名）。

**口径二：`action` 只有 `write` 与 `exec`，没有"读"。** hook 从没落过读动作。所以"找东西/看东西"不可能来自 `tool_activity`，只能来自 `events`（`memory.accessed` 335）或 `memory_access_log`（1,051）。界面上任何"他读了 X"都是编的；能说的是"他取用了记忆 X"。

**口径三：近 30 分钟只有 1 条活跃会话——这个真读数会让人以为系统死了。** `presence` 525 行、distinct session 301，近 30 分钟活跃只有 1 条（实测）。处置见第七节①：拆"在跑/最近来过"两行，量词固定"会话"——`presence` 是会话级不是人级，写"在线 1 人"是把会话数当人数，属口径造假。

**口径四：项目归属 91.7% 为空，左栏不能只列"有项目的"。** `tool_activity.project` 为空 25,426 / 27,723；近 24 小时 2,435 条里 1,802 条无项目（`anyi-studio` 473、大肥鱼生命系统 160）。点任一项目都会把九成数据筛没——所以左栏项目列表**必须有"未归属"项且默认可见**（见 5.2），否则最该被看见的那部分行为进不了视野。

**规模（本文数字唯一出处）**：`tool_activity` 27,671（近 24h 2,493）｜`board_posts` 442｜`push_log` 5,784｜`events` 2,974｜`memory_access_log` 1,051｜`presence` 525｜`project_stints` 305｜`boards` 153｜`citizens_all` 336｜`code_index` 785｜`config` 20。

**三处"不现成"（必须新增，不能拿现成顶）**：
① **合流端点**——上一代读口只有一个"只看工具表"的单源端点，本读口没有这个路由（访问即 404，路由清单见 `p0/fish_workbench_api.py:2302-2407`）；五源同轴由 `GET /api/stream` 承担（`items[]` + `cursor`，已实现，`:2363`）。不做会怎样：前端自己合并五个端点 = 第二份领域实现（93 §2.1 记的 K8 死法），且五个 asOf 会混进一屏。**文档已对齐实现。**
② **`lastTouchedAt` 字段**——`/api/projects`、`/api/boards` 没有"最后一次被交互时间"；不补只能按创建时间排，左栏退化成目录。
③ **"仓库"字段**——`tool_activity` 只有 `path`/`path_dir`/`path_abs`，没有仓库字段；`events` 的 `git.commit` 的 `payload` 已带 `repo_id` 与 `content_root`（见第十二节 3），提交类能显示真实仓库 id，工具动作类只能显示 `path_dir` 并标"仓库判不到"。**实现现状（2026-11-24）**：界面只给 `pathLabel`，两类都**没有**这半句（见 §八字段 5）；补半句属**实现待改（另案）**。

页签一的"公民综合/热推/热搜"三块是聚合，上一代读口都不给，现由 `GET /api/stats` 一处承担（只读聚合，已实现，`p0/fish_workbench_api.py:2396`）："在跑 / 最近来过"取 `stats.data.motion`、"工具使用"取 `stats.data.tools`，不再各自拼端点。能力清单是**两把尺子**，分开写：`capabilities[]` 本机**已实现 7 条**（`entry / facets / health / hosts / meta / stats / stream`，`/api/meta` 2026-11-24 实测，定义在 `p0/fish_workbench_api.py:86`）；**契约全集 26 条**（93 §3.4 的 22 条 + stream/stats/entry/facets 四条，见 97 §C7）。缺哪条对应区块显示"该区数据未接：缺 `<cap>`"。本节同时是给架构师的输入。**文档已对齐实现。**

## 五、四栏信息架构（52px 页签窄条 + 三列）

栅格写死 `52px / 200px / minmax(0,1fr) / 320px`：固定列 572，**1280×720 下中栏 708（55.3%）**、**1440×900 下 868（60.3%）**，两档均无横向溢出（`scrollWidth == clientWidth`，机检 `p0/tools/shoot_workbench.py`）。

最左 52px 是**顶级页签容器**，不是装饰：纵向 `tablist`，**只放已建好的页**（现两页：「现场」贴顶、「设置」贴底，`pages.ts:33-36`；未做的页签不画——画一个点不动的入口等于给一个够不着的承诺）；页签清单由 `ui/src/pages.ts` 驱动，**加一页 = 加一条数据**。选中态**三件叠**（2px 左侧竖线 + 底色 + 字色/字重），不做灰态占位。品牌位**暂隐藏**，将来只放窄条最上方——不塞进页签内容、不做说明性标签、早期不加 logo（用户裁决；U-06："不是管理后台，不是选项和开关的堆叠"）。

### 5.1 第 1 栏：页签窄条（52px）

**放什么**：页签清单（两条：「现场」贴顶、「设置」贴底，`pages.ts:34-35`）；将来的品牌位在最上方。**为什么在这**：它答"我在哪一页"，三列答的是内容问题——两者不等价，所以它不参与分宽度（52px 固定，页内仍是三列；设置页是两栏，见 5.6）。**点它**：单击切页；页签名与数据契约名分开——页签叫「现场」，读口 schema 仍是 `fish-workbench/1`（契约锚点，改名要连带改测试与外部脚本）。**空的时候**：页签清单为空等于没有产品，一期不会发生。

### 5.2 第 2 栏：项目块 + 看板块

**放什么**：上块 **3 个项目 + 「未归属」**（未归属排在这 3 行之后，再下面一行是"其余 N 个项目（展开）"）；下块 **3 块看板**（再一行"其余 N 块（展开）"）；项目按"最后一次被交互"降序（`Rail.tsx:103/106` 各 `slice(0,3)`，未归属在 `:144-150`，两个展开按钮在 `:151-159` 与 `:190-198`）。**为什么在这**：用户原话"点击后可以对右侧瀑布流起到筛选作用"——它是**过滤器不是内容**，回答"要不要只看这一个"，不回答"这个项目怎么样"（后者属未来的项目视图）。**文档已对齐实现**（97 §A2 的"3+3"与此一致）。

**项目块**：项目名 + 最后动作相对时间 + 未闭合标记（`project_stints.to_ts IS NULL`）。实测 305 行里 303 行未闭合、项目名 18 个，因此前 3 行大概率全未闭合，标记要能一眼扫出"最早 40 天没动的那个"（距今天数取 `from_ts`）。来源：`tool_activity.project` 取 MAX(`seen_at`)、`project_stints.project/from_ts/to_ts`、排序键 `lastTouchedAt`。

**"未归属"项（必须有，默认可见）**：实现把它排在 3 个项目之后（列表最后一格，`Rail.tsx:144-150`），不是第 1 行；文档按现状写，**未归属置顶属实现待改（另案）**。它承接 `project` 为空的行为（全库 91.7%）。点它 = 只看全部无项目归属的行为，与"再点取消筛选（全部）"不同：前者是过滤，后者是清空过滤。它不占 3 个项目的名额；一条行为都没有时它也不出现。

**看板块**：只列当日 open 板，取前 3 块（`Rail.tsx:106`），其余折叠成"其余 N 块（展开）"（`:190-198`）。块内：板名（`boards.id` + `period_key`）+ 最后登记相对时间 + 在场会话数（`presence` 按 `board_id` 去重 `session_key`）+ "在跑 N"角标（`Rail.tsx:61-65`）。别写"共 22 块"：`boards` 153 行、open 22、覆盖 30 个 period；总数放进块标题右侧小字"（另有 N 块开着）"。来源：`board_posts.board_id` 取 MAX(`created_at`)、`boards.status/period_key`、`presence.board_id/session_key`。**文档已对齐实现。**

**点它**：单击过滤第 3 栏，再点取消；选中态要有非颜色标记（左侧竖线，92 §七要求状态不靠颜色单独表达）。双击不做。

**空的时候**：项目块"还没有项目被交互过。第一条这样写：`fish remember <project> ...`"；看板块同构（`fish board ...`）。命令以后端实际子命令为准（对齐 `fish --help`），**不许给跑不通的命令**——比说"没有"更伤信任。

### 5.3 第 3 栏：对话式瀑布流

**放什么**：五类行为混排的一条时间线（类型与规则见第六节）。**为什么在这**：主任务 A 所在，位置正中、宽度最大（≥55%）；左右两栏都是它的上下文——左给过滤条件，右给读数与详情。一屏只服务一条主任务，这栏被压缩，主任务就没了。

**点它**：单击 = 高亮 + 右栏切页签二并填充；再点同一条不取消（避免误点后右栏空白）。键盘 `↑↓` 移动、`Enter` 等于单击、`Esc` 收回选中并回页签一。

**空的时候**：四种空态见第九节。来源：五张表，见第六节。

### 5.4 第 4 栏：页签区

**放什么**：页签一"系统数据"（默认常驻）+ 页签二"信息详情"（有选中才有内容）。**为什么在这**：两者都从属于中栏，不该占主区；默认给页签一，因为"先看整体"比"先看单条"高频（A 主 B 次）。

**点它**：页签头互切；点页签二而无选中 → "还没选中任何一条行为——左边点一条"，不是空面板。宽度 320–400px **不加宽**（加宽就抢中栏，第一个构图决定就废）。**空的时候**：页签一见第七节、页签二见第八节。来源：`/api/facets`（左栏）、`/api/stream`（中栏）、`/api/stats`、`/api/entry`、`/api/meta`——五个都是本读口**已实现**的路由（`p0/fish_workbench_api.py:2302-2407`）；上一代读口的两个读数端点与一个新鲜度端点不在本读口路由表里，访问即 404，**不再引用**（文档已对齐实现）。

### 5.5 自适应下限

窗口最小 1280×720（92 §七）：52 + 200 + 320 固定 572，中栏 708（55.3%）。更窄时**不缩栏宽、不折栏**——"点左栏过滤中栏、点中栏改右栏"这个三角是四栏存在的理由，折栏等于砍主任务。这是本规格最硬的一条版式约束。

**现状与目标不一致（如实标注）**：实现把 `min-w-[1280px]` 放在**整页栅格**上（`Workbench.tsx:38` 设置页、`:48` 现场页），窗口 <1280 时**整页横向滚动**，不是"只让中栏滚动"；两档基准视口（1280×720 / 1440×900）均无横向溢出（机检 `p0/tools/shoot_workbench.py`）。**"只让中栏横滚"属实现待改（另案）**；`ui/tailwind.css:60-63` 的注释也还按旧的三列版式写、并引 96 的旧节号，同属实现待改。

**<1280 视口没有任何用例（108 P1-5 第 6 条），本规格不为它承诺行为。**

### 5.6 设置页（第二页，`?page=settings`）

**放什么**：宿主接入层的唯一界面——左列表（装了哪些宿主、谁接了 fish）+ 右详情（安装、配置来源、版本、协议、最后活跃、能力、接入证据、机制）。**为什么在这**：它回答"这套东西装没装、能不能用"，时间尺度是天到月；塞进 320px 的判断面会把"此刻谁在动哪块"和"哪个宿主没接 fish"混成一屏（`Workbench.tsx:29-32`）。

**版式**：`52px + minmax(0,1fr)` 两栏，不是四栏（`Workbench.tsx:35-44`）；窄条贴底摆「设置」（`pages.ts:35` 的 `group: bottom`），不与「现场」抢顶部。深链 `?page=settings`（`router.ts:30-37`、`App.tsx:195-199`），刷新后仍停在这一屏。

## 六、瀑布流的条目类型与合并规则

难点：五张表时间字段不同、粒度不同，合一条线立刻冒出四个问题——谁先谁后、同一件事是否出现两次、连续动作是否把别的类型冲走、一次拉多少。

| # | 类型 | 来源 | 图标语义 | 主行模板 | 副行 | 时间口径 | 点击后页签二 |
|---|---|---|---|---|---|---|---|
| 1 | 工具动作 | `tool_activity` 全列 | `exec` 系（bash/pwsh）=终端；`write`=落笔；`edit`=铅笔 | `{公民短署名} {动作词} {目标}`：`exec`→"执行了命令"、`write`→"写了文件"、`edit`→"改了一处"；**未登记工具原样显示 `tool_name`，不猜语义** | 项目 · 结果（`ok` 假=未成功）· 时间 | `seen_at` | 宿主、公民、行为、操作面（该会话 `presence.surface`）、正在干什么、该公民最近的动作与事件（账本三段，见第八节）；**"仓库"一格未实现**（界面只给 `pathLabel`） |
| 2 | 看板登记 | `board_posts` | 便利贴 | `{公民短署名} 在 {板} 登记：{text 首行截 60 字}`——**全系统唯一的行为正文**，可点开看全文 | `kind`（进度/完成/备忘）· 时间 | `created_at` | 正文全文（全屏唯一可显示"原文"之处）、所属板、该板最近在场 |
| 3 | 推送 | `push_log` | 信封（"我们"发出） | `fish 推了 {code} 给 {公民短署名}` | 通道 · 反应（空=暂无反应）· 延迟 | `pushed_at` | 推送指针（`code`→记忆编码）、通道、反应与时间、预算；**不显示推送内容全文** |
| 4 | 记忆事件 | `events` 且 `type LIKE 'memory.%'` | 记忆方块 | 只三条白名单：`memory.recorded`→"记下了一条记忆"、`memory.accessed`→"取用了记忆"、`memory.retired`→"退役了一条记忆"；其余归"其他事件" | 编码（`subject`）· 时间 | `events.ts` | 编码 + 标题（回查 `code_index`）、`payload` 键名清单（不展示值） |
| 5 | 系统事件 | `events` 非记忆白名单：`session.opened`(513)/`citizen.registered`(338)/`git.commit`(329) 等 | 系统点 | 按类型映射：开了一个会话 / 登记了一个公民 / 提交了代码；**未登记类型显示 `type` 原值**，不译成看不见原文的"系统动作" | `actor`/`subject` · 时间 | `events.ts` | `type` 原值、`payload` 键名清单、`refs`、`cause` |

**必须解释的取舍**：`events.memory.accessed`（335）与 `memory_access_log`（1,051）是同一件事的两个投影。**瀑布流只取 `events`；`memory_access_log` 只用于"热搜内容"聚合。** 两源同入会让"取用记忆"出现两次，且字段名与精度不同，去重只能靠时间戳近似匹配——那是猜。

**合并规则（六条写死）**
1. **排序**：按各自时间字段降序；同毫秒按因果序 推送 → 工具动作 → 看板登记 → 系统事件（输入→响应→结果）；仍平局按主键数值降序。不依赖字段遍历顺序——否则刷新一次顺序变一次，用户以为数据在动。
2. **去重**：只做上面那一处。**跨源二次去重不做**：`git.commit` 与"某人跑了 git commit"可能同源，但没有任何字段能证明，猜着去重会删真行为。不做的代价是偶尔两条很像（观感），做了的代价是数据缺失。
3. **折叠**：同 `session_key` 在 60 秒内**连续** ≥3 条工具动作 → `{公民短署名} 在 {项目} 连续做了 N 个动作（展开）`。为什么必须：工具动作 27,671 对看板登记 442 ≈ 63:1（近 24h 仍有 2,493 条），不折叠就看不到"我们"的行为，任务 A 退化成读日志。展开后原地显示不跳位，折叠条参与排序（取组内最新时间）。
4. **一次拉多少**：首屏 40（`ui/src/store/workbench.ts:16` 的 `PAGE`）、增量 40、上限 500（`p0/fish_workbench_api.py:124` 的 `LIMIT_MAX`）。40 × 单行约 56px ≈ 2.2 屏，够铺满 900px 窗口还有余量；再多首次加载拖累首屏 < 1s（92 §七）。
5. **增量**：不做长连接，2 秒轮询 `since=cursor`（沿用 92 §6.2）。新条目到齐时：在顶部→直接插入；不在顶部→顶部显示"N 条新行为（点击回到最新）"，**绝不自动滚动**（会在用户读正文时把内容抽走）。
6. **过滤**：左栏过滤作用于数据源（服务端按 `project`/`board_id` 过滤），不是前端隐藏行——前端隐藏会让"40 条里剩 3 条"的空洞看起来像加载失败。过滤条件传给 `/api/stream`，游标重置。

**不做的"行为"（条目层四条）**：① 不做"读了文件"——`action` 只有 write/exec，硬做只能靠 bash 字符串猜"是不是 cat"；② 不做对话原文——语料在另一库（92 §5.4 G2），且读口无鉴权、`ACAO:*` 未修（92 §2.3）；③ 不做"AI 在想什么"的推断与自动摘要——同屏出现两种可信度不同的文字，用户分不清哪句是记录；④ 不做用户自己的界面点击——用户原话把"我们的行为"定义为"推送、提醒等信息"，界面点击属操作日志，没人看。

**⑧ 热搜内容**：`memory_access_log`(1,051) 按 `code` 取前 5，编码回查 `code_index`(785) 拿标题。**两档都给**——当前窗口一档 + 全期一档（老记忆会常驻榜首，只给全期会让"热搜"看起来停了三周），每行带次数与最后取用时间（`TabNeedYou.tsx:331-371`）。空：无记录 → "还没有记忆被取用过" / "这一窗里没有取用记录"；编码查不到（被物理删除）→ 该行"编码已不在索引里"，**不留空行**。

## 九、状态设计

**交互八态**：默认 = 行无背景、时间列右对齐、左栏未选中无标记；悬停 = 背景浅一档 + 时间列从 `HH:mm` 展开为 `HH:mm:ss`，**不弹浮层**（滚动中会跟着甩；实现即 `Time.tsx` 的 `group-hover/time`）；焦点 = 2px 焦点环，不许 `outline:none`（92 §七）；按下 = 背景再深一档（实现只有 `active:bg-n3` 一类底色，`active:translate` 全仓 0 处——**"按压缩进 1px"属实现待改（另案）**）；禁用 = 一期没有可禁用的主操作，唯一灰态是"页签二无选中"的字段区（它不是"不允许"，是"还没有"，悬停不弹说明）；加载 = 超 300ms 出骨架（只占位不填假数字，92 §6.2），超 8s 转"仍在读，已等 N 秒 + 取消"（`codes.json:11-12`）；空 = 见下；错误 = 三段（出了什么 / 为什么 / 你能做什么），贴后端原文，不改写成"加载失败"。

**四种空态，四句不同的话**：
① **读口未起**——整屏一条说明 + 启动命令 + 重试，**不显示任何数字、不显示骨架数字**：`读口没有起来，所以这里没有数据可看。启动命令：<命令>。起来后点"重试"。`
② **库为空**——每块显示"空库"并给"怎么写入第一条"（`fish remember ...` / `fish board ...`），**不显示 0**：0 是读数，"空"是状态。
③ **筛选后无结果**（用户做了动作）：`这个项目在「现场」里还没有行为记录（筛选条件：<项目名>）。` + "清除筛选"。
④ **时间窗内无行为**（用户没筛选，窗口本来空）：`最近 24 小时没有任何行为记录（不是筛选的结果）。` + "看更早"（窗口拉到 7d）。
**③④必须不同**：都写成"没有数据"，用户就分不清"我筛错了"还是"系统真没动静"——这两件事的下一步动作完全不一样。
