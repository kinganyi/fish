## 1. 这是什么、为什么要有（需求）

fish 的记忆库（`p0/data`）和你的 Obsidian 知识库（本机 `E:\Obsidian\安逸知识库`）**是两套东西**，
本批（B3）给它们之间开了一条**窄口**：

| 方向 | 允许 | 不允许（永久边界） |
|---|---|---|
| 知识库 → fish | 看目录 / 读单文件 / 库内检索（**按需扫描，不建索引**） | 正文进 `code_index` / `memory_fts` / `recall` / `inject`；自动"读到就 remember" |
| fish → 知识库 | 仅 `mode=rw` 的库：新建 / 追加 / 显式更新 Markdown；每次写前自动备份 | 删除 / 移动 / 重命名；写 `.obsidian/**` / `.trash/**` / **`90-模板/**`**；改 `[[双链]]`；改写非 UTF-8 文件 |

**读也不是无条件的**：命中内置敏感名单的文件（`*凭证*` / `*credential*` / `*secret*` /
`*密码*` / `*.pem` / `*.key` / `id_rsa*` / `.env*`）默认只回**文件名 + 大小 + 建议**，
要正文必须显式二次授权（CLI `--allow-sensitive` / MCP `allow_sensitive=true`）。
`kb search` 永不把它们的行做成片段（只计数，见 `scanned.skipped_sensitive`）。
名单是**内置且不可由用户删除**的——凭证保护不能依赖"你记得加规则"。

**写也有闸**（第四轮 S6）：`create` / `append` / `update` 命中敏感名单 → 默认直接拒
（`错误[sensitive]`，文件**字节一个不动**）；凭证内容交 Obsidian / 人工维护。

**授权旗只认明确布尔**（第五轮 N7，安全审计的 fail-open 修复）：`allow_sensitive` 接受
`true` / `false` / `1` / `0`（字符串也行，大小写与首尾空白不敏感）；`"false"` / `"0"`
就是**拒绝**，`"yes"` / `"on"` / `"真"` / `2` 这类模糊写法一律 `错误[bad_usage]`（不猜）。
MCP 面给 `true` 还**必须带有效 token**（否则只能记成 `unattributed`，追不到人）。
另外：**`allow_sensitive` 是模型自己就能填的布尔，不是人机二次确认**——它防误伤、留痕迹，
不防决心；人真要看正文，最稳的是自己在 Obsidian 里打开。

为什么是"窄口"：你的库是**十年积累**（实测 2492 文件 / 297 篇笔记 / 约 11.5 GB），
"顺手索引一下"会把整库灌进检索面，反过来"顺手帮你整理"会断双链。
所以本批的设计取舍是：**读要多、写要少、写必可撤**。

## 2. 操作手册

### 2.1 注册一个库（只登记，磁盘一个字节都不动）

```powershell
cd <仓库根>\p0
python fish.py kb vault add --name 安逸知识库 --path "E:\Obsidian\安逸知识库" --mode ro
```

- 加 `--default` → 之后 `kb tree` / `kb open` / `kb search` 不带 `--vault` 就用它；
- 加 `--ignore "**/_media/**"`（可重复）→ 追加忽略规则（默认已有 `.obsidian/**` /
  `.trash/**` / **`90-模板/**`**；后三条是**不可删**的，重登记也消不掉）；
- **同一个路径重复 add 不会新增行**（按 `normcase(realpath(path))` 判重，大小写/短名/junction 别名都归一）；
- 路径不存在 / 不是目录 → exit 1；`--mode` 不是 `ro|rw` → exit 2。

看已登记了什么：

```powershell
python fish.py kb vault list          # 名字 / 路径 / mode / 最近扫描 / vault_id
python fish.py kb doctor              # 逐库体检（存在/可写/忽略规则/条目/同名笔记/超限文件/备份体积/obsidian_cli）
python fish.py kb backup prune --keep-days 30 --dry-run   # 只看会删哪些旧回滚点（默认不删）
```

### 2.2 `ro` / `rw` 到底是什么意思

| mode | 读（tree/open/search） | 写（create/append/update） | 谁改的 |
|---|---|---|---|
| `ro`（**默认**） | 可以 | **拒绝**：`错误[mode_ro]`，提示 `fish kb vault set-mode <n> rw` | 只能人显式改 mode |
| `rw` | 可以 | 可以（每次写前自动备份 + 写后重读校验） | AI（经 MCP `kb_write` 或 CLI `kb write`） |

要点：

- **`ro` 是默认值**，不是"只读一会儿"。想开写必须由人跑 `set-mode ... rw` —— AI 不能给自己授权；
- `doctor` 里的"可写：是"说的是**操作系统层面**能不能写，与 `mode` 是两件事。`mode=ro` 时写入被 fish 拦在更前面；
- 改回 `ro`：`python fish.py kb vault set-mode 安逸知识库 ro`（下一次写就会被拒）。

### 2.3 读三件套（都不建索引、都不写正文）

```powershell
python fish.py kb tree   --vault 安逸知识库                 # 目录（只统计，不读正文；默认 depth=2）
python fish.py kb open   "10-漫剧/拆解库/_拆解库索引.md" --vault 安逸知识库
python fish.py kb open   "80-资料库/凭证管理_v1.0.md" --vault 安逸知识库 --allow-sensitive  # 敏感文件要显式授权
python fish.py kb search 拆解报告 --vault 安逸知识库 --limit 5
```

三条命令的回执都带**来源声明 + as-of + 扫描读数**（例：`scan=297 files / 3193462 bytes / 890 ms`）。
`search` 是**字面匹配、按需扫描**（不是语义检索），只扫 `.md`、单文件上限 2 MiB。
要 fish 记忆请用 `recall`，要编码请用 `resolve_code` —— **两套检索永不互相合并**。

第二轮之后的三条细节：

- **`--depth` 真的生效**（1–4）：`depth=1` 只列根 + 一级目录（并扫一级目录拿直接文件数），
  **不再下钻**。回执头部有**两行恒定**的深度说明——「统计面：数到第 N 层（更深的目录不显示、
  也不计入合计）」+「每目录最多列 20 项（超出记 more=N）」；「还有多少目录没展开」由
  `--json` 的 `scan.partial=true` / `scan.hidden_dirs=N` 承载（合计只含已展开部分，
  **不假装全量**）。头部说明**不随 depth 增减**：旧版每个节点挂一行"深层未展开"，
  depth 一变大这些行就消失，输出反而更短（那正是第四轮 b2e41b9 修掉的单调性问题）。
- **附件只计数、不列文件名**（`attachments/` 下几百张图名会吃光预算）。
- **`search` 每条命中给库内全路径 + 相对路径**：前者能直接落到磁盘，后者是 `kb open` 的入参形态。
- 链接面：`tree` / `search` 遇 junction / 符号链接一律**不列、不下钻、不命中**（库外内容不会漏进来）。

### 2.4 写三档（必须先 `mode=rw`）

```powershell
# ① 新建（目标已存在 → 报 exists，不覆盖）
python fish.py kb write "40-教程/新笔记.md" --vault 安逸知识库 --create --content-file .\c.md --frontmatter tags=草稿 --reason "补一条教程"

# ② 追加（目标不存在 → 报 not_found；沿用原文件 EOL）
python fish.py kb write "40-教程/已有笔记.md" --vault 安逸知识库 --append --content-file .\c.md

# ③ 显式更新（**必须**带 --base-sha256，乐观锁）
python fish.py kb open "40-教程/已有笔记.md" --vault 安逸知识库 --json   # 先拿 sha256
python fish.py kb write "40-教程/已有笔记.md" --vault 安逸知识库 --update --base-sha256 <那个sha> --content-file .\c.md
```

写命令的 stdout **固定三段**：① 改了什么（动作/字节/sha256/eol/校验）② 备份在哪 ③ 怎么撤（`fish kb rollback <write_id>`）。
`--content-file` 必须是 UTF-8 文本；正文里**不要**自己带 `---` 文件头（会被 `bad_frontmatter` 拒，frontmatter 走 `--frontmatter k=v`）。

第二轮的写边界（都是"拒"而不是"猜"）：

| 情形 | 结果 | 为什么 |
|---|---|---|
| 目标文件不是 UTF-8 族（GB18030 等） | `bad_encoding`，**文件字节不变** | 追加 UTF-8 段会写出"半 GBK 半 UTF-8"的混合编码，且写后校验必然通过（比的是"我写进去的字节"）——静默弄坏人的笔记 |
| 既有文件 > `max_open_bytes`（默认 2 MiB） | `too_large`（与读路径同口径），备份 payload 同限 | 一次写会整篇读入 + 备份一份 + 原子写一份，放大 ≈3× |
| frontmatter 值含换行/控制字符 | `bad_frontmatter` | 值里的 `\n` 会落成额外顶层属性（甚至提前闭合文件头）；frontmatter 只收单行标量 |
| 目标命中敏感名单（凭证/密钥/`.env`） | `sensitive`，**字节零改动、零落盘**（`create` 也是先拒再谈落盘） | 第四轮 S6：凭证不该由 AI 改，交 Obsidian/人工；确需改写要 `--allow-sensitive`（MCP 还要有效 token） |
| `90-模板/**` | `ignored` | 裁决 Q13：模板决定以后所有产出，AI 一律不许写。**强制项不依赖登记行**（第四轮 S2）：旧行只写了两条 glob，也照样拦 |

### 2.5 回滚

```powershell
python fish.py kb rollback 17-c424ffb2        # write_id 形如 <kb_access.id>-<8hex>，写回执第 ③ 段给
python fish.py kb rollback <write_id> --force # 文件在写之后被改过时才需要；会先把当前内容再备份一次
```

**`write_id` 是全串凭据**：回滚时读备份 `meta.json` 的 `write_id` 做全串相等校验，
后缀不对一律 `not_found`（**文件一个字节不动**）——不再接受"只匹配前缀"。
理由：`index.sqlite` 重建后自增 id 会重排，只认前缀的旧凭据可能命中**另一次写**，
而 `create` 的回滚动作是删文件（"用旧凭据删掉别人的新笔记"）。

三种语义：

| 当初动作 | 回滚做什么 | 边界 |
|---|---|---|
| `create` | **删除**那次新建、且此后无人改动的文件（唯一允许的删除） | 当前 sha ≠ 写后 sha → 拒（`stale_base`），`--force` 才继续（仍先备份现值） |
| `append` / `update` | 用备份里的原字节原子覆盖回去 | 同上；恢复后重读校验 sha256 |
| 备份被清理 | 明确失败（`backup_missing`），**不假装成功** | 备份只在本机、只在未被清理前有效（见 §4） |

## 3. Obsidian 兼容说明

| 项 | 行为 | 为什么 |
|---|---|---|
| 编码 | 读：UTF-8 → UTF-8(BOM) → GB18030；写：一律 **UTF-8 无 BOM**，且**目标必须是 UTF-8 族**（否则 `bad_encoding`，字节不变） | 实测全库 297 篇 md：**0 篇带 BOM**；不猜、不用 `errors=replace` 悄悄给乱码；也不往非 UTF-8 文件里拼 UTF-8 段 |
| 换行 | `update/append` **沿用原文件**（CRLF 就还是 CRLF）；`create` 用 LF | 实测 266 CRLF / 31 LF / 4 混合：统一成 LF 会在 Obsidian/git 里造出"整文件变动"的假 diff |
| frontmatter | **只增/改给定键**；未知键、注释、缩进子行、空行**原样保留**；值只收**单行**标量（含换行/控制字符 → `bad_frontmatter`），渲染后再做一次单行断言 | 不做"半个 YAML"：嵌套 map/list / 锚点 / 多行字符串一律报 `bad_frontmatter`，宁拒绝不猜着重写；值里的换行会注入出额外顶层属性 |
| `[[双链]]` | **零改写** | 改写双链 = 断链；改名/移动本来就不在本批允许面内 |
| 临时文件 | 写盘走同目录 `.<name>.tmp-<id>` → `fsync` → `os.replace` | 点开头文件 Obsidian 不索引；`replace` 是原子的，崩溃不会留半篇笔记 |
| `.obsidian` / `.trash` / `90-模板` | 默认忽略（**不可删**）：读不了、也不许写；判定按大小写不敏感 + 逐段去尾随点/空格（`.OBSIDIAN/`、`.obsidian /` 同样拦住） | 前两个是 Obsidian 本体；`90-模板` 决定以后所有产出（裁决 Q13）。Windows 上大小写/尾随空格只是别名，不是另一个目录 |
| 链接 / junction | 遍历面（tree/search）**不列、不下钻、不命中**；显式路径给链接 → `outside_vault` / `reparse_point` | 同一棵树不能有两套边界：显式路径有检查、遍历面也必须有一道 |
| 同步/恢复 | 不接管 | 要版本历史请用 Obsidian 自带文件恢复或给 vault 上 git（本批不做） |

## 4. 备份位置、清理与"回滚能撑多久"

- 目录：`<data_root>/_backups/kb/<vault_id>/<YYYYMMDDTHHMMSSZ>-<slug>/`
  - `payload` = 写入**前**的原字节（`create` 时没有这个文件，回滚 = 删新建文件）；
  - `meta.json` = `rel / action / sha256_before / sha256_after / bytes / citizen_id / ts / write_id`；
- **只备份被写的那一个文件**（整库约 11.5 GB，绝不整库复制）；同秒同路径的第 50 次写
  会用 **uuid 后缀**新开目录，**绝不复用/覆盖**旧回滚点；
- `_backups/` 在 `.gitignore` 里 → **不进版本库**（它是运行时数据）；
- **永不自动清理**（裁决 N2）：`kb doctor` 只报告「备份 N 份 / 体积 / 最旧 / 最新」；
  要清旧回滚点必须**显式**跑：

  ```powershell
  python fish.py kb backup prune --keep-days 30 --dry-run   # 先看
  python fish.py kb backup prune --keep-days 30             # 真删（只删 meta.ts 早于 30 天的）
  ```

  `--keep-days 0` 会被拒（"保留 0 天 = 全删"不该由笔误触发）。
- 备份缺失时 `rollback` 明确失败（`backup_missing`，文案改说"可能已被清理：人为删除 / prune"），不会写出半截文件。

实测（临时 rw 库，非真实库）：`create` → 0 → 51 B（`sha256 63428bf28c87`，`eol=lf`，校验=通过），
回执给 `write_id=17-c424ffb2` 与备份目录；`rollback` → 文件被删除；
`append` → 29 → 60 B 且仍是 CRLF；`rollback` → 恢复 29 B，CRLF 保留。

### 5.2 MCP（AI 用的就是这两个工具）

| 工具 | action | 说明 |
|---|---|---|
| `kb` | `vaults` / `tree` / `open` / `search` | 只读。回执头**固定三行**：`source=知识库（未建索引）` / `as_of=<ISO8601>` / `scan=<N files / M bytes / x ms>`（`open` 为 `truncated=… / shown=A/B bytes`）。敏感文件要 `allow_sensitive=true`（明确布尔；`"false"` 是拒绝、`"yes"` → `bad_usage`）**且带有效 token** 才给正文 |
| `kb_write` | `create` / `append` / `update` | 写。`via="mcp:kb_write"`；`mode=ro` → `isError=true` 且文案含 `mode=ro`；`update` 必带 `base_sha256`；**必须带有效 token**（见下）；敏感目标默认拒，`allow_sensitive` 同款严格布尔。**`90-模板/**` 不给任何开关**（强制忽略、不可删） |

两条纪律：

1. **`token` 仍是两个工具的可选参数（永不 required）**——"不 required"只表示协议允许不带，
   不表示不带就能写。**`kb_write` 没有有效 token → `isError=true`**，文案与 board checkin 同口径
   （"先调 `session_start` 拿 token"）；这与 board 是同一个决定：写操作必须能回答
   "是哪个公民的**哪个会话**改的"——审计只记 `unattributed` 等于开一条无法追责的写通道。
   带 token 时 `kb_access.account_id` 记 `session_key`（会话级归属）。
   CLI（`fish kb write`）**不要求 token**：那是人自己在终端里跑，本地可信。
2. **审计不落 query 原文、不回显正文**：`search` 无论成功/失败都只写 `meta.query_hash`（sha256 前 12），
   失败行的 `path` 恒为空串（第二轮 R1）；拒绝行另有 `meta.reason_code`（错误码，可统计）。
   **授权访问会留痕**（第五轮 N9）：读/写两面**只在真授权时**记 `meta.allow_sensitive=true`
   （读 `open`、写 `create/append/update` 同口径），普通读写不长这个字段——于是
   "谁授权改/读了凭证类文件"事后可解释，而普通操作不多出一处隐私面。

## 7. 出问题时的第一反应（失效提示）

| 现象 | 含义 | 下一步 |
|---|---|---|
| `错误[offline]` | 库路径打不开（盘拔了 / 目录改名） | 检查盘符与路径；有 `last_scan` 时 `tree` 会降级显示并标 `stale` |
| `错误[mode_ro]` | 想写一个 `ro` 库 | 由**人**跑 `fish kb vault set-mode <n> rw`（AI 不该自己改） |
| `错误[sensitive]` | 读：命中内置敏感名单（凭证/密钥/.env…）；写：目标同命中（默认拒写） | 读：确认要看请加 `--allow-sensitive`（MCP：`allow_sensitive=true` + token）；写：凭证交人工；或直接在 Obsidian 里打开 |
| `错误[ignored]` | 路径落在 `.obsidian/**` / `.trash/**` / `90-模板/**`（含大小写/尾随空格变体） | 换路径；这三条**不可删、也没有开关能放行**（第四轮起强制项与登记行无关） |
| `错误[path_invalid]` | 坏路径：`..` / 绝对 / 盘符 / UNC / NUL 字符 / 设备名（NUL、CON）/ ADS（`x.md:hidden`） | 给 vault 内相对路径；Windows 不允许 `:` 与设备名 |
| `错误[bad_usage]` | 用法错：`open` 给了目录或空路径、参数类型不对、`allow_sensitive` 写法模糊（`"yes"` / `"on"` / `2`） | `tree` 看目录；`open` 只读单个文件；授权旗写 `true` / `false`（或 `--allow-sensitive` 开关） |
| `错误[too_large]` | 单文件 > `max_open_bytes`（默认 2 MiB），读**和写/备份**同口径 | 用文件工具读，或 `kb open --max-chars` 分段 |
| `错误[media]` | 媒体/二进制（含"png 改名成 .md"） | 用对应查看器；知识库只读文本 |
| `错误[bad_encoding]` | 读：UTF-8 / GB18030 都解不开；写：目标不是 UTF-8 族 | 读：另存为 UTF-8 再读；写：在 Obsidian 里转码（本次未改动文件） |
| `错误[bad_frontmatter]` | frontmatter 值含换行/控制字符，或现有文件头没有收尾 `---` | frontmatter 只收单行标量；多行内容放正文 |
| `错误[stale_base]` | `update`/`rollback` 时文件已被改过 | 重新 `kb open` 拿新 sha；确认要覆盖再加 `--force` |
| `错误[not_found]`（rollback） | `write_id` 与备份记录不符（全串校验，不接受只匹配前缀） | 核对回执里的完整 `write_id`；文件未被改动 |
| `错误[backup_missing]` | 备份被清理了 | 无法自动回滚；用 Obsidian 自带恢复或 git |
| `obsidian_cli=unavailable` | Obsidian app 没在跑（当前实测就是这状态） | **读写都不依赖它**，只是没有增强能力（双链解析等本批不做） |
