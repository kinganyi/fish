## 三、Electron 新增部分

**新 🔴：`--dist` 静态服务在 8 个任务里无主。** §3.4 定义了 `GET /` + `/assets/*`；T06 验收要 `curl 8787/` 200（后端带 `--dist`）；T08 依赖写"T01（…读口支持 `--dist`）"——但 T01 的目标/源文件/验收里没有静态服务，T07 只管 CORS，T08 那句"若 `--dist` 的静态服务落在 T07"等于自己承认没定。生产加载改 `loadURL` 之后这块是承重件：T08 没法开工，T06 那条验收注定红。改法：写进 T01 验收，删掉"若"。

🟠 四条：

1. **托盘只有「停止读口」没有「启动读口」**；preload 四通道无 restart；离线页写"重试"但零 fetch、也没通道。停止之后唯一出路是退出重开，而这是托盘常驻的日常动作。改法：菜单项做启停切换（或加第 5 通道 `restartReader`），离线页重试走它。
2. **T08-3 与 §3.10.3-3 冲突**：收养来的读口退出时不动，而判据取 `meta.pid` 等它 3 秒消失——机器上已有读口时，按自家设计必然红。改法：先 `netstat` 确认端口空闲，或断言 `meta.pid == 壳 spawn 的 pid`。
3. **`ui/package.json` 作用域切分冲突**：T08 要"独占 devDeps 整段"，但 T06 的 vite/vitest/jsdom/testing-library 也在 devDeps。改法：按 key 切（T08 只拿 electron/electron-builder）。
4. **十小节里仍有"说清了其实没定"**：关窗=隐藏、托盘四项与灰显、`will-navigate`/`setWindowOpenHandler`/`setPermissionRequestHandler` 全只有散文，无失败判据（3.10.10 只给了 `webSecurity` 与 CSP 两条机检）。

T08 人时与依赖：算式自洽（5+1.5+0.5+2=9），够开工、偏紧；三条验收都指向可失败点（>80 MB / 三夹具+变异 / pid 3 秒消失）；与 T06 的 `ui/dist`+`base:'./'` 写清了，`--dist` 那半截见上。
