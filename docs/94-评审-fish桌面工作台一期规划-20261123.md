## 四、六类逐类结论

1. **编造与错指**：**未发现 🔴 级"文档说有、代码没有"**；20 组抽查全中（函数行号、6 个缺陷、表/索引、规模读数）。错指都在 🟡：`fish_inject.py`（Y8）、计数与探测次数（Y1）、行号指注释（Y9）。**最不可靠的一处证据**是 `import fish=824.4ms` 与 `doctor=50,466ms`：复跑 341ms 与 27s，差 2.0–2.4 倍——单次样本被写成表里的"实测"，易被读成稳定值。
2. **一致性**：R-01~R-10 有 7 条有落点；G8 无主且互斥（🔴-1）；R-10 四自检只落一（🟠-2）；三判定无字段（🟠-3）。反向外延：`pid`、start/stop 脚本、`/api/meta` 是架构新增，合理但应回写 PRD。
3. **可失败性**：真能红的不少（A-6 调后端函数、A-7 的 405、FakeProvider 变异、`SqliteProvider` 全 raise 仍须绿、EQP 前缀区间对照、白名单反射）。三类病：跑不起来（T02）、跑通即过（T04 首条、A-5、`或 empty:true`）、量级不匹配（A-3 的 2,000 行）。
4. **只读纪律**：三个已知写点自己全点了（doctor 写连接、gov commit、自愈回写）——加分；但 §3.9-1 被自家刷新路径否掉（🔴-2），且 PRD"不写文件"与 PID/缓存文件的冲突未认领。
5. **性能**：全是单次样本，复跑同量级，方向成立（doctor 异步、inject 独立、corpus 骨架 + `count` 默认 false）；§3.8 用"预算 vs 实测"两列是对的。不自洽处 Y7；首屏 <1s 无任何实测。
6. **诚实度**：§0 与 R9 是全文最好一节（明说没装依赖、没跑前后端、没压测、没验壳），X-01 还主动纠了任务书。唯一越界是把 §2.5 三条命令写成"判据"而非"待跑清单"。
