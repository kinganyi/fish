## 二、原始对话数据在哪（两宿主，均可读）

### DSH
- 路径：`I:\app\DSH-Home\home\sessions\<workspace编码目录>\<session-id>\session.v4.jsonl.zstd`
- 体量（实测）：**513 个会话 / 519.7 MB（压缩）**；9 个工作区（learn 443、工作杂项 33、知识库AI 28、anyi-ppt 8…）；近 7 天 146 个。
- 格式：zstd 压缩的 JSONL（Python `zstandard` 0.25.0 可用，实测解压正常）。事件类型（抽 12 会话统计）：
  `user/message`(229) `assistant/message`(1444) `tool/call`(1850) `tool/result`(1864) `step/start|end` `turn/start|end` `system/message` `agent/inbox/spliced` `session` `session/title` `compaction/prune`(15) `compaction/summary`(2) `workspace/changes` 等。
- 关键结构（实测样本）：
  - `session` 头：`{version:4, id, createdAt, cwd, parentSession, origin:"subagent", delegationDepth, agentPreset}`。
  - `user/message.data`：`{content:[{type:"text",text:…}], source:{kind:"hooks-claude-code"}, role:"user", id}`。
  - `assistant/message.data`：`{turn, step, message:{role:"assistant", content:[{type:"reasoning"},{type:"text"},{type:"tool-call",name,arguments}], source:{provider,model}}, usage}`。
  - `tool/call`/`tool/result`：独立事件，带 `callId`/`toolCallId`，结果 `content:[{type:"text",text:…}]`。
  - `compaction/prune.data`：`{shadowedRange, shadowedSeqs, shadowedTokenCount}` → **只标记"不进上下文"，原始消息仍在日志里**。
- 内容类型分布（抽 40 会话）：`reasoning` 4448 / `text` 1194 / `tool-call` 6062 → **reasoning 占大头**，采集需默认排除。
- 隐私事实：`user/message` 里**真的含 fish token 明文**（SessionStart 注入块），采集必须脱敏。

### WorkBuddy
- 路径：`C:\Users\15596\.workbuddy\projects\<workspace-key>\<session-id>.jsonl`（另有 `sessions/*.json` 只是心跳元数据，不是对话）。
- 体量（实测）：**9920 文件 / 4.2 GB**；单会话可达 348 MB（含工具渲染文件）。
- 格式：JSONL，行类型 `session-meta` / `message` / `ai-title` …；`message` 行带 `{id,timestamp,type:"message",role,content:[{type:"input_text",text}],sessionId,cwd}`；带 `providerData`/`_meta`。
- 结论：**两宿主都能采**，但要各写一个 adapter（DSH 解码 zstd + 事件模型；WB 直接读 JSONL + 行模型）。

## 三、体量与运维事实

- DSH 压缩 520 MB → 解压后约 2–3 GB（样本 2.37 MB 解压 / 0.13 MB 压缩，约 18×）。
- WB 4.2 GB（含渲染 txt 等非对话文件，需过滤）。
- 文件会**持续追加**（活跃会话 mtime 秒级变化）→ 采集必须增量（mtime+size 游标），不能全量重扫。
- DSH 日志有 `compaction/prune`：被裁消息仍在文件里；采集可全采，但可打 `shadowed` 标（区分"当时在上下文里" vs "已压缩出去"）。

## 五、边界与未决（必须在方案里回答）

1. **存哪**：主库（现在 5.4 MB）还是独立 `data/corpus.sqlite`？GB 级语料不宜进主库。
2. **存什么**：原文全文 / 去 reasoning 的对话 / 只存切片+指针（原始日志仍在）？三者的检索能力与隐私风险不同。
3. **打标**：host / workspace / project / session / citizen / origin(subagent?) / turn/step / time / shadowed；缺项目时怎么办（"未分类"+cwd）。
4. **隐私**：token 明文（已实测）、reasoning、群聊/私聊、凭证文件；脱敏规则与保留期；删除与回滚（会话被删/改写）。
5. **检索**：FTS5 中文分词现实（现有 `extract_terms`）、BM25 排序、时间衰减；**排名算法交给主 AI 研究线，本层只提供接口**。
6. **推送**：什么时机推（prompt/tool_after/inject）、推什么（片段+链接还是摘要）、防噪音（去重/冷却/阈值）、采纳回填。
7. **知识库**：用户说"纳入知识库的一部分"——是 fish 记忆库、还是 Obsidian vault？vault 是 ro，不能自动写。
8. **多宿主**：DSH + WorkBuddy 先行，Codex/ZCode 留 adapter 位。
9. **体量治理**：增量游标、原始日志不复制、定期 compaction、冷热分层。
10. **与主 AI 研究线的关系**：本层交付"语料 + 接口 + 打标"，不交付"最优召回"；接口要能替换排序器。
