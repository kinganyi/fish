收敛后的形状是：**词表 1 个文件（3 条字面量）+ 注册表 1 个文件（spec 字面量）+ 语义分类 1 处（`COLLECTOR_SCRIPTS`）**。第 8、12、13、14 四处之所以不派生，不是因为难，而是因为它们**不是同一个事实**：脚本并集是「文件清单」、`--host choices` 是「产品支持的推送宿主」、`hosts=` 是「调用方显式选口径」、环境变量表是「凭证通道」。

**三点必须说清的口径**：

1. **`protocol` 归词表，不归注册表推导**。实测（本节末）：把 `fish_naming.SESSION_HOSTS` 改成「调用时从注册表推导」，再跑 `verify_hosts` 的 ⑥-变异（摘掉一个 spec），`consistency()` 返回 `warnings=[]、ok=True`——**判据失去判别力**。数据侧证据支持词表独立存在：`tool_activity.session_key` 实际前缀只有 `codebuddy`（26,200 行）与 `dsh`（861 行），但 `citizens_all.host` 有 9 种写法（`dsh` 277、`cli` 62、`workbuddy` 11、`codebuddy` 7、`zcode` 2、`unknown`/`dsh-desktop`/`codex` 各 1、空 1）。`workbuddy:` 前缀当前 **0 行**，它仍是**历史契约**：删掉它不会报错，只会让老键静默失效（`split_session_key` 返回 `("","")`，见 `fish_naming.py:241`）。所以词表是「对外世界已有事实的登记」，不是注册表的函数。
2. **语料适配器选择不进 `fish_hosts`**。理由是可证伪的三条：①它是类对象而非词，塞进 spec 等于让「数据」持有「实现」；②`fish_hosts` 的探测不读语料层，今天的 `corpus_adapter_hosts()`（`fish_hosts.py:1619-1634`）为了核对一条关系**延迟 import 语料层**，是唯一一条回边；③让 `fish_hosts` 拥有它会把 zstd 依赖拖进探测。正确落点 = 词表（白名单）+ 实现表（`fish_corpus`）+ **import 期两侧对拍**。任务书把这一项列给 `fish_hosts`，我给的结论是「不进」，并要求用一条判据钉住（第 8 节 M4）。
3. **不新增第二份「宿主能力」词表**。`hooks_supported`（能力）与 `hooks_install`（本工具是否负责）是两件事——`zcode` 就是前者真、后者假（`fish_hosts.py:333,354`）。混成一个字段，就会重演 A2 那类「声明与已装不一致」的假否定。

## 3 兼容层：四个名字的处置

原则：**名字一律保留，值改为派生**；只有这样才能「改动面小 + 可回退」，同时满足「改一处全变」。四个名字都**没有**被 17 条锁定判据直接引用（`grep TARGETS p0/test_*.py` 无命中），但 `SESSION_HOSTS` 被 `verify_hosts.py:240` 用 tuple 相等钉住——**顺序也算**。

| 名字 | 处置 | 实现 | 为什么 |
|---|---|---|---|
| `fish_naming.SESSION_HOSTS`（`:216`） | **保留名字** | `= fish_hosts_vocab.PROTOCOL_VOCABULARY` | 顺序逐字保留 → `verify_hosts` ④ 的 `PROTOCOLS == tuple(SESSION_HOSTS)` 不变；`split_session_key`（`:241`）只做成员判断，行为不变 |
| `fish_corpus.ADAPTERS`/`HOSTS`/`DEFAULT_HOSTS`（`:51-56`） | **保留名字** | `ADAPTERS = {h: _IMPLS[h] for h in vocab.CORPUS_ADAPTER_HOSTS}`；`HOSTS = tuple(ADAPTERS)`、`DEFAULT_HOSTS = tuple(ADAPTERS)`（现值即 `("dsh","workbuddy")`） | `test_corpus_contract.py:170` 与 `adapter_for`（`:140-145`）行为不变；白名单少写/多写一条在 import 期硬失败 |
| `install_hooks.TARGETS`（`:93-96`） | **保留名字** | `TARGETS = {spec.id: (lambda s=spec: _target_path(s)) for spec in fish_hosts.spec_all() if spec.hooks_install}`；`_target(host, file)` 改为 **live** `fish_hosts.spec_of(host)` | dict 的键来自注册表（import 时快照），**解析**由 live spec 决定；`desired_hooks` 的未知宿主仍抛 `ValueError`（保留 `:185` 文案形状） |

### 4.1 波次依赖与并行边界

W1 是 W2 的前置（`fish_hosts` 要 import 词表，词表必须先存在）；W3 依赖 W2（渲染要吃 `hooks_plan` 与常量 `PROTOCOLS`）；W5 依赖 W3（`mcp_entry` 字段与 `hooks_install` 同批落在 spec 上）；W4 与 W3 **可以并行**（文件面不相交：`fish_corpus*` vs `install_hooks*`），但**不许同 commit**——否则回退粒度变粗；W6 完全独立，可以先做。

不建议全并行的理由是可证的：W3 与 W4 都会让 `pytest test_surface_naming.py` 与 `test_corpus_contract.py` 同时变红时无法二分定位；而本轮全部判据的价值就在「红的时候能立刻指认是哪一处的字节变了」。所以顺序上宁慢一步。

## 5 `install_mcp.py` 泛化：结论是「只读化 + 参数化，不启用多宿主写入」

现状 64 行：写死 `~/.workbuddy/mcp.json`（`:15-16`）、写死 `FISH` 条目（`:21-28`）、`main()` 直接备份→写→回读（`:31-60`），**没有 `--check`**，跑起来就写盘。

## 9 「万无一失」的标准（可失败的表述）

一句话：**「万无一失」= 上表 E/S/R 三组判据全部绿，且每一条都先被证明过它会红**；没有变异自证的绿不算绿。

展开成六条可失败判据：

1. **改一处全变**：加一条 spec（不动任何消费方）后，`TARGETS`/`--host choices`/`desired_hooks` 三处**自动跟随**（S1）；任何一处仍写死 `("dsh","workbuddy")` → 红。
2. **词表不被推导吞掉**：注册表缩水时 ⑥-变异仍能产 warning（S2 + `verify_hosts` ⑥-变异）；实测「注册表推导」写法下 `warnings=[]、ok=True` → **该写法直接判红**。
3. **字节等价**：`--check` 输出零差异（E2）、`desired_hooks` 两份 sha256 相同（E1）、真实配置双指纹不变（E3）；任何一处差一个字节 → 红。
4. **热路径不退化**：`import fish_activity` 相比基线 +≤10 ms、`import fish_naming` ≤5 ms（C3）；`fish_activity` 若间接 import `fish_hosts` → 红（实测 +379 ms）。
5. **零循环**：AST 静态无环（C1）+ 24 种 import 顺序全 0（C2）；任何一条反向边 → 红。
6. **已知红不搬家**：四组回归的**失败集合**与基线完全相同（R 表）；新增任何一个失败条目 → 红。

以上六条同时成立，才允许说「A1 完成」。它们的共同性质是：**先能被坏输入弄红，才有资格在好输入上说绿**。
