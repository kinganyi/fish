## 0 一页结论

- 要补的断链只有一条：**fish 有"提炼后的记忆"，没有"当时说的话"**（F:8-10）。缺的不是存储技术，是"可回到原话的那一层"。
- 两宿主日志都可读、体量真实：DSH **514 会话 / 521.1 MB**（实测 03:1x；F:28 记 513/519.7 MB，差值是活跃会话仍在追加，F:50），WB **1387 个 jsonl / 4102 MB**（实测；F:42 的 9920 文件含渲染产物）。
- 采集**不能依赖 hook**：hook 的 `transcript_path` 恒为空（A:54,70,90；现场心跳文件 `p0/data/_audit/posttool-push/_heartbeat` 里该字段就是 `""`），只能扫盘 + 增量游标。
- 两条开源路线各给一半答案：dsh-world 给"增量投影 + 幂等 + 游标 + 只留对话"（W:23-28,59）；dsh-agent-soul 给"门牌优先、一手原文不搬家"（S:8,27-30）。语料层要的是这两半的**采集与定位**，不是它们的检索（W:45；S:38 都没有 FTS/向量）。
- 两条反直觉实测（514 会话全量扫头部）：**459/514 是子代理会话**（`origin=subagent`；depth 1:337 / 2:123），主会话只有 55；**514/514 的 cwd 都没命中 `workspace_map`**（4 条映射全指向子目录，而会话 cwd 是工作区根，441 条就是 `workspace\learn`）→ 用户明确要的"分项目打标"，现状是 **0 覆盖**。
- 采信口径：子代理语料**默认入库**（否则丢掉 89% 的语料，W:27 的"排除子代理"在这里不适用）；推送侧默认标「（子代理会话）」，推不推见 O11。
- P0 只承诺一件事：**能采集、能打标、能查回原文、能推 1 条并回填采纳**。其余（算法、跨宿主扩展、KB 自动写入）都不在 P0。

## 1 背景与目标

### 1.1 现在断在哪（每条都能落到现场）

| # | 断链 | 现场证据 | 用户可感知的后果 |
|---|---|---|---|
| 1 | fish 库里没有消息/对话/transcript 表，19 张业务表全是编码与状态 | F:8-10（SCHEMA 清单） | 用户问「上次那个结论」只能靠已编码记忆；**没被提炼的讨论等于不存在** |
| 2 | 原始对话在宿主日志里，fish 从不读 | DSH 514 会话 / 521.1 MB、9 个工作区（F:27-28，实测）；WB 4.1 GB jsonl（F:42，实测） | 宝藏就在盘上，系统视而不见 |
| 3 | hook 拿不到 transcript 路径，拿不到"这次说了什么" | A:54,70,90 + 心跳实测 `transcript_path:""` | 任何"靠 hook 顺手采集"的方案都会静默少采；必须独立扫盘 |
| 4 | 现有推送推的是"编码 + 标题 + 理由"，不是"当时原话" | F:13-14（push 管线）；P:10773「只递标题+编码+一句理由」；实测 push_log 1190 条（10-24T10:31Z→10-26T19:21Z） | 推送只能提醒"有这条记忆"，不能回答"我们当时是怎么说的" |
| 5 | 同一批数据里 reasoning 占大头，直接采会把噪音和隐私一起搬进来 | F:37（40 会话：reasoning 4448 / text 1194 / tool-call 6062）；F:38（user 消息里含 fish token 明文） | 全量照抄 = 又大又危险；必须"只留对话" |
| 6 | "分项目打标"现在落不了地 | 实测：514 会话 cwd 无一命中 `workspace_map`（4 条映射全指向子目录；441 条 cwd 是 `workspace\learn` 根）；`project_stints` 84 条里 74 条是"未分类"且按公民不按会话（P:520-525） | 就算采到语料，也只能按"工作区"归类；问"这个项目以前怎么说的"仍答不准 |

### 1.2 三个互不重叠的产品目标

| 目标 | 一句话 | 判定锚点 |
|---|---|---|
| G1 可收集 | 两宿主全量增量采集，不丢、不错、可重建 | 覆盖率 ≥95%，重跑幂等，坏文件降级可见（§6） |
| G2 可定位 | 任意片段能回到**原文**（门牌 + 字节偏移），且查得动 | `read(pointer)` 取回的文本与源日志逐字一致；P95 延迟达标（§6） |
| G3 可用 | 现有推送系统能推**1 条原始片段**并回填采纳 | 一次「之前讨论过 X」至少推出 1 条，且 24h 内不重复（§3 P0-6） |

> 定位口径：本层是**知识库的原材料层**，不是知识库。它只保证"原话可定位、可引用"，不保证"哪条最该被推"——后者归主 AI 研究线（§8.2）。

## 3 需求池

优先级口径：**P0 = 最小可用闭环（采集 + 打标 + 可检索 + 能推送 1 条）**；P1 = 让闭环可用/可控；P2 = 扩展位。
「验收判据」一律写成**能失败**的形式：前半是正常输入要绿，后半是坏输入必须红。

## 5 隐私与治理

### 5.1 默认不进语料（黑名单是默认，白名单才入库）

| 内容 | 默认 | 理由 |
|---|---|---|

| `tool/call` 参数、`tool/result` 正文 | 不入 | 含文件内容、命令、凭据（F:35-36）；工具结果 ≠ 对话 |

### 5.2 脱敏（三道，缺一不可）

| 道 | 位置 | 判据 |
|---|---|---|
| ① 落盘前 | adapter 写段前 | 命中即替换为 `〔已脱敏:类型〕` 并累加 `redacted_count`；不许整流丢弃 |
| ② 出口 | `search`/`read` 返回前再扫一遍 | 与①用**同一份**规则常量（避免"两处各写一份"的假绿，P:296-297 的既有纪律） |

## 8 与主 AI 研究线的接口

> 本层交付"语料 + 打标 + 接口"，**不交付最优召回**（F:79）。原则：**过滤在层内，排序可替换，输出形状不变**。

### 8.1 对外查询契约（CLI / MCP / 推送共用同一份实现）

```text
corpus.search(
  q: str,                        # 用户原话（必填）
  terms: [str] | null,           # 调用方已切好的词；null → 层内切（现用 P:8526 的 2-4 字 n-gram）
  filters: {                     # 全部 AND；空 = 不限
    host[list], project[list], workspace[list], session[list], citizen[list],
    role[list], origin[list], time_from, time_to, include_shadowed: bool
  },
  limit: int = 8,
  budget_tokens: int | null,     # 返回片段的字符预算（超了截断并在 meta 声明）
  ranker: str = "default"        # 可替换点，见 8.2
) -> {
  hits: [{
    pointer:   "log:<host>:<session_id>#seq=<n>"   # 有 seq 的宿主
             | "log:<host>:<session_id>#line=<n>", # 无 seq 的宿主（WB）
    host, session_id, session_title, role, occurred_at,
    project, workspace, citizen_id, origin, shadowed,
    snippet: str,              # ≤240 字，已脱敏，可直接进推送
    chars: int, score: float, ranker: str,
    why: [str]                 # 打分依据，必须可解释（K2/K8 靠它复盘）
  }],
  meta: { total_matched, returned, ranker, filters_echo, degraded[], as_of, truncated }
}

corpus.read(pointer, max_chars=8000) ->
  { text, truncated, redacted_count,
    source: { path, byte_from, byte_to, sha256, missing: bool },
    tags: { host, session_id, project, citizen_id, origin, occurred_at, shadowed } }

corpus.stats(scope?)   -> { by_host, by_project, sessions_seen, segments, degraded[], orphan[], lag_sec }
corpus.forget(scope)   -> { deleted_segments, tombstones_created }
corpus.rebuild(scope, dry_run) -> { planned, written, skipped_by_tombstone }
```

> 链接形态：P0 的"链接"就是门牌本身（`corpus.read(pointer)` 可直接解析、可粘进对话或笔记）；**不做 HTTP 链接、不做 UI**（N5 待定）。这也是"原文不搬家、只给门牌"（S:8）落到用户可感知处的唯一形态。

### 8.2 召回算法可替换点（研究线只管这一处）

| 点 | 契约 | 不许做的事 |
|---|---|---|
| `ranker` | `rank(candidates, q, ctx) -> [(pointer, score, why)]`；`candidates` 是**已过滤**的段集合 | 不许自己扩过滤条件（越权取数）；不许增删 hits 字段；不许改 `snippet`（脱敏已做） |
| `tokenizer` | `terms(q) -> [str]`，替换现有 `extract_terms`（P:8526） | 不许改 `filters` 语义 |
| 索引 | 层内自建（FTS5 或 n-gram 表），位置在 `corpus.sqlite` | 不许挂到 `memory_fts`（P:955）上 |
| 默认实现 | 必须提供**无外部依赖**的词法排序，保证研究线未就位时 P0 可用（W:45 / S:38 都无 FTS/向量，正好证明"没有算法也能跑"） | 不许把 P0 的通过条件绑在外部服务上 |

**返回形状冻结**：研究线换算法时，`hits[]` 的字段名与语义不得变——推送渲染、采纳回填、体检判据全部依赖它。

### 8.3 三条不可越过的硬约束（写给将来的算法/架构）

1. **过滤先于排序**：`filters` 必须在候选进入 ranker 之前生效；否则跨项目/跨公民的段落会经排序"合法"漏出。
2. **门牌必须可回原文**：任何 hits 必须能 `read` 出与源日志逐字一致的文本；回不到就标 `missing`，不许用摘要顶替（S:8「一手层永远优先于任何转述」）。
3. **推送即记账**：凡推出必写 `push_log`（`conv:` 前缀 + 显式 project），凡被读必回填 accepted（P:2539/2679）——没有记账的推送等于永远算不出 K7。
