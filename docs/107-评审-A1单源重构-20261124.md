## 3 分级发现

### 🔴 致命：无

### 🟠-1 `install_hooks.py:159` 把「事件」退回第二份真相（W3 遗留）

- **位置**：`p0/install_hooks.py:103`（派生）与 `:159`（字面量，覆盖前者）
- **证据**：`git show ef2c686` 只加了 `+REQUIRED_EVENTS = tuple(INSTALL_SPECS[0].events)` 与三处校验，`git show d3f0448` 里旧字面量**没有任何 `-REQUIRED_EVENTS` 删除行** → 旧行原位保留。探针：给 dsh/wb 的 spec 各加 `Stop`（含 `hooks_plan`）后 `REQUIRED_EVENTS` 仍是 4 个；构造「文件只有 4 事件」的副本跑 `cmd_check` → **exit 0（判一致）**，而 `desired_hooks('dsh')` 含 `Stop`、`merge_hooks` 会写入 `Stop`。即 `--check` 与 `--apply` 对同一份目标给出相反结论。
- **为什么严重**：这正是本工具存在的理由（「写错了不会报错，只会某个功能悄悄没了」）的同型失败；设计 §3 明确要求该常量「取 `INSTALL_HOSTS[0]` 的 events 并 assert 同序」。
- **缓解**：`test_two_hosts_four_events_and_one_collector`（`:313`）用 `set(hooks)==set(REQUIRED_EVENTS)` 会在 dev 期红，所以只覆盖一半（测试能抓、生产判据不能抓）。
- **改法**：删掉 `:159` 整行（及其上方注释）。修后 `:103` 派生成为唯一来源，`_ORDER_MISMATCH` 守卫才真正生效。补一条判据：`tuple(INSTALL_SPECS[0].events) == REQUIRED_EVENTS`（当前 import 期只校验各 spec 之间同序，不校验最终导出值）。

### 🟠-2 语料 `--host all` 仍写死两台（W4 同类残留未收口）

- **位置**：`p0/fish_corpus.py:1443`（`run_cli` 的 ingest 分支）；配套 `:1738/1746/1749/1771` 的 choices
- **证据**：AST 字面量普查命中；`ADAPTERS/HOSTS/DEFAULT_HOSTS` 已派生（`:70-72`），但 ingest 路径绕过 `DEFAULT_HOSTS` 自己写死二元组。后果：白名单加一台（且实现表同步，import 期对拍通过）后，`ADAPTERS` 自动变 3 项，而 `ingest --host all` **静默只采 2 台**——与 W4 自己要防的「少一行 = 某个宿主的语料静默停采」完全同型，且 import 期硬失败判据**给不出警报**（两侧一致）。
- **改法**：`hosts = DEFAULT_HOSTS if host_arg == "all" else (host_arg,)`；四行 choices 改 `["all", *DEFAULT_HOSTS]`。补判据：把 `CORPUS_ADAPTER_HOSTS` 加一项后断言 `run_cli` 收到的 `hosts` 含新宿主。

### 🟡-1 `test_surface_naming.py:432/452` 没有「patch 生效」判据（工程师自述属实）

- **证据（我独立做的实验）**：把 `install_hooks.py` 复制到 `%TEMP%`，只改一处——`cmd_check` 里 `desired = desired_hooks(...)` 改成 `_render_direct(...)`（内部持有导入时的真函数引用，模拟「直调 spec 渲染」）。结果：`:432`、`:452` 两个测试体**仍然通过**（exit 2，`"方言契约"`/`"空白"` 都在文本里）。原因：红来自 `validate_hooks` 读**文件**里的非法 matcher，而不是 `desired` 的比较；绕过变体甚至多打一行「与目标不一致」也仍满足断言。
- **能红的断言（我验证过判别差）**：`apply_host("dsh", target)` 写出**合法**配置后，`with mock.patch.object(ih,"desired_hooks", return_value={})` 跑 `cmd_check` → **经模块全局名 = exit 2**（desired 变空 → changed），**直调 spec 渲染 = exit 0**（desired 等于文件）。对照组（不 patch）必须 exit 0，以证明红只可能来自 patch。
- **改法**：新增 `test_cmd_check_goes_through_module_global`（上面两条断言一起写）；预计 42 → 43，属判据增强，需在设计/记录里登记。

### 🟡-2 W5 缺省=写：与设计 §5 相反（按任务书是合理的），但配套有缺口

- **判定**：**合理**——任务书要求「默认行为与输出文本与现在一致」，现行为就是写；把缺省改只读会让既有调用静默不写（另一种「悄悄没生效」）。旧/新写档代码逐行对照：步骤 1–4 与打印文案一致，唯一差异是回读断言从 `fish["command"]==PY` 改为 `fish==want`（更严，不改输出）。
- **缺口**：① 设计 §5 至今仍写「入口拆两档——`--check`（默认档）」，未同步，后来人按文档理解会错；② `install_hooks` 有 D2 家目录护栏（我验过 `_refuse_default_home` 是纯函数、拒绝文案正确），`install_mcp` **没有**——一条不带参数的 `python install_mcp.py` 会直接写真实 `~/.workbuddy/mcp.json`（备份+回读有，但无「环境变量未设 → 拒绝」护栏）。

### 🟡-3 `verify_hosts.py:240` 的「词表同源」判据被弱化成恒等式

- 现状：`fish_hosts.PROTOCOLS == tuple(fish_naming.SESSION_HOSTS)`，两边都派生自同一叶子 → 恒真。它仍能抓「有人把某一边重新写死成不同值」，但**抓不到「词表本身漏一条」**（那种情况两边一起漏，判据照绿）。
- 建议：加一条变异——把 `fish_naming.SESSION_HOSTS` 替换成少一项的元组后，`check_protocol` 必须红（现在会红吗？会，因为 tuple 不等 → 但那是「检测重新声明」，不是「检测漏项」）。更实的判据：对每个 spec.protocol 与 `PROTOCOL_VOCABULARY` 做**双向覆盖**（`set(PROTOCOLS) == set(spec.protocol)-{""}`），漏项时红。

### 🟡-4 `--check` 文本指纹必须带捕获方式，否则跨人复核会打架
