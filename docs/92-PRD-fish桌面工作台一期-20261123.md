## 一、一页结论

这一期只做一件事：**把 fish 已经躺在库里的东西，变成一眼能看见的六块画面，不给任何写入入口。**

用的人只有安逸一个。标准不是"六个页面都在"，是三条：

① 早上打开，5 秒内能从全景判断今天系统有没有问题——有没有东西没闭合、数据是不是还在进来；
② 任何一条记忆、一段语料、一次推送，两次点击内看得到出处；
③ 每个数字都对得上库里的真值；读口没起、库是空的、语料没有，它就说"没有"，不说 0，更不填假数据。

形态先是浏览器能看的本地网页，Electron 壳最后套（89 §10）。

## 二、产品定位与边界

### 2.1 为什么是"内部工具 + 留产品化口子"

三条理由：

- **只有一个用户在提需求**。多用户、账号体系、安装包分发，做的全是没人会用的东西。
- **判据能立刻证伪**。"我自己明天还会不会打开它"——打开率掉了就是设计错了，没有解释空间。89 §2.3 说透了：「只有天天用它的人，才有资格判断哪里该改」。
- **当前价值在"看见"，不在"操作"**。fish 不缺编辑能力（CLI 与 25 个 MCP 工具都在写），缺一个地方让人一眼看出"哪里不对"。

但内部工具不等于一次性脚本，三条口子现在就留（都来自已拍决策）：

1. **数据面与 UI 分层**：壳只经 HTTP 说话，不碰 SQLite（K6）；读口走 provider 化（D3）。这决定将来能不能上云——K9 已认定上云必然是"服务端权威 + 只读缓存"，今天直读 SQLite 的投影函数就是明天的债。
2. **契约锚点**：消费方认 `schema: "fish-ui/1"`，不认表结构（K7）。
3. **聚合在 Python 侧算完**：前端不自己算"是否闭合""是否撞车"。第二份领域实现才没有生长空间——dsh-fish 就死在它上面（K8）。

### 2.2 一期明确不做（八条）

1. **任何写入**：不改库、不写文件、不发帖、不签到、不闭合、不删。11-22 已拍板。
2. **多用户 / 账号体系 / 权限模型**：唯一用户不需要。
3. **云端同步**：K9 的服务端权威还没建，现在做等于给不存在的服务器写客户端。
4. **DSH 面板集成 / 多端同构**：D2 已定二期；U-03 的诉求依赖"先有能跑的界面"，顺序不能倒。
5. **AI 执行**：E1 已定二期，接之前必须先验证 `DSH_HOME` 隔离（89 §9 第 5 条）。
6. **打包与自动更新**：R1 把 PyInstaller + 杀软误报列在最高级，一期用网页形态绕开。
7. **凭证回显**：只显示"去哪拿"，永不显示值（铁律 15）；且见 2.3，读口无鉴权时连路径都不该进界面。
8. **UI 内堆开关**：U-06 原话「不是管理后台，不是选项和开关的堆叠」——一期配置项只显示、不可改。

### 2.3 一条被忽略的安全约束，它直接改了产品设计

`fish_ui.py` 今天仍在给所有响应发 `Access-Control-Allow-Origin: *`（第 510、518 行，今日原文），且**无鉴权**。D4 在 11-22 已拍板"修"，代码今天还是 `*`。

这不是安全债，是产品约束：**本机任意网页都能读走读口全部投影**。所以一期界面按"可能被任意本机页面读到"设计——不显示凭证位置、不显示未脱敏原文、不显示完整会话键（读口已在做短署名 `名字·dsh#88f9`，这点是对的）。等 D4 修完、壳内只放行自己的 Origin，再放宽。这条约束不回答"要不要做"，它划"一期界面内容的天花板"。

## 三、用户与场景

### 3.1 他不是管理员

这是本 PRD 最重要的一句判断。他不关心"配置得对不对"，他关心**今天这套东西有没有坏、有没有东西没收拾**。所以：首屏先结论（一个灯 + 一句人话），再数字，最后明细——反过来就是管理后台；每个"不对劲"必须配一个一次点击能执行的动作（一条可复制命令）；不设"设置"入口。

5 秒判断的判据（本文初值，可调；验收只验"越线必变色"，不验具体数字）：红灯 = 读口不可用 / 任一宿主采集中断超 24 小时 / 有超 30 天未激活的未闭合项目；黄灯 = 有未闭合项但不到红，或某数字取不到；绿灯 = 以上都不是。

### 3.2 四个真实场景

**A · 早上开机（旅程 6）**
第一眼看全景：灯是黄的，写着"1 个项目 41 天没闭合、1 个看板有 2 个会话挂着没下板"。点开清单，每条后面跟一句可复制命令。他未必当场处理，但知道今天有这个尾巴。这是 U-07 原话：「这类事情需要在 UI 层面让用户感知到，并知道是什么事情没有闭合」。

**B · "之前讨论过"（旅程 4，U-25）**
他记得前几天讨论过一个方案，记不清在哪个会话。进语料视图搜一个只有那次讨论才出现的词，命中三段，右边是原文，带宿主/项目/时间。他看到的不只是文字，是**出处**。U-25 原话是「精准推送原始数据段落和链接」——一期先把这条路修成人工可走。

**C · hook 断流（真实事故，89 §5.2）**
上次某宿主 hook 断流 11 天，没有任何地方能看见。现在采集活性矩阵里那行是红的："最后采集 2026-11-12，已停 11 天"。这块的价值不在功能，在**把沉默的失败变成看得见的失败**。

**D · 收工前看谁还没下板（旅程 3 半，U-20）**
看板与协作首屏按"多方在前、单人在后"列板，每板显示在场人数与最后动态时间。谁挂着没下板一眼可见；不必知道那是谁，短署名 `dsh#88f9` 足够他去 DSH 里找。

| 差异 | K10 | 11-23 口述 | 本文裁决 |
|---|---|---|---|
| 活动 | 独立一视图 | 未列 | 降为「看板与协作」下钻页（4.2①） |
| 推送 | 未列 | 独立一块 | 升为「推送与注入」 |
| 知识库 | 隐含在记忆 | 并入「记忆与知识」 | 纳入一期，深度收窄（4.2②） |

### 4.2 三处必须解释的裁决

**① "活动"为什么降为下钻页？** 它回答"谁在动、动了哪里"，与看板同源（`tool_activity` 与 `presence` 是同一协作面的两个投影）；占顶栏位会稀释协作面，做下钻页反而成了证据层——看板说"我在写 A"，动作流证明"他写的是 B"。降位不降内容：虚拟滚动、游标增量、过滤一样不少。

**② 知识库为什么必须在、但必须浅？** 必须在：11-23 亲口把"记忆与知识"算成一块。必须浅：U-24 的搜索边界（整库跳过还是允许持久索引）到 10-27 仍未拍板（UI需求全景 §6 第 3 项）。一期取最保守读法——**只读 vault 注册表 + 根两层目录**，这两层在 `kb_vault`/`kb_asset` 表里，不涉及全库扫描与搜索语义。

**③ 画像为什么只留"注入预览"？** 一期想知道的是"新 AI 收到的我是谁对不对"，那是体检不是编辑。U-13 的"手动采纳"确实存在，但要写 `profile_slots`，必须等写入期。而 `profile_proposals`/`profile_questions` 两张表已存在——数据在、没有显示的地方，正好是一期该补的（G4）。

## 六、关键交互与状态

### 6.1 四类空状态，四句不同的话

**① 读口未起**：整屏一条说明 + 启动命令 + "重试"。**不得显示任何数字，不得显示骨架数字**——读口没起和"库里是 0"是两种现实，混起来会让人以为数据丢了。

**② 库为空（刚建库）**：每格显示"空库"，附一句"怎么写入第一条"（`fish remember ...`）。**不显示 0**：0 是读数，"空"是状态。

**③ 语料没数据**：分三态——"语料库不存在"（没接）、"库存在但没有段"（接错或没采）、"有段但没有命中"（词不对）。三句文案不同，因为处理方式不同。

**④ 首次使用**：一期不做向导（没有写操作可引导），只给一页说明：这是什么、为什么现在没数据、数据从哪来。

### 6.2 加载态

首屏 < 1s（88 §6.3）。超 300ms 显示骨架，但**骨架只占位、不给假数字**；超 8s 转"仍在读，已等 N 秒"+ 取消。全景低频轮询（读口注释写"2 秒轮一轮就够"），动作流高频但只取增量。

### 6.3 错误态

必须三段：**出了什么**（贴后端原文，不许改写成"加载失败"）→ **为什么**（判不出就写"原因未判到"）→ **你能做什么**（一次点击能执行的命令）。禁止白屏，禁止只写"出错了"——不说原因的仪表盘，等于把可排查的问题变成不可排查的问题。

### 6.4 不许用假数据填平空白（写死）

一期不允许任何硬编码示例、演示数据、占位数字——连"示意的 1,234"也不行。空就写"没有"，缺就写"缺"，不知道就写"判不到"。变异自证见 A-1。

## 七、非功能要求

- **性能**：首屏 < 1s（88 §6.3）。列表按 **10 万行量级**设计虚拟滚动——语料 108,158 段（主理人 11-23 核实）、动作流 26,182 行（88 §6.1），取大者作设计上限。虚拟滚动是架构项，不是优化项（89 §5.3）。
- **窗口**：最小 1280×720（六格顶栏 + 侧列 + 详情的下限）；100%/125%/150%/200% DPI 不糊。
- **视觉基调**：默认状态就要好看（U-06）。一期只做亮色。判据是"不配任何开关时它是否好看"。
- **键盘**：Tab 顺序合阅读顺序；`/` 聚焦搜索；`Esc` 关下钻；`↑↓`/`j k` 列表移动；`Enter` 打开。不用鼠标能走完"全景 → 未闭合 → 明细"。
- **可访问性最低线**：正文对比度 ≥ 4.5:1；焦点必须可见（不许 `outline: none`）；状态不靠颜色单独表达（灯 + 文字）；图标按钮配文字。
- **恒定性**：顶栏题字与 asOf 行不随滚动消失；跨视图数字不一致时以各自 asOf 为准，**不许统一成一个时间掩盖刷新不同步**。

## 八、验收标准（六条 + 两条地基，每条都能红）

| 编号 | 判据 | 怎么证伪它 |
|---|---|---|
| A-1 | 界面无假数据 | 停掉读口 → 必须显示"读口未起"；出现任何数字/骨架数字/示例值即红 |
| A-2 | 数字对账 | 指向只含部分表的副本库 → 缺的表必须显示"缺"；显示 0 即红（0 与缺不同） |
| A-3 | 动作流不卡 | 首屏 < 1s、滚到末页 ≥ 50fps；关掉虚拟滚动必须变红，否则判据没测到真东西 |
| A-4 | 搜索有判别力 | 搜不存在的词必须 0 条；搜真实编码必须 1 条且正文与 `fish recall` 一致。任一边不成立即红 |
| A-5 | 语料三态分明 | 空语料库 → "库为空"；有段无命中 → "0 命中"；两句必须不同，相同即红 |
| A-6 | 注入预览与后端一致 | 调后端自己的 `inject` 函数比对；前端自建模板渲染出"看起来一样"不算通过 |
| A-7 | 读口仍然只读 | POST/PUT → 必须 404/405；`assert_write_rejected` 仍在每次开连接路径上。任一失效即红 |
| A-8 | 六块都在 | 读口只返回旧 scene（无新端点）→ 缺的块必须显示"该视图数据未接"，不许整屏崩、不许空着不解释 |

A-7、A-8 是地基：一个保"这版没有写能力"，一个保"后端没补齐时界面说的是实话"。**任一条判据靠"看起来对"过关，这版就不算交付。**

## 九、待确认的问题（6 条，都阻塞设计）

**9.1 顶栏按六格还是按 K10？** 推荐按 11-23 口述六格，"活动"降为看板下钻。理由：更近、更具体，"推送与注入"是 K10 漏掉的真需求（U-18 有原话）。代价不大：日后要让动作流独立，加一格是几行代码。

**9.2 一期只读与 U-09"UI 手动闭合"冲突怎么办？** 推荐一期只显示未闭合、附可复制 CLI 命令，闭合进二期（R-21）。理由：写入需要权限与撤销语义，一期都没有；而"看见"已能兑现 U-07。风险：他可能觉得"看着不能点"难受，所以命令必须一键复制。

**9.3 知识库做到什么深度？** 推荐 vault 清单 + 根两层目录，不做搜索、索引、图谱。理由：U-24 的搜索边界到 10-27 仍未拍板，边界定前做搜索很可能要推翻；目录两层不依赖那个决策。

**9.4 语料原文给到什么程度？** 推荐列表统一下发后端已脱敏片段（`fish_corpus` 自带 `_strip_private` 与 `redacted_count`），点开读全文显示脱敏计数；**不提供"看未脱敏原文"**。理由：读口无鉴权且 `ACAO:*` 未修（2.3）。

**9.5 读口由谁起？** 推荐由壳起后端子进程（只读），起不来时界面照 6.1① 显示原因与命令。理由：它决定空状态文案——手动起时说明从哪条命令开始，自动起则"读口未起"应是异常。这偏架构，但决定产品文案，必须现在定。

**9.6 单人看板显示吗？** 推荐显示，按"多方/单人"分组。理由：`collect_boards()` 今天把成员 < 2 的板整块丢掉，而 89 §1.1 与 UI需求全景 都记着"20 块看板"（88 §6.1 另记 44）；界面只给几块，他会认为"数据丢了"。分组既诚实，又不让单人板污染协作画面。
