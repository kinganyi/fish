### 5.1 🟡 「窗口无行为」时左栏误报「这个库还是空的」

- **影响**：只发生在"某窗口 0 行、库里有旧数据"的场景（例如停了一整天后打开 24h 视图）。文案分类错，不是数据错；与 doc 96 §九「0/空/缺/判不到四者文案必须不同」的口径相悖。
- **建议修法**：Rail 复用 Stream 的 `dbEmpty` 判据（加 `stats?.tools.cumulative === 0`），或在"窗口空"时改用 `codes.windowEmpty` 的短句。证据截图：`%TEMP%\fish-qa-r2\shots\r2-window-empty.png`。

### 5.2 🟡 折叠组 >100 条且落在页边界时，翻页覆盖数重复计数（latent）

- **构造**（只在副本库）：39 条不同 code 的独立推送 + 105 条同 code、60 s 间隔的连续推送（用未来时间戳保证严格连续且排在最前），`limit=40` → 大组正好是本页第 40 条（页边界）。
- **结果**：`counts.total=3,765`、翻到底 `rawSum=3,770` → **重复计数 +5**；同一构造下大组在页首时 `rawSum≈total`（不触发）。大组本身 `count=105 / innerLen=100 / truncated=true`。
- **根因**：`fold_items` 把明细截到 `FOLD_ITEMS_MAX=100`（`fish_workbench_api.py:117,948`），而翻页游标用 `last_raw_sk(fold) = fold.items[-1].sk`（`:987-992`）——截断时它是"第 100 条明细"，不是"组内最旧原始行"；下一页把剩下的 5 行再折一次、再计一次。
- **为什么当前不表现**：24h 实测最大组 **15 条**，远低于 100；只有单 code 连推 >100 条且恰好压在页边界才会中。
- **建议修法**：折叠时把 `run[-1]["sk"]` 存进 `meta`（或让 `fold` 带 `oldestSk`），游标取它；或把 `fold.count` 改成 `len(group_items)` 并另存 `covered`。回归判据：造 105 条连推 + 39 条单条，`rawSum == counts.total`。
- **判定**：🟡 P2（潜在、当前数据不触发），进 Known Issues，不阻塞交付。

### 5.3 ⚪ 页签二「时间」行重复小时分钟

`05-ledger-deeplink-2259.png` 里显示 `10-25 19:19 19:19:59`。`TabLedger.tsx:117-119` 同时渲染 `stampOf(ts)`（`MM-DD HH:mm`）与 `clockOf(ts)`（`HH:mm:ss`），`format.ts:18-32` 两者都含 `HH:mm` → 视觉重复。属观感冗余，不影响数据，⚪。

### 5.4 ⚪ 文档与实测的两处小漂移
