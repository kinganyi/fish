# 109 · 设置页「推送」面板：设计与验收（2026-11-24）

> 一句话：设置页拆成二级导航（**Agent 接入 / 推送**），推送页把「有没有用、为什么没用、
> 想调哪里」三件事分开摆；**唯一的写口**是 `POST /api/push/config` 与 `POST /api/push/preset`
> （白名单 + 类型/范围 + 审计），`push.enabled` 仍然不可写。
>
> 工作树：`I:\app\fish-pushui`，分支 `fish4-3/push-ui`，基线 HEAD `f603009`。

## 一、结构（为什么是二级导航）

| 层 | 内容 | 判据 |
|---|---|---|
| 顶级（52px 窄条） | 现场 / 设置 | 一级导航只有「看哪一屏」，不动 |
| 设置内部（200px 二级导航） | Agent 接入 / 推送 | `?page=settings&sub=push` 深链，刷新后仍在推送页 |
| 推送页内容 | 工具栏 → 诊断提要 → 通道 → Top offenders → 调整 → 最近推送 → 口径 | 六块 + 刷新都在 DOM 里有稳定钩子 |

为什么拆：宿主接入的时间尺度是**天到月**（装没装、接的哪条通道），推送的时间尺度是
**分钟到周**（有没有用、调哪个键）。挤在一屏里，用户永远在找「刚才那个开关去哪了」。
拆开之后两页各自带自己的「读取时刻」——**两个 asOf 不能混成一个横幅**，它们本来就是两次请求。

前端文件：

```

ui/src/views/settings/Settings.tsx    设置壳：52px 由 Workbench 给，内部 200px + 内容
ui/src/views/settings/AgentAccess.tsx 宿主 master-detail（从旧 Settings 原样迁过来，左栏 260→220）
ui/src/views/settings/Push.tsx        推送页（本文件的主角）

```

## 二、读口（GET，永远只读）

| 端点 | 返回 | 口径 |
|---|---|---|
| `GET /api/push/overview?days=7\|30` | `window / totals / channels / kinds / diagnostics / topCodes / config / asOf` | `totals` **整段复用** `fish.push_stats(conn, days, now)`；其余聚合用 SQL |
| `GET /api/push/events?limit&channel&reaction` | `items[]`（按 id 倒序） | 不设时间窗；`reaction` 不传=不过滤，**`pending`=只要待判**（`reaction IS NULL` 的行）。**空串不是契约**：`parse_qs` 默认丢空值、前端 `buildUrl` 也跳空串，那条「空串=待判」的路在 HTTP 上根本到不了（评审 🟠-2，§十） |

`diagnostics` 的四块回答「为什么没用」：

- `receiver`：`session_context` 里没有项目归属的会话比例 + `tool_activity` 同窗口的空项目比例
  + `workspace_map` 行数（收件人不知道推给谁，谈采纳率没意义）。
- `openLoop`：推送编码的标题命中 `fish_common.ATTENTION_OPEN_KEYWORDS`
  （未闭合/待办/下一步/todo/待确认/待定/待验证/待补）的次数与编码数。
- `artifact`：`mem_type='artifact'` 的推送/采纳（产物占大头说明推的是文件不是结论）。
- `duplicates`：同 `session_key + code + UTC 日期` 出现 ≥2 次的组数，以及最大那组的明细。

kinds 的归类顺序写死在一处（`classify_kind`）：`mem_type` 优先 → 前缀兜底
（`board/kb/activity/git`）→ 其余归 `memory`。**实测本库 `code_index.mem_type` 里没有
`memory` 这个值**，所以「认不出类型」的行就是普通记忆推送；`conv:` 这类前缀按契约也落进
`memory`（本库 18 条），这是有意的口径，不是漏判。

性能：30 天 6 200 行，`push_stats` 实测 0.24 s + 聚合合计 < 0.5 s；按 `(库, days)` 缓存
15 s，**写成功后整片失效**（否则面板会拿着旧 config 说「还是 10」）。

## 三、写口（POST，唯一两个）

```
POST /api/push/config   body {"key":"push.open_budget_tokens","value":600}
POST /api/push/preset   body {"preset":"pause"|"resume"}
```

- 白名单 7 键（范围写死，类型取 `fish_common.CONFIG_DEFAULTS` 的**登记**，不另写一份）：

  | 键 | 类型 | 范围 | 默认 |
  |---|---|---|---|
  | `push.after_tool_every_n_calls` | int | 1..9999 | 10 |
  | `push.prompt_enabled` | bool | — | true |
  | `push.prompt_max_items` | int | 1..5 | 2 |
  | `push.prompt_min_interval_sec` | int | 0..3600 | 90 |
  | `push.open_budget_tokens` | int | 0..2000 | 450 |
  | `push.score_floor` | float | 0..1 | 0.0 |
  | `push.value_floor` | float | 0..1 | 0.0 |

- **不可写**：`push.enabled`（在 DSH 上设 false 会连 `tool_activity` 采集一起停，
  `fish_push_hook.py:138` —— 那是「把仪表盘关掉」不是「调安静」）、
  `push.factors/rrf/mmr/rerank/corpus_enabled`（改它们要重新校准，不在本页做）。
- 预设：`pause` = 9999 / 关 prompt / 预算 0；`resume` = 10 / 开 / 450。
- 错误映射：未知/不可写键 → `400 bad_key`；类型/范围不合法 → `400 bad_value`；
  非 JSON object → `400 bad_json`；body > 64 KB → `413`；库写失败 → `500 internal_error`。
- 写路径**另开连接**（`sqlite3.connect(timeout=15)` + `busy_timeout=15000`），读路径永远
  `fish_ui.open_readonly`（`mode=ro` + `query_only=1`）。`open_conn` / `prove_read_only` /
  `assert_write_rejected` 的既有行为一个字节都没改。
- `GET /api/push/config|preset` → **405**（提示「写配置要用 POST」），不是 404：
  404 会让人以为端点不存在，于是去猜另一个路径名。

### 审计

`<数据目录>/_audit/push-config.jsonl`，**逐键一行**：

```json
{"ts":"2026-11-24T06:27:35Z","actor":"workbench","key":"push.after_tool_every_n_calls","old":10,"new":20}
{"ts":"2026-11-24T06:27:36Z","actor":"workbench","key":"push.prompt_enabled","old":true,"new":false,"preset":"pause"}
```

任务书写「预设审计 2 行」，实际按**逐键一行**记（pause/resume 各 3 行 = 6 行）：
行结构是 `{ts, actor, key, old, new, preset?}`，一行记多个键就写不下 `key/old/new`。
值没变的键不写（也不记审计）——「没改」不该在审计里留下一条看起来改过的行。
**单键写口同一口径**：`write_config` 在 `old == new` 时直接返回
`{"key","old","new","source","auditAt":null,"changed":false}`——不调 `set_config`、
不追加审计、`config` 那一行既不插入也不刷新 `updated_at`；`changed` 只在两个分支都给，
调用方不必靠 `auditAt` 反推「到底写没写」。
审计写失败**不阻断主写**（配置已经生效，回滚更糟），但会 `warn_derived` 出一行
`⚠ 派生写入失败`，且写回执的 `auditAt` 为 `null`，界面上会说明「审计写失败，看服务端日志」。

## 四、界面纪律

1. **四张指标卡各自带分母**，不做跨卡换算；采纳率算不出时显示「判不到」而不是 0。
2. 通道行是纯 CSS 条（无图表库），条宽 = 本通道量 / 最大通道量。
3. 调整区每项显示「现场值 / 默认 / 来源（库里有行 / 吃默认）→ 范围 → 上次写」；
   保存前 `window.confirm` 二次确认；成功后**重新 GET overview**（不拿本地值假装生效）。
4. `push.enabled` 只读 + 红色警告；**不提供一键关**。
5. 1280×720 不横向溢出（唯一判据 `scrollWidth == clientWidth`），1440×900 同测。
6. 沿用现有 tokens（`bg-n0..n7` / `text-sub|meta|section` / `border-n3` / `font-mono`），
   不新增依赖。

### 变异靶子的选择（为什么不用「完全未知的键」）

任务书写「临时删掉白名单检查 → **未知键**必须被接受」。实测：完全未知的键（如
`not.a.real.key`）在变异后仍然过不去——因为 `fish_common._key_type` 对未注册键抛
`KeyError`，`set_config` 根本不接受它；**「白名单」与「注册表」是两道理**。所以变异靶子用
`push.serendipity_ratio`：它在 `CONFIG_DEFAULTS` 里注册（float，默认 0.10），只是不在
本页白名单里。变异前 400、变异后 200 且库里读到 0.2 —— 这才证明**白名单那一行真的在挡**。
同一个脚本里另有 `not.a.real.key` 的 400 断言（V-08 前半），两件不同的事分别有判据。

## 六、已知边界（如实写）

1. **口径只到「推送行」这一层**：`receiver` 用 `session_context.project` 判「收件人项目未知」，
   而这个库 30 天内 53 个会话**全部**没有项目归属（`unknownRate = 100%`）。这不是面板的错，
   是采集侧没有把 cwd 映射成项目；面板把这件事**显示出来**（而不是把采纳率算得很漂亮）。
2. `kinds` 的 `conv:` 前缀按契约归 `memory`（见 §二），本库 18 条。
3. `duplicates` 的「天」是 UTC 日期（与库里时间戳存法一致），不按查看者时区重算。
4. 面板不读语料库（`corpus.sqlite` 是另一份文件），也不改 `push.enabled`。
5. 推送页没有自动轮询：它是「看一眼、调一下」的面，不是实时面板；每次进来读一次 +
   手动刷新 + 写入后自动重读。
6. 预设审计是**逐键**（3 行/次），与任务书「2 行」的字面不符，原因见 §三「审计」。
7. **「值没变」的回执文案**：~~还没跟上~~ → **已修（2026-11-24 15:23–15:35，读数见 §九）**。
   原来的毛病是：`POST /api/push/config` 在 `changed=false` 时 `auditAt=null`，而
   `api_push_write_config` 把 `sources[push-config-audit].ok` 判成 `auditAt is not None`
   （于是 `false`）、前端 `saveKey` 也打印「审计写失败，看服务端日志」——事实是**什么都没写，
   也就不需要审计**。现在判据换成 `changed`（预设用 `changedCount > 0`）：没变 → `ok=true`
   + `rows=0` + `detail="值未变化，未写库、未写审计"`；真写了没落审计 → 仍 `ok=false`；
   前端三态分开提示。`data.changed` / `data.auditAt` 的语义**没动**（V-24 照旧判）。
   代价还是那条：动前端就得重建 dist，于是 01–07 会一起变「比 dist 旧」，所以本轮
   **连截图一起重拍**（01–06 + 07 补拍 + 08 由 V-16/17/18 写，旧图挪进
   `screenshots/_legacy-predist/`，一张没删）。
