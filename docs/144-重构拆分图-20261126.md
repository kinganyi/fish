### 1.3 决定方案形态的四条硬约束（取自实测）

1. **外部引用面 366 个不同 `fish.<name>` / 166 个文件**（`mcp_server` 独占 83 个，其余散落）。→ re-export 必须**全量、对象同一**，少一名就在运行时静默消失。
2. **依赖分层锁死拆序**：identity、memory 外依赖为 0（只依赖叶子 `fish_db/fish_trust/fish_schema/fish_common`）；inject+activity 只依赖 identity；layout、cmd 依赖其上全部。**一个域只能在它的下游都已下沉后才能成模块**（否则新模块被迫 `import fish`，触 J2）。
3. **`fish_cli.py` 用 `install(globals())` 把 fish.py 的 globals 装成 `_f` 派发 `cmd_*`**。本次 **cmd_* 一律不搬**，故 `fish_cli` 一行不改。
4. **常量随域迁移**：每个域函数引用的模块级常量必须同行；唯一**跨域共享常量 `LIKE_ESCAPE_SQL`**（memory 与剩余 cmd 都用）→ 归 `fish_memory` 并让 fish.py 从它 import，**不要塞 fish_common（只剩 1 行）**。J5 陷阱：`cli_entry_hint` 用 `Path(__file__)` 兜底，搬走即违 J5，因此不搬（见 §4）。

## 3 推荐顺序

**先刀一（identity）→ 刀二（memory）可与刀一并行（互不依赖、文件面不重叠）→ 刀三（inject，硬依赖刀一）。** 理由：identity 被最多上层依赖且零外依赖，先落地它可解锁刀三以及后续 push-log/layout/cmd 的拆解；memory 独立可并行缩短墙钟；inject 放最后正因它唯一外依赖就是 identity。

**每刀验证三步（缺一不算完成）**：
1. 定向：`pytest test_split_contract.py -q` —— J1/J2/J3/J4/J5 全绿。
2. 全量：`pytest -q` —— 0 fail；用「修饰前后条数对账」，**不锁死固定通过数**（在途数字会过期）。
3. **变异自证**：把某导出对象改成 wrapper（`def f(*a):return real(*a)`）→ J1 同对象判据必须红；把 fish.py +300 行 → J4 必须红；给新模块加 `import fish` → J2 必须红；还原后全绿。

## 4 不建议做的事

- **不搬 `cli_entry_hint`**：用 `Path(__file__)` 兜底，搬进新模块即触 J5；且它是入口表现层，留下。
- **本次不搬 cmd_* 与 layout**：cmd 是装配层；layout 依赖面最广（identity+memory+activity+migrate 全要），现在搬会把「3 刀」拖成 5 刀、并让 `fish_cli` 的 `install(globals())` 派发链暴露风险。留作刀四/五。
- **不往 `fish_common`（969/970，仅 1 行）和 `fish_push`（1550/1550 顶格）塞任何东西**。
- **不为拆而拆**：`migrate`(281)、`push-log`(138) 体积小、被 cmd 广泛内联，留 fish.py；单个私有 helper 不单独建模块。
- **本次不给 `fish_kb`/`fish_workbench_api`/`mcp_server` 补窗口**：是真实缺口，但属独立工单，塞进来会模糊本图范围。

## 5 每刀「完成」定义（验收判据）

一刀完成 = ① fish.py split 行数落入新窗口、新模块落入其窗口；② `pytest test_split_contract.py` 全绿且 `pytest -q` 0 fail；③ 迁出名字 `getattr(fish,n) is getattr(新模块,n)` **全部成立**（对象同一，非副本）；④ 全仓 366 个外部 `fish.<name>` 运行期 `hasattr(fish,name)` 全真；⑤ 新模块顶层无 `import fish`（J2 静态+干净子进程双查）、`symtable` 无未定义全局（J3）、无 `__file__/__name__`（J5）；⑥ ratchet 新增一条 history、链头/长度/锚值同步。刀二/刀三同构，仅换模块名。
