## 3 关键设计决策

1. **为什么是新模块 `fish_kb_index.py`（偏离任务书"fish_kb.py 独占"）**：
   `fish_kb.__all__` 是动态生成（`__all__ = sorted(n for n in globals() …)`），而 `test_split_contract` J1b 要求它与 `fish.py` 的 `from fish_kb import (...)` **逐字相等**；C 不许改 `fish.py`。往 `fish_kb.py` 加任何模块级名字都会让 J1b 红。故索引层独立成模块；A 合并时接线（见 §6）。**`fish_kb.py` 一行未改**。
2. **敏感文件不入索引**：`kb_is_sensitive_name` 命中即跳过（真实库跳过 1 篇：凭证类）。索引是"离线缓存"，不能成为敏感正文的第二份落点。
3. **FTS 切法单一来源**：索引侧 `fts_text()`、查询侧 `fts_match_expr()`，与 `memory_fts` 同一套 bigram 切词（J2 家族）。
4. **只读 vault 安全**：只读 `_kb_walk` 产出的 `abs`，路径来自 vault 根内；不写 vault。
5. **删除语义**：盘删 → `status='deleted'`（行保留、FTS 删）；vault 离线 → 整库跳过，**绝不**把全库标 deleted。
6. **A 接线契约**：`search_kb` 返回 `hits[{vault_id,vault_name,rel,title,snippet,score,matched_field,...}]`；`exclude` 用 `kb:<vault name>:<rel>`（与 `_kb_push_candidates` 现有 code 形态一致）；`kb_index_fresh(max_age_hours=168)` 供断路器。

## 4 已知限制 / 未闭合

1. **A 未接线**：`_kb_push_candidates` 仍走旧 `_kb_search_multi` 扫描；`FISH_KB_USE_INDEX` 开关与 7 天陈旧断路器需 A 在合并时落地（本模块已提供 `search_kb` + `kb_index_fresh`）。
2. `search_kb` 的 `project` 参数保留未用（KB 无项目字段；设计预留）。
3. 归一化后会出现 `score=0.0` 的尾部命中（min-max；调用方需自行按阈值过滤；推送侧应设门槛）。
4. 超 `max_open_bytes` 的文件按 `error='too_large'` 跳过（不索引）；真实库无此情况。
5. `kb_index` 不自动清理"已删除"旧行（保留可审计）；如需压缩由维护任务后续处理。

## 5 回滚

- 功能回滚：不调用 `fish_kb_index` 即回到旧路径；A 接线后用 `FISH_KB_USE_INDEX=0` 回旧 walk。
- 数据回滚：`DROP TABLE kb_fts; DROP TABLE kb_index;`（纯派生，可由 vault 重建）。
- 代码回滚：`git revert 5da8508`（3 个新文件，无既有文件冲突）。
