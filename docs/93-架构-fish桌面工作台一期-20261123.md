
**两种实现共存**：`SqliteProvider`（两个 `mode=ro` 库 + `domain`）、`FakeProvider`（内存字典，随生产代码交付）。共存判据不是"能跑"，是**同一套契约测试参数化到两个实现**：`pytest -k provider_contract` 各跑一遍全绿。

**`domain.py` 的纪律**：只准 `from fish import <这 4 个名字>`，函数体零逻辑，只有参数转发与异常归一。判据：反射 `domain` 模块，断言从 `fish` 导入的符号集合**恰好等于 4 个**，多一个就红。

**collectors 能做什么、不能做什么（🟠-1 的正面裁决）**：

- **可以**：`SELECT` 投影、`WHERE` 等值/集合过滤（复用 provider 已经算好的行字段）、`COUNT(*)` 只在"与检索同一条 WHERE 且该 WHERE 由 collector 自己拥有"时允许（一期没有这种）。
- **不可以**：`MATCH`（必须走 `search_memories`）；用 `ORDER BY` 决定检索排序口径；把"是否闭合/是否撞车/是否 dormant/是否 superseded"重算一遍（K8 的"第二份领域实现"）。
- **因此这三件事被明确删掉**（不是"以后再说"）：
  1. `/api/memory/search` **不接受** `status`、`memType` 入参——`search_memories`(`fish.py:2355-2357`) 没有这两个参数，加上就得改白名单或重写过滤。
  2. `/api/memory/search` **不发** `totalMatched`——该函数返回 `(rows, src_of)`（`:2466`），全库总数只能靠再写一条 COUNT（`_list_where` 在 `fish.py:2558` 是私有函数，引用它等于第 5 个 import → 撞白名单判据）。改发 `meta{returned, truncated, limit}`：`truncated = len(rows) == limit`。
  3. `/api/memory` **不发 `cursor`**——`list_memories`(`:2607-2609`) 返回行里没有 `recorded_at`，`(recorded_at, code)` 键集分页**物不出来**；一期只支持 `limit ≤ 200` + `truncated`。`declared` 改为 `filtersEcho`（collector 回显它自己传下去的 `project/tags/since/until/limit`），**不调** `format_list_declaration`(`fish.py:2644`)——它要 `total`，而我们拿不到 total 就宁可不说，也不说半真。

**判据（可失败）**：`FakeProvider` 能让 `/api/scene` 与全部新端点族产出 200；变异：`SqliteProvider` 全方法 `raise NotImplementedError`、只挂 `FakeProvider` → 全部端点仍须绿。**外加一条活判据**：`p0/test_fish_ui_memory.py` 断言 `collectors/memory.py` 里**零 SQL**（不出现 `FROM code_index` / `MATCH`）。

**代价（v2 重测）**：`import fish` 进程内 **231.2 ms (213.8–262.4, n=5)**、进程墙钟 **331.9 ms (311.0–373.2, n=5)**（基线 `python -c pass` 85.8 ms）。`fish.py:10593-10596` 模块级执行 `_fish_cli.install(globals())`，所以 `import fish` 顺带装配整份 CLI。对策：**服务启动时预热一次**，之后 `sys.modules` 命中，per-request 为 0。

> v1 这里写的 824.4 ms 是**冷缓存单次样本**，已作废。评审复测的 341 ms 与本次进程墙钟 331.9 ms 同一口径，两个数都对——错在 v1 没写口径与样本量。

### 3.5 多库

- **每请求一连接**：`sqlite3` 连接不能跨线程安全共享，`ThreadingHTTPServer` 每请求一线程。
- **每连接真试一次写**（A-7）：只读连接上 `CREATE TABLE` 立即抛错，代价可忽略。语料侧 `_connect_read`(`fish_corpus.py:773-786`) 已是 `mode=ro`（注释写明"读动作不改库"）。
- **连接上限 8**：`BoundedSemaphore(8)`，拿不到立刻 `503 BUSY`（不排队——排队会让"卡住"看起来像"死了"）。
- **WAL 两条真实约束**：只读连接不能 checkpoint（`-wal` 由采集侧收缩）；只读打开 WAL 库需 `-shm` 可读（当前可读）。若把 data 目录 ACL 收成只读，ro 打开会失败 → §7-R8。
- **语料库不存在是正常态**：`store.db_path(root).exists()` 为假时**绝不建库**，回 `missing` + `action: "fish corpus ingest --host dsh"`。

### 3.6 schema 演进（三条 + 受控变更表）

1. **加字段不改版本**（消费方必须忽略未知字段）——但 **`/api/scene` 例外：一个字段都不加**（见下）。
2. **加端点不改版本**，靠 `capabilities` 发现（A-8 的机械落点）。
3. **改字段语义/删字段/改空态含义 → 升 major**；`fish-ui/1` 冻结。
4. **受控变更表（🔴-2 的解法；v4-2 / v4-8 补全）**：`/api/scene` 的**字段名与形状永久冻结**，但**值**可以在"显式受控变更表"里被修正——一期只有 1 条（G8）。表是 `p0/tools/scene_diff.py` 的 `SANCTIONED` 常量（源码见 §5-T02-2b），每项含五个字段：

   ```python
   {"missing.dialogue": {"key": "missing.dialogue", "from": "<fish_ui.py:461 的旧写死串，逐字符相等>",
                         "to": None, "task": "T04", "reason": "G8"}}
   ```

   **三条硬规则**：① 只有表内 key **豁免类型检查**，且只在 `after ∈ {from, to}` 时成立（`string → null` 是受控的类型变更，不是漏判）；② `to` 只认一个值，**不是白名单**——第三种值 → `SANCTION_THIRD` 红；③ 表上限 1 条，`len(SANCTIONED) > 1` → `SANCTION_TABLE` 红。

   **为什么不撞 §3.6-3 的"改空态含义 → 升 major"**：`missing.dialogue` 的契约类型从第一天起就是 `string|null`，基线只是**从未真的产出 `null`**；T04 让这个声明第一次落地，不是改语义。要改语义或加第二个受控项 → 必须升 major，**不许扩表**。

**为什么选"值级修正"而不是"把探测塞进 `/api/meta` 让 scene 完全冻结"**：后者要求 PRD 的 G8 改口径（`missing` 标 deprecated 但值仍是错的），而 §3.1-5 列的缺陷里 `missing.dialogue` 的**错的是值不是形状**。选"值级修正"能同时满足 G8 原文与 A-8 冻结；代价是必须维护那张 1 行的受控变更表——这是明账，不是白名单。

**`/api/scene` 为什么不升 2**：A-7/A-8 是地基。让 scene 的字段与形状完全不变，"新前端指向旧读口"这个测试才是真的（旧读口只回 `fish-ui/1`、且没有 `/api/meta`）。前端遇 `/api/meta` 404 → 进"只读旧契约"模式 → 全景之外五格显示"该视图数据未接：缺 `<cap>`"。**这就是 A-8 的机械化实现。**

### 3.7 CORS / 鉴权（D4）

1. **只绑回环**：`--host` 默认 `127.0.0.1`，`0.0.0.0` 直接报错退出（不静默）。
2. **Origin 白名单**：只放 `http://127.0.0.1:<port>` / `http://localhost:<port>`（端口来自 `--allow-origin`，可多条）。`Origin: null` 一律拒。
3. **无 Origin 请求**：放行但只允许 `GET/HEAD/OPTIONS`。
4. **`Sec-Fetch-Site: cross-site` 一律 403**——浏览器给的、页面伪造不了。DSH 自己对本机 HTTP 面用的就是这套（88 §1.3 引 `api-request-trust.ts:91-118`，含 `Host` 回环校验与 `Origin: null` 拒绝）。
5. **不做 token**（唯一用户；2+3+4 已堵住"本机任意网页读走投影"）。**撤销条件**：出现"给别人用"或"上云"，立刻换一次性 token + 短 TTL。

**🟠-6 的落点**：读口兼发静态（`--dist ui/dist`）后，页面与 API **同源**，2+3+4 自然成立、CORS 根本不需要。`--allow-origin` 只服务"dev server（Vite 5173 或 `python -m http.server 5180`）另起"这一种情形；**5180 与 `--allow-origin` 的关系**：不传 `--allow-origin http://127.0.0.1:5180` 时，从 5180 页面发出的请求会被 403（这是设计，不是 bug），报错文案里直接给这条参数。

**判据**：
- `curl.exe -i -H "Origin: https://evil.example" http://127.0.0.1:8787/api/scene` → **403**，且响应**不含** `Access-Control-Allow-Origin`。
- `curl.exe -i -H "Origin: http://127.0.0.1:5180" http://127.0.0.1:8787/api/scene`（带 `--allow-origin`）→ 200 且 `ACAO` 回显具体来源。
- `curl.exe -i -H "Sec-Fetch-Site: cross-site" -H "Origin: http://127.0.0.1:8787" …` → 403。

### 3.9 只读纪律：四条硬边界 + 一条判据纪律（🔴-1 的落点）

**1. 零 DDL/DML。** 本设计不含任何 ALTER/INSERT/UPDATE/DELETE。索引建议一律写成"何时必须加"。

**2. `assert_write_rejected` 保留**在每次开连接路径上（A-7）。注意 `build_scene` 现状只开一连接、只探一次（`fish_ui.py:443-445`），不是两次（v1 错，Y1）。

**3. 语料 doctor：真只读路径已核实，但一期不做凭证扫描。** 逐条核实评审的三处行号：


实测 5 次：`ok=True` ×5，`access_log` 4→4、`access_doctor` 0→0、`segments` 108,158→108,158、WAL 22,029,672→22,029,672、mtime 不变（#11）。**但它是 18,854 ms (n=5)**。

**一期决策**：`/api/corpus/doctor` **不接受"现跑"**，只回**只读子集**（segments/sessions/tombstones/degraded/orphans/unmapped/accessLogRows/stall ≈7 ms）+ `coverage{scanned[], skipped:["plaintext_secrets","fts_gap"]}` + `okSubset`。**不做凭证扫描的理由**：18.9 s 的操作不该长在仪表盘上；PRD 的四项自检里"语料 doctor"要的是体检结论，而 `secret_hits` 是**离线安检**职责（由 `fish corpus doctor` CLI 在采集后跑）。**代价必须说出来**：`okSubset=True` 不等于"全库无明文凭证"——所以字段**不叫 `ok`**，界面上必须显示"凭证扫描未跑（怎么跑：`fish corpus doctor`）"。

**4. `read_body_path` 的自愈与只读冲突（Y9 修正）。** 在 `relocated` 态它会写**两次**：`UPDATE code_index SET file_path`（`fish.py:853`）+ `append_event(...)`（`:854-857`）。只读连接上必失败 → 端点显式捕获，把 `bodyState` 报成 `relocated_readonly`（文案：文件被移动过，已定位到新路径；自动修回需要写权限，一期只报不修）。**判据 D5**：读一次 relocated 条目前后，`code_index.file_path` 与 `events` 行数**必须不变**；变异：把 conn 换成写连接 → 两者必变 → 红。

**5. doctor 缓存的语义（⚪-1）。** `data/_ui/corpus-doctor.json`：

```json
{"schema":"fish-doctor-cache/1","generatedAt":"<UTC ISO>","root":"<绝对路径>",
 "dbBytes":0,"walBytes":0,"subset":{},"secretHitCount":null,"coverage":{"scanned":[],"skipped":["plaintext_secrets","fts_gap"]}}
```
- **过期**：`generatedAt` 超 24 h → 端点回 `stale:true` 但照发（过期数据比没有数据有用），界面标"上次体检 <时间>"。
- **损坏**：JSON 解析失败或 `schema` 不认 → 回 `availability.state="unavailable"` + 文件路径，**不是 500**。
- **并发刷新**：写临时文件 + `os.replace` 原子替换；单飞锁 `corpus-doctor.lock`（拿不到锁直接回"刷新中"，不排队）。
- **刷新动作**：`fish ui doctor --write`（唯一允许写文件的地方，写的是缓存不是库；它的**读数**必须走上面那条 `record=False` 路径）。

**6. 一条判据纪律（v2 新增，纠正评审判据的一半）。** "刷新后库文件 mtime / `-wal` 大小 / 相关表行数零变化"这三项里，**mtime 在 WAL 模式下会漏**：实测空库夹具写入 1 行并 commit，`corpus.sqlite` 的 `mtime_ns` **完全没变**（1795383901466287900 前后相同），因为落盘进 `-wal`。所以判据必须是：

- **D1（主）**：`SELECT COUNT(*) FROM corpus_access_log WHERE action='doctor'` 前后相等。**实测有判别力**：坏输入 0→1、好输入 0→0。
- **D2**：`corpus.sqlite-wal` 字节前后相等（实测 22,029,672→22,029,672）。
- **D4**：`SELECT COUNT(*) FROM corpus_segment` 前后相等（实测 108,158）。
- **mtime 只作辅助**，不进判据；谁把它写成判据，这条会在有人写入时绿着过去。

## §3.10 Electron 壳设计（v3 新增）

> **编号说明**：本节插在 §3 尾部而不重排后面各节，是为让既有交叉引用（§3.9-x / §5-T0x / §6-11 / §7-Rxx）全部保号。壳与读口同属"进程与运行时"层，放这里也讲得通。

### 3.10.1 进程模型与目录

```
ui/                              ← renderer 包（T06 写；一次 install、一个 lock）
├── package.json                  dependencies: react/vite/tailwind…；devDeps: vitest/jsdom/@testing-library
├── codes.json                    空态与离线文案唯一真相（renderer import；壳的 gen-offline 也从这里读）

└── dist/                         vite 产物 → 打包时 extraResources 落 resources/ui-dist（Python 要能读）

shell/                           ← 壳包（T08 写；**唯一装 Electron 的包**）
├── package.json                  main = "dist-electron/main.js"；devDeps: electron + electron-builder + typescript
├── .npmrc                        electron_mirror / electron_builder_binaries_mirror（§7-R14）

│   ├── reader.ts      ~140 行    python 解析 + spawn + 端口三判定 + 收养 + 停止/重启
│   ├── tray.ts         ~90 行    托盘图标与五项菜单（含纯函数 buildTrayMenu）
│   ├── assoc.ts        ~60 行    fish:// 与文件路径 → open-target 归一

│   └── tsconfig.json             ES2022 / CommonJS / outDir ../dist-electron
├── scripts/gen-offline.mjs ~20 行 ../ui/codes.json → offline.html（文案单一真相）
├── test/shell/                   纯 Node 单测（不启 Electron）

```

**为什么两包（v4-6）**：Electron 的 151.0 MiB 二进制只在 `shell/` 装——`ui/` 的构建与 vitest **完全不碰 Electron**；devDeps 按包切干净，两个任务按目录零重叠，不再抢同一个 `package.json`。**代价**：两次 install、两个 lock，`shell` 打包含前置 `npm --prefix ../ui run build`。

**依赖边界写死**：`ui/dependencies` = renderer 运行时 + **构建工具**（react、zustand、`@tanstack/react-virtual`、vite、`@vitejs/plugin-react`、tailwind 4、typescript）——它唯一的"生产动作"是 build，所以 `--omit=dev` 后必须仍能构建；`ui/devDependencies` = 测试工具（vitest/jsdom/@testing-library/@types）；`shell/devDependencies` = electron、electron-builder、typescript、@types/node，**不装** react/vite。

三条纪律：**main** 是唯一能碰 `fs`/`child_process`/`app` 的层；**preload** 必须 `contextIsolation:true` + `sandbox:true` + `nodeIntegration:false`，只暴露下表 **5** 通道（v4-5 加了 `restartReader`）；**renderer** 与浏览器里那份**逐字节相同**（不引 Electron 类型、不写"我在不在壳里"的分支），壳只经 HTTP 跟它说话。

| preload 暴露 | 语义 | 为什么在壳侧 |
|---|---|---|
| `getRuntime()` | `{port, apiBase, dbPath, pythonPath, errors[]}` | 渲染层不知道端口与库路径，**也不该知道** |
| `onOpenTarget(cb)` | 订阅"要打开哪条记忆" | 事件从 OS 来，只有 main 拿得到 |
| `openPath(p)` | 用系统默认程序打开本地文件 | 需要 `shell.openPath` |
| `quit()` | 退出应用 | — |
| `restartReader()` | 重启读口：`kill` 自家 pid → 重新三判定 → `spawn`（v4-5） | 离线页按钮与托盘共用；**只有 main 能 spawn** |

**"零领域逻辑"判据**：`dist-electron/preload.js` 里 `if`/`switch`/`for`/`.filter(`/`.map(` 出现次数**必须 0**，且不含领域名词（`code`/`memory`/`board`/`corpus`/`status`/`project`）。变异：加一句 `if (t.kind==='memory')` → 必红。

### 3.10.2 谁起 Python 读口（端口方案 = **固定 8787 + 三判定**）

**结论：固定 8787，不用 `--port 0`。** 主进程：

```ts
spawn(pythonPath, ['-X','utf8','fish_ui.py','--db',indexDb,'--host','127.0.0.1',
                   '--port','8787','--dist',distDir],    // dev 追加 --allow-origin http://127.0.0.1:5173
      { cwd: p0Dir, windowsHide: true, detached: false, stdio: ['ignore','pipe','pipe'] })
```

`cwd` 必须是 `p0/`：`fish_ui.py:60` 的 `DEFAULT_DB` 相对 `p0/` 拼，且 `import fish_common` 要 `p0` 在 `sys.path`（§5-T02-1 坑 3 实测）。

`distDir` 两条来源：打包态 `path.join(process.resourcesPath,'ui-dist')`、开发态 `../ui/dist`。**静态服务本身归 T01**（v4-4）：`reader.ts` 只负责把路径传进去，不实现文件服务。

**不用 `--port 0`**：① 现读口**打不对端口**——`fish_ui.py:594-595` 打的是入参 `args.port` 而非 `srv.server_address[1]`，`--port 0` 会打印 `…:0/`；要支持就得改读口 + 新增 stdout 契约，给"起没起来"多加一个可失败点。② **端口 0 让已存在的读口不可发现**——孤儿一旦存在，没有稳定地址能问到它。

**三判定（顺序写死，判据可红）**：

| # | 探测 | 判定 | 动作 |
|---|---|---|---|
| 1 | `connect 127.0.0.1:8787` 失败 | **空闲** | 正常 spawn |
| 2 | `/api/meta` 200 且 `schema` 以 `fish-ui/` 开头、`readOnly===true`、`db.index`==本次库、`GET /` 的 `Content-Type` 是 `text/html` | **自家读口** | **收养**：不 spawn，记 `meta.pid` 供「停止读口」用 |
| 3 | 其余（有响应但不是 fish 读口 / 库路径不同 / 没带 `--dist` 而 `/` 回 JSON） | **他人占用** | **不 spawn、不杀、不换端口**；离线页 + 占用 PID + `netstat -ano \| findstr :8787` |

后两个条件不是洁癖：没带 `--dist` 会让窗口**加载到 JSON 而不是界面**（`/` 无 `--dist` 回 scene JSON，§3.4）；库路径不同则显示**另一份数据**——比不启动更坏，因为它看起来是对的。

**失败三态**（对齐 6.1①）：① `error`（ENOENT）→ 离线页"找不到 Python"+ 用过的路径 + `where python`；② `exit != 0` → 贴 **stderr 尾部 20 行原文**（`fish_ui.py:583-585` 的"库不存在：<path>"就这么出来，不许改写）；③ 起来但 5 s 内 `/api/meta` 不通 → 按 ② 处理。**两个 pipe 必须持续消费**：不读满 64 KB 会卡死子进程——这是"读口活着但不响应"的真实成因。

**Python 路径**：首启取 `where python` **第一条非 Store 别名**的结果落 `%APPDATA%\<app>\config.json`，之后一律绝对路径（§0.1 #8、§7-R18）。

### 3.10.3 退出清理（Windows 子进程孤儿：**本机实测不是必然**）

**先纠任务书的前提**：Node v24.19.0 上，`detached:false` 的子进程在父进程**正常退出**与**被 TerminateProcess 强杀**下**都跟着死**（心跳 #4 停 1 行、#5 3→3→3）；改 `detached:true` + `unref()` 才活（#6 4→6）。**"孤儿"是 `detached:true` 的结果，不是 Windows 的必然**（机制属 **[未验证]**；行为已实测，有正对照 #10）。

**但判据不能建在未文档化的 OS 行为上**（换 Electron 内置 Node、换 Windows 都可能变）。三层，前两层才是方案：

1. **`detached:false`**（默认，别动）：白拿一层 OS 兜底。
2. **`before-quit` 显式收尾**：`child.kill()`（实测 kill→exit **4.31 ms**，#7）→ 等 ≤1,000 ms → 仍在则 `taskkill /PID <pid> /T /F`。**这才是"3 秒内消失"的确定性来源。**
3. **收养来的读口不是我 spawn 的**（判定 2）→ 不受 job 对象保护。规则：**退出时不动它**（可能是用户手动起的）；**退出清理只杀壳自己 spawn 的 PID**（`reader.pid` 记的那一个，`detached:false` 已实测父死子亡），**禁止 `taskkill /IM python.exe` 这类按映像名的清理**——本机另有 5 个无关 `python.exe`（§0.1 #9），按名字杀会误杀别人的进程。收养来的读口只能由托盘「停止读口」这个显式动作按 `meta.pid` 杀（v4-10）。

**验收判据（T08-3）**：

```powershell
# 前置①：8787 必须空闲——否则测的是"收养"，而收养按设计就不该被杀（这是 T08-3 与 §3.10.3-3 冲突的解法）
if (Test-NetConnection 127.0.0.1 -Port 8787 -InformationLevel Quiet) { 'FAIL 前置：8787 已被占用，先按三判定收口'; exit 1 }
# 前置②：壳把自己 spawn 的 pid 写到 %TEMP%\fisharch\reader.pid（main 启动时写）
$pid0 = (curl.exe -s http://127.0.0.1:8787/api/meta | python -X utf8 -c "import json,sys;print(json.load(sys.stdin)['pid'])")
$pidShell = [int](Get-Content "$env:TEMP\fisharch\reader.pid")
if ($pid0 -ne $pidShell) { "FAIL 前置：meta.pid=$pid0 ≠ 壳 spawn 的 $pidShell（收养态不该进本判据）"; exit 1 }
Start-Sleep -Seconds 3   # 走托盘菜单「退出」之后
if (Get-Process -Id $pid0 -ErrorAction SilentlyContinue) { 'FAIL 3秒后仍活着' } else { 'PASS' }
```

**变异自证要成对**：`detached:true + 无 kill` → **必红**（已实测半段 4→6）；`detached:false + 有 kill` → 必绿；中间那格（`false + 无 kill`，本机大概仍绿，是 OS 兜的底）**只记录不判定**——否则一次绿可能只是 OS 兜底，判据没测到 before-quit。

### 3.10.4 单实例（第二实例只做一件事：把参数转给第一实例）

```ts
if (!app.requestSingleInstanceLock()) { app.quit(); return; }
app.on('second-instance', (_e, argv) => {
```

### 3.10.5 托盘与窗口语义（**关窗 = 隐藏**）

- 图标 `tray.png` 16×16 与 32×32（按 DPI 取），另留单色版。
- 菜单五项：`打开主窗` / **启停一格**（`running` → "停止读口"，`idle` → "启动读口"，`occupied`（他人占用）→ 灰显）/ `重启读口`（v4-5：`kill` 自家 pid + 三判定 + `spawn`；离线页同按钮）/ `开机自启`☑（§3.10.6）/ `退出`。左键单击托盘 = 显示/隐藏切换。

### 3.10.6 开机自启（选**托盘菜单勾选项**，不在安装时写注册表）

两条路取舍：安装时写 Run 键"能开不能关"（一期无设置页）；`setLoginItemSettings` 读写的是同一个键，能开就能关，交给托盘那一格正好。

- 首启写一次 `app.setLoginItemSettings({ openAtLogin:true, args:['--hidden'] })`——**默认开**：需求要"开机自启"，默认关等于没实现。
- 托盘那一格是唯一开关，**不新增设置页**（PRD `:54` 的 U-06 反对堆开关）；`--hidden` → 开机只进托盘不弹窗。
- **只在打包态生效**：`app.isPackaged` 为假时跳过（否则开发态会把 `electron.exe` 写进自启）。
- **验证**：`Get-ItemProperty 'HKCU:\Software\Microsoft\Windows\CurrentVersion\Run' | Select-Object -ExpandProperty 'fish-workbench'` → 指向安装后的 exe + `--hidden`；托盘取消勾选后再查 → 该项消失。**[未验证本机]**（要 T08 打出安装包，见 §7-R14）。

### 3.10.7 文件关联（关联什么、双击后怎么定位到那条记忆）

**建议：不动 `.md`，改用两样东西。** 本机 `.md` 大概率已归 Obsidian/记事本，抢它会让别的工具静默坏掉；而"双击打开某条记忆"**根本不需要文件**，需要一个可寻址的名字。

| 关联物 | 形态 | 双击后发生什么 | 落点 |
|---|---|---|---|
| **自定义协议**（主） | `fish://memory/ANYI-261022-10` | main 解析 argv → 校验形状 → 渲染层路由 `/memory/<code>` | builder `protocols` |
| **自定义扩展名**（次） | `.fish`（一行编码或 JSON 指针） | 同上，走文件路径分支 | `fileAssociations` |
| `.md`（**不做全关联**） | — | 界面按钮用 `shell.openPath` 交给系统默认程序 | 不写注册表 |

**校验**：只认 `^fish://memory/[A-Za-z0-9_-]{2,64}$` 与 `.fish`，其余参数**丢弃并记一行日志**（不弹窗——开机自启时 argv 里可能是别的东西）。编码存在性**不由壳判定**（K8），壳只做形状校验与转发；不存在时由 `/api/memory/{code}` 的 404 走 PRD 6.3 三段式，**壳不改写文案**。

**三种话，不许合并**：① 形状不合法 → 状态栏"忽略一个无法识别的打开参数：<原文>"；② 形状合法但读口没起 → 离线页（同 6.1①）；③ 读口在、编码不存在 → 视图内 404 三段式 + 可复制 `fish recall <code>`。

### 3.10.8 打包（`electron-builder`，per-user nsis）

### 3.10.9 前端产物怎么被加载（**这里偏离了任务书 item 9，理由可判**）

任务书要"生产用 `loadFile(ui/dist/index.html)`"。**本文改生产 `loadURL('http://127.0.0.1:8787/')`**：`file://` 页面发往该地址的**每个请求都是跨源**——§3.7-4 定 `Sec-Fetch-Site: cross-site` 一律 403，§3.7-2 定 `Origin: null` 一律拒（机制 **[未验证本机 Electron]**，跨源这点确定）。要让它跑，只能给 D4 开这两个口子，而 D4 的全部价值是"本机任意网页读不走投影"（PRD 2.3 `:60`），开完等于白修。反过来 `loadURL` **同源**：D4 一行不改，`--dist` 的静态服务（🟠-6，§3.4）顺带把页面发出来，A-8 也还在原路径上。

| 形态 | 加载方式 | 说明 |
|---|---|---|
| 生产 | `loadURL('http://127.0.0.1:8787/')` | 读口兼发静态（`--dist resources/ui-dist`），同源、零 CORS |
| 开发 | `loadURL('http://127.0.0.1:5173')` + 读口 `--allow-origin http://127.0.0.1:5173` | §3.7 已有机制 |
| 读口起不来 | `loadFile(path.join(__dirname,'offline.html'))` | 离线页**零 fetch**（不触 D4），只显示原因 + 命令 + **"重启读口"按钮**（走第 5 通道，v4-5） |

**代价**：`loadFile` 那个"界面不依赖读口"的好处没了——这正是 §7-R16 要交代的。

**T06 判据相应改写**（替代"能被 `loadFile` 加载"，保留其意图 = 产物自包含）：① `python -m http.server` 托管 `ui/dist`（无 Vite、无 HMR）→ 页面完整可用；② 资源引用全相对（`base:'./'`），出现 `src="/assets` 即红；③ `file://` 打开 `dist/index.html` **不白屏**，能渲染"读口未起"空态（同时是离线页兜底与 `loadFile` 语义的等价判据）。

**判据的四层 + 两道前置，逐层说清什么算红**（源码见 §5-T02-2b）：
- **前置 A（v4-3）冻结副本指纹**：`--frozen` 只算 sha256、从不当库打开；`--expect-frozen` 不符 → `FROZEN` 红。三份输入的 `db`/`schema` 必须相同（否则 `DB`/`SCHEMA` 红），防"after 跑在另一份库上"。"行数"由 PASS 第一行的 `keys=a/b/c` 与 `top` 承担（换副本时它们与 sha256/bytes 一起变）。
- **前置 B（v4-3）噪声集有上界**：噪声集仍是"同一份基线跑两次的差异集"（自校准），但**冻结上界**——`len(noise) <= 1` 且 `noise ⊆ {asOf}`；b1/b2 的键集或列表长度不一致 → `NOISE_DRIFT` 红。**上界不是手写白名单**：越界即判据自身失败，不放过。
- **第 1 层 键集合**：`set(baseline) == set(after)`，**允许新增字段的集合是空集**（`pid` 进 `/api/meta`，不进 scene）。少一个、多一个 → `KEY_MISSING`/`KEY_EXTRA` 红。
- **第 2 层 列表长度**：列表路径集合相等 + 逐路径 `len` 相等（`pushes[]`、`sessions[]`…）→ 否则 `LIST_MISSING`/`LIST_EXTRA`/`LIST_LEN` 红。**列表缩短不会被"键集合"含糊掉。**
- **第 3 层 类型**：每个键的 JSON 类型相等 → `TYPE` 红；**唯一例外是 `SANCTIONED` 表内那一条**（`string → null`，v4-2）。
- **第 4 层 值**：除 `asOf` ∪ `SANCTIONED` 表内 key 外逐键相等 → `VALUE` 红；受控项只认 `{from, to}`，第三种值 → `SANCTION_THIRD` 红；`from` 与基线不符 → `SANCTION_DRIFT` 红。

```python
#!/usr/bin/env python3
# -*- coding: utf-8 -*-
"""scene_diff.py —— /api/scene 快照四层对拍器（只读，不碰任何库）。

四层顺序写死：键集合 → 列表长度 → JSON 类型 → 值。
退出码：0 = PASS；1 = FAIL；2 = 用法/IO 错误（不是判据红）。

判据纪律（三处硬约束，全都能红）：
  1) 噪声集自校准但**冻结上界**：只允许 {asOf}，且最多 1 个键；
  2) 受控变更表 SANCTIONED 逐键写死 key/from/to，且只对表内 key 豁免类型检查；
  3) 冻结副本指纹（sha256 + 字节数）与三份输入的扁平键数必须进 PASS 输出。

只读：本脚本只读 JSON 文件；--frozen 只做哈希与取大小，从不当库打开。
"""
from __future__ import annotations

import argparse
import hashlib
import json
import os
import sys

NOISE = frozenset({"asOf"})
MAX_DETAIL = 40

# 受控变更表：一期只有 1 条（G8）。表外任何键变化 → 红。
# 类型层同样豁免：string -> null 是类型变更，只在表内放过。
SANCTIONED = {
    "missing.dialogue": {
        "key": "missing.dialogue",
        "from": "语料层（fish_corpus.py）在主树未合，events 表记的是系统事件不是对话轮次",
        "to": None,
        "task": "T04",
        "reason": "G8",
    },
}


def harden_stdio() -> None:
    """GBK 安全：Windows 管道/控制台默认 gbk，输出一律强制 utf-8 + 不因不可编码字符而崩。"""
    for name in ("stdout", "stderr"):
        stream = getattr(sys, name, None)
        try:
            stream.reconfigure(encoding="utf-8", errors="backslashreplace")
        except Exception:  # 老解释器 / 被替换的流：保持原样，靠下面的 ascii() 兜底
            pass


def typename(value) -> str:
    if value is None:
        return "null"
    if isinstance(value, bool):
        return "bool"
    if isinstance(value, (int, float)):
        return "number"
    if isinstance(value, str):
        return "string"
    if isinstance(value, list):
        return "list"
    if isinstance(value, dict):
        return "object"
    return type(value).__name__


def flatten(node, prefix: str = "", leaves=None, lists=None):
    """扁平化：dict 用 `.` 连，list 用 `[i]`；列表长度单独记进 lists。"""
    if leaves is None:
        leaves = {}
    if lists is None:
        lists = {}
    if isinstance(node, dict):
        if not node and prefix:
            leaves[prefix] = {}
        for key, value in node.items():
            flatten(value, "%s.%s" % (prefix, key) if prefix else key, leaves, lists)
    elif isinstance(node, list):
        lists[prefix] = len(node)
        for index, value in enumerate(node):
            flatten(value, "%s[%d]" % (prefix, index), leaves, lists)
    else:
        leaves[prefix] = node
    return leaves, lists


def load_scene(path: str):
    with open(path, "r", encoding="utf-8") as handle:
        doc = json.load(handle)
    if not isinstance(doc, dict):
        raise ValueError("top-level JSON must be an object: %s" % path)
    leaves, lists = flatten(doc)
    return doc, leaves, lists


def sha256_of(path: str) -> str:
    digest = hashlib.sha256()
    with open(path, "rb") as handle:
        for chunk in iter(lambda: handle.read(1 << 20), b""):
            digest.update(chunk)
    return digest.hexdigest()


def brief(value, limit: int = 60) -> str:
    text = ascii(value)  # ASCII 转义：任何值都不会让 gbk 管道崩
    return text if len(text) <= limit else text[:limit] + "..."


def build_parser() -> argparse.ArgumentParser:
    parser = argparse.ArgumentParser(
        prog="scene_diff.py",
        description="four-layer diff for /api/scene snapshots (key set / list len / type / value)",
    )
    parser.add_argument("--baseline", required=True, help="baseline run #1 (git show 45c4888 的 fish_ui.py 产出)")
    parser.add_argument("--baseline2", required=True, help="baseline run #2（与 #1 同一冻结副本，只用于自校准噪声集）")
    parser.add_argument("--after", required=True, help="candidate run（候选读口产出）")
    parser.add_argument("--frozen", required=True, help="冻结库副本路径：只算 sha256/字节数，从不当库打开")
    parser.add_argument("--expect-frozen", default="", help="可选：钉死冻结副本 sha256（小写十六进制），不符即红")
    return parser


def main(argv=None) -> int:
    harden_stdio()
    args = build_parser().parse_args(argv)

    try:
        doc_b, leaf_b, list_b = load_scene(args.baseline)
        doc_b2, leaf_b2, list_b2 = load_scene(args.baseline2)
        doc_a, leaf_a, list_a = load_scene(args.after)
        frozen_sha = sha256_of(args.frozen)
        frozen_bytes = os.path.getsize(args.frozen)
        input_sha = {name: sha256_of(path)[:8] for name, path in (
            ("b1", args.baseline), ("b2", args.baseline2), ("after", args.after))}
    except (OSError, ValueError) as exc:
        print("ERROR %s" % exc)
        return 2

    fails = []

    def fail(category: str, key: str, detail: str = "") -> None:
        fails.append((category, key, detail))

    # 受控变更表一期上限 1 条：超过即红，防止它长成万能白名单
    if len(SANCTIONED) > 1:
        fail("SANCTION_TABLE", "size", "一期上限 1 条，实际 %d" % len(SANCTIONED))

    # ── 冻结副本与同源性：换了一份冻结库、或 after 跑在别的库上，必须红 ──
    if args.expect_frozen and frozen_sha != args.expect_frozen.lower():
        fail("FROZEN", "frozen", "sha256=%s != expected=%s" % (frozen_sha[:16], args.expect_frozen[:16]))
    for name, doc in (("baseline2", doc_b2), ("after", doc_a)):
        if doc.get("schema") != doc_b.get("schema"):
            fail("SCHEMA", name, "%s != baseline %s" % (doc.get("schema"), doc_b.get("schema")))
        if doc.get("db") != doc_b.get("db"):
            fail("DB", name, "%s != baseline %s" % (doc.get("db"), doc_b.get("db")))

    # ── 噪声集：自校准（跑两次取差异集），但只准落在冻结的 {asOf} 里且最多 1 个 ──
    noise = sorted(k for k in set(leaf_b) & set(leaf_b2) if leaf_b[k] != leaf_b2[k])
    if set(leaf_b) != set(leaf_b2) or list_b != list_b2:
        fail("NOISE_DRIFT", "shape", "baseline 两次结构不同：冻结副本被换 / 数据在动")
    if len(noise) > 1:
        fail("NOISE_DRIFT", "count", "noise=%d > 1" % len(noise))
    outside = [k for k in noise if k not in NOISE]
    if outside:
        fail("NOISE_DRIFT", outside[0], "noise outside %s: %s" % (sorted(NOISE), ", ".join(outside[:5])))

    key_b, key_a = set(leaf_b), set(leaf_a)

    # 第 1 层：键集合（允许新增字段的集合是空集）
    for key in sorted(key_b - key_a):
        fail("KEY_MISSING", key, "type=%s" % typename(leaf_b[key]))
    for key in sorted(key_a - key_b):
        fail("KEY_EXTRA", key, "type=%s" % typename(leaf_a[key]))

    # 第 2 层：列表路径与长度
    for path in sorted(set(list_b) - set(list_a)):
        fail("LIST_MISSING", path, "len=%d" % list_b[path])
    for path in sorted(set(list_a) - set(list_b)):
        fail("LIST_EXTRA", path, "len=%d" % list_a[path])
    for path in sorted(set(list_b) & set(list_a)):
        if list_b[path] != list_a[path]:
            fail("LIST_LEN", path, "%d -> %d" % (list_b[path], list_a[path]))

    # 第 3 层：类型（SANCTIONED 表内的 key 豁免——string -> null 是受控的类型变更）
    common = sorted(key_b & key_a)
    for key in common:
        if key in SANCTIONED:
            continue
        if typename(leaf_b[key]) != typename(leaf_a[key]):
            fail("TYPE", key, "%s -> %s" % (typename(leaf_b[key]), typename(leaf_a[key])))

    # 第 4 层：值（噪声集 + 受控变更表；受控项只认 {from, to} 两个值，第三种值必红）
    hits = 0
    for key in common:
        if key in NOISE:
            continue
        old, new = leaf_b[key], leaf_a[key]
        if key in SANCTIONED:
            item = SANCTIONED[key]
            if old != item["from"]:
                fail("SANCTION_DRIFT", key, "baseline=%s != from=%s" % (brief(old), brief(item["from"])))
                continue
            if new == item["from"]:
                continue                      # 还没落地（T04 之前）：合法
            if new == item["to"]:
                hits += 1                     # 恰好落地一次
                continue
            fail("SANCTION_THIRD", key, "after=%s not in {from,to}" % brief(new))
            continue
        if old != new:
            fail("VALUE", key, "%s %s -> %s" % (typename(old), brief(old), brief(new)))

    counts = {}
    for category, _key, _detail in fails:
        counts[category] = counts.get(category, 0) + 1
    summary = " ".join("%s=%d" % (item, counts[item]) for item in sorted(counts))

    if fails:
        print("FAIL total=%d %s" % (len(fails), summary))
        for category, key, detail in fails[:MAX_DETAIL]:
            print("  %s %s %s" % (category, key, detail))
        if len(fails) > MAX_DETAIL:
            print("  ... %d more" % (len(fails) - MAX_DETAIL))
        return 1

    print("PASS schema=%s top=%d keys=%d/%d/%d lists=%d noise=%d(%s) sanctioned=%d"
          % (doc_b.get("schema"), len(doc_b), len(leaf_b), len(leaf_b2), len(leaf_a),
             len(list_b), len(noise), "asOf" if noise else "none", hits))
    print("     frozen=sha256:%s bytes=%d inputs=b1:%s b2:%s after:%s"
          % (frozen_sha[:16], frozen_bytes, input_sha["b1"], input_sha["b2"], input_sha["after"]))
    return 0


if __name__ == "__main__":
    raise SystemExit(main())
```

## §6 共享知识（12 条，写码前统一）

1. **错误信封只有一个形状**：`{schema, asOf, availability:{state,detail}, data, error?, sources:[{source,ok,rows,error,ms}]}`；`sources` **永远出现**（A-2 的证据）。
2. **`asOf` 是载荷生成时刻，不是响应时刻**；缓存命中时 `asOf` = 算缓存那一刻（92 §七）。
3. **时间口径**：库里全是 UTC ISO（`fish_common.now_utc:56`），后端只发 UTC + 时区标记，前端本地化。今天有血的例子：`presence WHERE last_seen_at >= '2026-11-23T00:00:00'` 得 0 行——本地 05:2x 时 UTC 还是 11-22T21:2x，拿本地日期边界比 UTC 字符串会造成"全部休眠"的假警报。
4. **0 与缺严格分开**：缺 = `null` + `sources[].ok=false` + `detail`；前端禁 `?? 0`、禁骨架数字、禁示例值。已知实例：`corpus.stats` 的 `db_bytes.segments/fts` 在本机返回 `0`（`dbstat` 取不到时 `_table_bytes` 返回 0，`fish_corpus.py:726-732`）——**这个 0 不是读数**，读口必须转 `null`。
5. **领域判断一律后端算**（K8），前端不算这六个：闭合、撞车、板多方/单人、记忆状态、注入内容、**在场三组**。
6. **状态码**：`200` 有数据或明确空态；`400`/`403`/`404`/`405`/`503` 见 §3.4。不用 200 传错误，不用 500 传"库不存在"。
7. **命名**：出参 `camelCase`，入参查询串小写（`citizen`/`project`/`since`/`limit`）；SQL 列名不出前端。
8. **日志**：一行 JSON `{ts,level,method,path,status,ms,source,err?}` 到 stderr，**不落库**。现状 `log_message` 被 `pass`（`fish_ui.py:500-501`），改造后保留安静、但错误行必须打。
9. **空态文案由后端给 `code` + `action`**，前端只映射；同一个 `DB_MISSING` 六视图说同一句话。
10. **可复制命令必须真能跑**：`action` 里的命令要能在 PowerShell 5.1 直接跑（`curl.exe`、带空格路径加引号、中文输出加 `-X utf8`）。
11. **Windows/PowerShell 5.1 的三条硬坑（v2 新增，判据死在这里）**：① `>` 重定向是 UTF-16，**别用它接 git/python 的 UTF-8 输出**——用 `python -X utf8 … > file` 或让 python 自己 `write_bytes`；② 原生命令管道默认 gbk，**中文 JSON 会 `UnicodeEncodeError`**（实测 `'\U0001f534'` 直接 rc=1 + 0 字节）；③ `Get-Content` 数行会少数，行号一律用 `read`/node。
12. **只读纪律的唯一写法**：新开连接必须 `open_readonly()` + `assert_write_rejected()`；新增写库动作 = 架构违规，评审直接拒。**唯一允许写文件处** = `data/_ui/corpus-doctor.json`（§3.9-5）。
13. **壳层两条（v3 新增）**：① 只有 `main` 能碰 Node，`preload` 零领域逻辑（§3.10.1 有 0 次 `if` 的机检判据），`renderer` 与浏览器版**逐字节相同**；② **8787 是"读口存在性"的锚**，自动换端口即设计退化（§3.10.2）。
