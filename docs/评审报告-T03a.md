### S2 [🟠] `score` 与 `score_breakdown` 是**两个阶段**的数——T03b 要满足 R3 只能重写 `score`，与 C1 的自锁正面冲突

### S3 [🟠] `dup_penalty` 在真实链路**结构性恒 0**，且按报告自己给的接线配方仍然恒 0；与 `_push_history`/`_silence_weight` 重复惩罚同一现象

## 6 · 对评审重点六问的直接回答

**Q1 kind_class 是否最小侵入 / 有无更干净做法 / 会不会让下游误用**
最小侵入成立（改 `kind` 会动既有锁，不可取）；但**下游一定会误用**：`select_push_candidates`/诊断仍读 `kind`（S1 证据），且 mem 侧五种 kind 一个都没有 `kind_class` → "三类合流"是空头承诺。把它做干净只需三件：单点归一函数 + 不变量判据 + 交接写清"其余类别由 T03b 映射"。在 T03b 边界适配（不污染候选）是更干净的另一条路，但代价是每个消费点都要记得映射表——**当前的字段化方向对，缺的是配套**。

**Q2 `score_breakdown` 是观测还是参与 score / 与 benefit−cost、双折扣纪律是否一致 / `dup_penalty` 归一与 34 §3.3 / `combine_features` 与 R3**
T03a 里它是**纯观测**（`score` 不被改写，C1 有判据）——这一点与本项目"打分公式只有 `_cand` 一份"的纪律**一致**，也对 `freshness` 保持了双折扣纪律（传给 `_cand` 的仍是 `None`）。但：
① 它与 `score` 是**两个阶段**的数，34 §3.3 的 f1 应是首阶段原分，这里是检索 relevance（S2）；
② `dup_penalty` 归一（min(count,5)/5，负号在权重上）与 34 §3.3"次数、负向、权重 −0.30"**不冲突**，属合理细化，但它在真链路上恒 0（S3），且与 `_silence_weight` 对同一现象二次惩罚；
③ `combine_features` 线性、不夹紧、分项和严格等于总分 → 与 R3 **代数自洽**；但值域 [−0.30, 0.95] 不是 0..1，且若 `score := combine_features` 则 R3 恒真（Y4）。另外 `freshness` 在检索分里已含 0.2×recency（`fish_corpus_rank.py:351-352`），T03b 再乘 0.15 的 freshness 是**跨阶段再折扣一次**——这条要 T03b 明确认账或让 f1 退化为 BM25 归一。

**Q3 六特征单源放 `fish_corpus_rank.py` 是否引入 push→corpus 跨域依赖 / 52 §2 是否允许 / 更合适的位置**
