## 11 · 已知限制 / 未闭合（登记，不冒充已解决）

1. **跨类分数不可比（评审 W3）**：`relevance` 用整个 head 的 min-max，三类首阶段分不同源
   （记忆 = `(benefit−cost)×weight`；kb 恒 0.5；corpus = relevance 0–1），所以跨类**只保序
   不保距**；`score > 0` 门槛拿它当绝对值用（开启时）。已在 `combine_features` 的 Y4 段与
   `select_push_candidates` docstring 写清，本轮不改归一策略（属 A 的裁决面）。
2. **`access_ratio` 取数口径（W4）**：用 `memory_access_log` 的 `COUNT(*)`（同一会话反复读
   会累加），设计写的是 `access_count / max(access_count)`。二者选一需 A 拍；本轮保持并登记。
3. **`dup_penalty` 与既有两套"重复"机制的分工（W6）**：`dup_penalty` = 24h **全局**推送次数
   （封顶 5）；`_silence_weight` = 按 code 全历史的忽略比例（权重乘子）；`_cand` 的
   `false_p` = 成本项；prompt 路径上还有 24h 会话级排除。**后果（QA F-3）**：prompt 路径上
   `dup_penalty` 几乎恒 0（同会话/同 kb 候选已被 24h 排除）——R4 绿 ≠ 生产上"防重复"到位。
4. **`rerank_candidates` 不可重入（W7）**：入口没有 `score_stage` 守卫，二次调用会把"重排分"
   当首阶段分再 min-max。当前无二次调用点；登记为潜在坑（本轮不修，避免引入未判据化的行为）。
