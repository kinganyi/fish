用户的目标是"把作用等价的实现去重、收敛、规范化，同时保住解耦/模块化/性能意图的代码"。审计结论分三句：

判决原则：**机制合并、策略留名**。两个函数做同一件事的"做法"可以合；对同一件事的"判断策略"（解析失败算无穷大还是算未知、空标签显示为空白还是"(未归属)"）必须留在调用点并各自命名——强行统一会制造新的语义债。

## 四、补扫：新发现（每条带实测或位置证据）

### N-1（应改判）`connect` 不是三个库，是两个同库 + 一个异库，且外键双标

原判断把三处 `connect` 归为"不同库，保持"。实测：

- `fish_activity.connect`（`:205`）打开 `<data_dir>/index.sqlite`，`timeout=5.0`、`busy_timeout=3000`，**不设 `foreign_keys`**；
- `fish_schema.connect`（`:692`）打开**同一个** `<root>/index.sqlite`，`timeout=10.0`、`busy_timeout=10000`、**`foreign_keys=ON`**；
- `fish_corpus_store.connect`（`:232`）打开 corpus 库，是另一个库，保持。

后果可测：同一张 `presence`、同一条非法 `board_id`，两条连接路径给出相反答案。实测输出：

```
A fish_schema.connect   PRAGMA foreign_keys = 1
   -> REJECTED: FOREIGN KEY constraint failed
B fish_activity.connect PRAGMA foreign_keys = 0
   -> ACCEPTED (silent write of orphan row)   <<< DIVERGENCE
```

schema 里确实有 7 条外键（`board_posts`/`presence`/`git_remote`/`git_repo_alias`/`git_checkout`/`git_obs`/`git_commit`），而 `presence` 正是 hook 高频写的表。所以"外键这件事"在 hook 路径上从来没生效过。

### N-4（新）时间口径：两套互斥约定，77 次字面量

`"%Y-%m-%dT%H:%M:%SZ"` 在 17 个生产模块出现 77 次，具名封装至少 6 个（`fish_common.now_utc:56`、`fish_common._utc_str:664`、`fish_push_audit._iso:225`、`fish_workbench_api.iso:179`、`fish_maintenance._iso_utc:188`、`fish_git_store._iso:41`）。重复本身不算大问题（一行 strftime），**真问题是两套 naive datetime 约定**：

- "naive 就当 UTC"：`fish_common._utc_str:671-674` 用 `replace(tzinfo=utc)`；
- "naive 当本地、再转 UTC"：`fish_maintenance._iso_utc:188-189` 用 `astimezone(utc)`，`fish_session_hook.py:132-133`、`fish_activity.py:1637` 同族。

对 aware datetime 两者结果相同；对 naive 差一个本地偏移（本机 UTC+8 即 8 小时）。仓里有 31 处生产代码调用无 tz 的 `.now()`（`daily_report.py:258`、`fish_kb.py:1835`、`hook_io.py:113` 等），燃料充足。

## 七、判据本身要能失败：三个反例与一个"假绿"

已有判据里最危险的一条是 `test_surface_naming.py:198` 的 `test_fish_resolver_same_answer`。它声称"两个解析器给同一个答案"，但用例全是 `/a/b/c/x.py` 这类**不存在的纯文本路径**——两边都不会进 `realpath` 分支，所以它**今天在分叉已成立的情况下依然绿**。这就是假绿：判据覆盖了"相等"，没覆盖"为什么会不相等"。

防法三条，建议写进验收模板：

1. **先在坏输入上证明判据会红**。我这次的顺序是：先建 junction 跑对拍（红）→ 再给修复前后对比。没红过的判据不算判据。
2. **变异必须打在"语义开关"上**，不是打在注释/变量名上。例如 C-C1 的变异是"摘掉 canonical 兜底"（语义），不是"改个变量名"（形式）。
3. **对照组必须绿**。C-B1 里"从 DB 删光 `prompt` 行"会红，但如果**任何**输入都红，说明判据读的是空集——所以每条判据都要带一个未变异对照。

最容易变成假绿的一条（我的自评）：**C-A2（host 默认值）**。因为它看起来像在测"合并没改行为"，而实际上如果把四个 hook 的默认值统一成 `dsh`，再用"四个都等于 dsh"当断言，它会**全绿**——但那恰恰是错误方向（posttool 的 `workbuddy` 如果是有意的，这个判据就掩盖了行为改变）。防法：断言必须写成"每个 hook 的默认值 == 该 hook 的**历史**默认值"这个显式清单，并在改动前先把清单落进测试；清单本身要能回答"为什么 posttool 是 workbuddy"。

## 八、风险与不做清单

### 最危险的一处合并：时间口径（N-4）

不是 A1（删掉两个没人写的值，无法影响任何历史行），也不是 A2（今天无 junction，行为中性）。**最危险的是把六个时间封装合成一个**：两套 naive 约定互斥，本机差 8 小时；失败形态是**静默的**——时间戳仍是合法 ISO 串、`parse_utc` 照常解析、窗口查询照常返回，只是"最近 24 小时"悄悄变成"最近 32 小时"。142 处字面量 + 31 处 naive `.now()` 让这个错误极难在 code review 里看见。

**结论：这一片本轮不合并**，只做两件低风险的事——① 把"naive 必须显式声明约定"写进 coding 约定；② 给 `_utc_str` 与 `_iso_utc` 各补一条针对 **naive 输入**的判据（先证明它俩对 naive 输入**不相等**，这个红是特性不是 bug）。

### 第二危险：W-E 开外键

它把"静默脏数据"换成"静默丢数据"——hook 的失败策略是静默，所以这个方向的错在运行期完全无声，只在"怎么少了几条在场记录"里慢慢体现。

### 不做清单（看起来重复，但不该合）

1. **hook 不许 import `fish`**：`fish.py` 依赖 26 个模块、import 成本秒级；hook 有 3 秒预算。所以 4 个 hook 里"看起来能与 fish 共用"的东西，只能进叶子模块。`hook_fastpath.py:72` 的"不 import fish、不起子进程"是**性能契约**，不是懒。
2. **UI 与服务端各一份类型**：`ui/src/api/types.ts` 与 `fish_workbench_api` 的 dict 结构是**跨进程契约**，两端各写一份是正常且必要的；合并它需要代码生成，收益不抵成本。但注意 `types.ts` 里 `channel: string`（`:454`）是**裸字符串**，编译期拦不住第五个值——这是 W-B 之后仍存在的缺口，应登记。
3. **`fish_kb.kb_atomic_write`（`:189`）不与 `fish_atomic` 合并**：前者带 EOL 检测与归一（`kb_detect_eol:173`），是"保字节形态的写"，后者是"保原子的写"，目标不同。
4. **`session_context.channel`（cli/hook/parent）与 `push_log.channel` 不合并**：两个不同维度，各自的 CHECK 各自成立。A1 的教训恰恰是**曾经把它们混在一起**。
5. **`fish_activity.connect` 与 `fish_corpus_store.connect` 不合并**：不同库、不同 PRAGMA 策略（corpus 要 `readonly` URI 与 `isolation_level=None`）。
6. **`topCodes`（审计，30 天/12 条，LEFT JOIN `code_index` 取标题）与 `pushTop`（面板，1 天/5 条，不 JOIN）不合并**：窗口、LIMIT、JOIN 三处都不同，合并会把首屏性能绑到审计口径上。但两者 SQL 形状确实近，应登记为"同形不同义"。

### 其他风险

- **多会话共用工作树**：本仓有 `_wave-backup/` 与已知的"落错分支"事故史。任何一波动手前先 `git branch --show-current` + `git status -sb`，改完立刻 `git log -1 --oneline` 复核落点。
- **生产库只读**：本文所有库读操作都走 `mode=ro` URI。W-B/W-E 的判据若需要写库，只能在临时副本上写，不许碰 `index.sqlite`。
- **`workspace_map` 那条已失效映射（N-8）** 会让 W-C 的 C-C3 对拍"看起来很干净"（不存在 → 文本兜底），别当成 junction 覆盖充分的证据。
