## 2. 五问直接回答

**a) 两维模型够不够用？——够用，但理由要改写两处。**
"不用 `agentPath` 数组"的结论成立；它给的四条理由里第 2、4 条要改：
① 它说"两个宿主都不交错"。实测：DSH 父日志 `isSubAgent`-类事件 0、WB 父 transcript（835 MB / 105,637 行）`isSubAgent:true` **0 次**——**落盘形态**确实不交错，这条成立。但**宿主能力**层面不成立：我在 WB `app.asar` 的 `conversations.js` 里读到 `readHarnessSubagent` 返回 `{sessionId, rootSessionId, parentSessionId, **parentToolCallId**, agentRole, agentNickname}`，`node.js` 的 `routeSubagent` 用 `rootSessionId ?? parentSessionId` 定 owner——**"同一会话多代理"的形状在 WB 已有字段**，只是没写进父流。所以正确表述是"当前落盘形态不交错"，不是"没有数组场景"；`agent_path` 的预留因此**更有必要**，别写"fish 不接这类宿主"。
② `agent_role` 跨宿主语义不齐：DSH 取 `agentPreset`（稳定枚举，如 `dafish-team`），WB 取 `providerData.agent`——我抽 40 个 agent transcript、12,407 条消息，取值除 `software-engineer` 外大量是**自由任务名**（`impl-outbound-doc`、`extract-quote-c`、`lineage-audit`、`r-model-mcp`）。同一列一半是枚举、一半是每 spawn 变化的标签，按它聚合会得到高频噪声。**改法**：`agent_role` 只放能对上宿主枚举的值（WB 用 `expert_runtime_identity`/`agentName`），`providerData.agent` 落 `agent_label`。
**反例回答（会不会出现 Claude Code 式同会话多代理）**：会，而且 WB 的 `parentToolCallId` 已经是那个形状；但那时需要的不是标量加长，而是 `agent_path` 开始填值 + `parent_session` 自指——文档已把这条写进 §3.1 的"唯一预留"，方向正确。

**b) "路径即父"能否作 primary basis？——能，但只能当"可失败的二级"，而且必须补一条跨源对拍。**
三点全核过：(a) 2,092 个 transcript **无一个**在 `subagents/` 之外，`subagents/` 里也**无**非 `agent-*` 的 jsonl，相对深度**全为 4**（`<ws>/<父sid>/subagents/agent-*.jsonl`），所以"路径即父"今天没有假阳性；(b) 31/31 父 id 都在 `sessions` 表；(c) 独立第二源：10 个 `teams/*/runtime.json` 的 `leadSessionId` 与 31 个父目录**10/10 完全相等**——这是文档没做、但对它有利的强证据。
**但**：21/31 的父**没有任何独立源可对拍**（它们不是 team lead），而 J3 只校验"有父就带 basis"，**父错了照样绿**。所以：`runtime` 优先、`path` 兜底的顺序对，但 J3 必须升级为两条可失败判据：① 父 id 必须命中 `sessions`（它已有）＋ ② **10 个 team lead 行必须逐条等于 `runtime.leadSessionId`**（变异：临时副本里改一个 lead 的 session 目录名 → 该行必须 `missing`，且对拍必须红）。

**c) 继承父公民的最大风险一条**：**吊销/到期粒度从"会话"塌缩到"公民"，并且与 `citizens.host_session_key` 的单值语义冲突**（详见 🔴-1，可复现：继承后的子会话跑 `fish session end` 直接抛 `ValueError`；回退旧 `start_session` 会给每个子会话**再造**一个未命名公民，同会话两公民 + 归属漂移）。
按题目三小问逐条：**推送去重/采纳率不会错**（去重与统计都按 `session_key`：`fish_push.py:836-860`、`fish.py:8184-8200`；文档说的"按 `(citizen, code)` 去重"在代码里不存在，见 🟡-1）；**经验层会失真**（`memory_access_log`/`daily`/`blind-spot rate` 都按 code 与 citizen 聚合、不区分 session，子代理读过 = 父"读过"，`push_stats` 的盲区消除率会虚高）；**会话级权限无法区分**——成立，但 fish 本来没有会话级权限模型，只有公民级可见性，继承恰好是想要的行为；真代价是撤销粒度。

**d) 推送 §3.5 是否闭合？——不闭合**：核心输入无证据（🟠-1）、闸门与回退不闭合（🟠-2）、判据在 WB 侧恒空（🟠-4）。三条都不是措辞问题，是"按它写的做会得到相反结果"。

**e) 最不可靠的一处证据**：**`transcript_path` 在 WorkBuddy hook 里可用**。它被当作 §3.5 规则 3 的第一优先级输入、W4.5 的实现项、J-P2② 的构造样本，但：① WB `app.asar`（12,293 个文件、172.9 MB，**可解析**）全文检索 `transcript_path` = **0 命中**、`hook_event_name` = **0 命中**；② 本仓自己的 `docs/PRD-对话语料层-261027.md` 与 `docs/ARCH-对话语料层-261027.md` 写着"hook 的 `transcript_path` **恒空**（A:54,70,90 + 心跳实测）"；③ 它自己 §7-9 又说"hook 是否给 agent 标识 **当前 [判不到]**"。同一份文档对同一字段给出三种相反说法，且都未取证。
另附一条反证它"未复跑"的理由：它说"应用包本机不可读（原文来自只读调研 @8346925）"——**不成立**，asar 明文可解，我用一条 40 行脚本就读到了 `parentSessionId`/`readHarnessSubagent`/`routeSubagent`。所以"转引"不是客观限制，是没做。

### 🔴 致命（改完才可开工 W4）

**🔴-1 W4 的"继承父公民"与现有身份架构冲突，且回退点不成立**
- 位置：§3.3（"子会话继承父公民"/"父轮换时级联吊销"）、§5-W4 回退格、§7-7。
- 证据：① 身份查找**只认 `citizens_all.host_session_key`**（`fish.py:3741-3752`），而 `host_session_key` 是 `citizens` 上的**单值列**——一个公民只能挂**一个** session_key。子会话继承父公民后，子 session_key 在任何 `citizens` 行里都不存在。② 于是 `end_session` 的**无 token 入口**必然炸：`fish.py:4529-4534` `find_session_citizen(...)` 为 None → `raise ValueError("当前会话没有登记过公民")`。而 `fish session end` 是文档化命令。③ 回退（"切回旧 `start_session` 调用"）会走 `find_or_create_session_citizen`（`fish.py:3771-3785`）→ 子 session_key 查不到 → **新建一个公民**；此时子会话的 `session_tokens.citizen_id`=父公民、`citizens` 里又有一个新公民 → **同一会话两个公民**，`resolve_citizen` 两级各自命中不同值 → 归属漂移。这正是本设计要治的病。④ 它说的"父**轮换**时级联吊销（`:4527`）"也不对：`revoke_session_tokens(parent_hash=…)` 只在 `end_session` 里调用；`start_session` 的轮换只按 `session_key` 吊销（`fish.py:4401`），级联**不发生在轮换**。
- 改法：(i) W1 的 `session_identity` 必须成为身份**唯一解析口**，并明确 `find_session_citizen`/`end_session`/`find_or_create_session_citizen` 三处一起改（现在 W4 的文件清单只列了 `ensure`/`rotate`、`issue_agent_token`、`fish_activity.resolve_citizen`，**漏了 `end_session` 与 `find_session_citizen`**）；(ii) 回退必须是"开关 + 一个 `citizens` 侧兼容写"（把被继承的 session_key 记进旁表而不是 `host_session_key`），否则给出**不产生第二个公民**的回退步骤；不能只写"切回旧调用"。
