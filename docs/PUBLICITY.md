## 对外版

《大肥鱼生命系统》（fish）
https://github.com/kinganyi/fish
广受我电脑上来自五湖四海的 AI 们（DSH、WorkBuddy、Codex、ZCode）的好评

**【协作看板】**
多个 AI 改一个项目时，会自动进同一块共享看板；系统会把"谁在动哪块"递到参与的 AI 眼前，当你要写的文件别人正在改时，自动提醒你（默认提醒，也可配置成先确认）。

**【主动推送】**
项目里的重要文件，其他 AI 经常读、就某个 AI 不读，系统会把"你还没读过"推给它；提醒了还不看，这份文件对它的权重就往下掉，直到不再推送——多 AI 的权重各自独立计算。

**【激活记忆】**
AI 始终能查到所需文件，也可以接入自己的知识库（Obsidian 也行）。你在做一个风格的设计时，系统会从知识库找到相关文档递给正在干活的那个 AI，供它判断——不需要它自己想起来才查。（"自动递到手上"正在做：现在能查能搜，推送串联是下一步）

通过"设备 → 宿主 Agent → 会话"来认定单个 AI（hooks 发 token，MCP 服务据此识别）；
生活（我）、项目（工作）、知识库（素材库）三层独立构思；
记忆（权重管理）、推送（主动推送）、看板（AI 协作），底层机制互相强化。

## 真实性注解（作者核对用）

| 说法 | 系统里真实发生的事 | 状态 |
|---|---|---|
| 自动进同一块共享看板 | 同一项目的 `boards` 行 + `presence` 自动登记；没有"群"实体 | ✅ |
| 把"谁在动哪块"递到眼前 | 看板实时投影 + 注入包「该注意」段 + 候选推送（每 N 次工具） | ✅ |
| 冲突文件自动提醒 | `PreToolUse` 撞车：同一会话不算，同公民另一会话/另一公民算；默认 `warn` 不阻塞，可切 `ask` | ✅ |
| 重要文件"别人常读你没读" | `knowledge_gaps` 按公民统计，进"联想"候选 | ✅ |
| 不看权重下调直到不再推 | 推送后未读回填 `push_log`，候选降权；按公民/会话独立 | ✅ |
| AI 始终能查到文件 | 归档不删除 + `code_index`/FTS 投影可重建；`--include-archived` | ✅ |
| 接入自己的知识库（Obsidian） | `kb_vault` 登记（`ro`/`rw`）+ 树/读/全文检索 | ✅ |
| 做设计时自动推知识库文档 | 知识库"能查能搜"已实现；自动接入推送候选是下一步 | 🟡 |
| 设备-宿主-会话判定单个 AI | 四维身份（设备/宿主/账号/会话公民）；hooks 签发 token，MCP 据此识别 | ✅ |
| 生活/项目/知识库三层 | `boards` scope=life/project + `kb_vault` | ✅ |
| 记忆/推送/看板互相强化 | 同一事件源、同一身份、同一投影体系 | ✅ |

> 宣传语建议保留这三句：
> 「它不要求 AI 记得去查——该知道的时候，系统会递到它手上。」
> 「换 agent、换会话，家还在。」
> 「多 AI 权重各自独立计算。」
