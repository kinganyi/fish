# 分支开发说明（git 仓）

> 建立时刻：2026-10-25 23:5x（Asia/Shanghai）｜建立者：`fish-开发AI`
> 决策记录：fish 记忆 **`大肥鱼生命系统-261025-20`**（rule，永不衰减）
> 拍板：用户 2026-10-25 23:49——fish 后续**主线任务改为分支线上开发**，不直接改 `p0` 主工作树。

## 1. 为什么要有这个仓

- fish 项目**此前没有任何 git**（`p0`、项目根、`learn` 三处 `git rev-parse` 均 exit 128），历史版本靠 `p0/历史版本/*.bak`。
- 同一时刻 `fish-主AI-3` 在主工作树 `p0/` 上修 EVAL-261025-17/18/19/20/21 与看板机制缺口。
- 两个 AI 共用一棵树时，"改哪片"只能靠口头协议；引入 git 后可以做到**分支隔离 + 可追溯 + 可回滚**。

## 2. 载体与基线

| 项 | 值 |
|---|---|
| 仓库根 | 本文件所在项目的根目录（`大肥鱼生命系统`） |
| 主分支 | `main`（只放基线，不直接开发） |
| 开发分支 | `dev/fish-devA`（git worktree 挂载，独立目录 `learn\fish-devA`） |
| 基线 | `fish-主AI-3` **收工态**（不是中间态）：`p0` 代码 ≥10 分钟无写入 + 无测试进程 + 无工作区锁 |
| 基线指纹 | 见首提交 message：`fish.py` / `mcp_server.py` 的 sha256 + 时刻 |

**为什么用 worktree 而不是同目录切分支**：同一个目录切分支**不隔离文件**——对方未提交的改动会直接落进你的工作区。worktree 是同一仓、独立目录、各挂分支，是真隔离。

## 3. 版本化范围

**纳入**：全部 `*.md`（39 份文档 + `docs/`）、`p0/*.py`、**`p0/data/projects/**/*.md`（正文，唯一副本）**、`p0/data/blobs/`、`35-迁移映射-mapping.json`、`.ai-memory/`。

**排除**（见 `.gitignore`）：`p0/data/index.sqlite*`、`p0/data/_backups/`、`p0/历史版本/`、`p0/data/_audit|_reports/`、看板渲染文件、`__pycache__/`、`.pytest_cache/`、`_research/`，以及 **`24-会话全记录-卷1/卷2`**。

> 会话全记录为什么排除：2026-10-25 建仓前的**凭证扫描实测命中**这两份文件里有 `fsh_` 前缀 token 明文（会话日志把 hook 注入的凭证记了下来——这是已裁定接受的代价）。它们仍留在磁盘，只是**未脱敏前不进版本库**；要入库必须先脱敏再单独提交。

> ⚠️ **重要边界：git 不是 events 的备份。**
> events 是唯一真相，但它是 `index.sqlite` 里的二进制、每次写入都变，版本化只会得到"无法阅读的历史"。
> events 的安全仍由 fish 自己的 `data/_backups/` 机制负责（建立本仓时已有 11 份 / 11.89 MB）。
> **不能因为"进了 git"就认为数据安全——这是两层不同的保护。**

## 4. 纪律

1. 建仓/基线完成前，不得在 `p0` 开工改任何文件。
2. 开发只在 worktree 内；worktree 的 `p0/data` 是收工态快照副本（sqlite backup 一致拷贝），**开发与测试不碰生产库**。
3. 合并回 `main` 的权在用户，不自行合并。
4. 判据：`git worktree list` 两处、worktree 当前分支 `dev/fish-devA`、`git status --porcelain` 干净、worktree 内全量 `unittest` 与基线对账。
5. **devA 副本里真实 vault 的 `mode` 恒为 `ro`**（第二轮 N5 / 安全 F15）：`kb_vault` 里那条
   `安逸知识库` **只能读**。写验收一律在 `tempfile.mkdtemp()` 造的临时 vault 上做；
   生产 `rw` 在合并时由主理人执行，不在开发副本里预演。
   > 事故留档：T04/T05 期间这条纪律被破过一次（当时 `mode=rw`，`kb_access` id 17–20 有
   > `create MCP-复核.md` / `append 旧正文.md` / `rollback`）。已全部 rollback，实测真实库
   > 无 `MCP-复核.md` / `旧正文.md` 残留；`mode` 已回到 `ro`。

## 5. 回滚

- 退掉 git：删除项目根 `.git` 即回原状（建仓前本来没有 git，零历史包袱）。
- 退掉 worktree：`git worktree remove <worktree 路径>`（或先 `git worktree prune`）。
