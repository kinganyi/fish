## §0 一页结论

**三栏语义重定义（一句话各）**：

- **左栏 = 切片器**，回答"这一屏我要按哪一刀看"。它不是"项目列表"也不是"看板列表"，它是**当前视图的作用域**——所以同一时刻只能有一刀生效。
- **中栏 = 流水**，回答"刚才发生了什么、谁做的、做在哪"。全屏唯一的正文区，只读、可折、不可写。
- **右栏 = 判断面**，页签一回答"现在需要我做什么"（不是"系统有什么"），页签二回答"这一条背后是谁、他还干过什么"（账本，不是属性表）。

**三个数决定了这次设计必须偏离 96**（实测，见 §1）：

1. `tool_activity.project` **91.7% 为空**（25,391 / 27,688）→ 96 的"点项目过滤中栏"在 24h 上会把 3,404 条砍到 **560 条**（工具 151 + 推送 409；另两源无项目列，只能归"未归属"），而**工具动作里 1,829 条（74.8%）根本不带项目**——用户看到的是"系统大部分行为消失了"，而不是"我筛了项目"。
2. 看板登记**全库只有 445 条**（今日 5 块开着的板里 3 块 0 条）→ 若"看板"是 post 过滤，点下去基本得到空屏；而同一块板（board 155）的会话 24h 内有 **1,519 条**动作。板的正确语义是**会话作用域**，不是登记过滤。
3. `tool_activity` 里**同一个会话吞掉 57.6% 的动作**（1,407 / 2,444）→ 折叠不是"锦上添花"，是不折叠就看不清别人在干什么。

**四个端点的实测耗时（n=3 中位数）**：`/api/stream` 27.3 ms（24h，首调 103.1 ms）｜`/api/stats` 42.6 ms（复用 `fish.push_stats(days=1)`，60 s 缓存）｜`/api/facets` 25.3 ms（项目聚合）｜`/api/entry` `[未验证]`（预估 < 15 ms，同量级单行查询，T03 第一件事就是测它）。

**成本**：6 个任务 / **32 人时**（含 4 h 联调）。**`fish.py` 一行代码都不进**——实测它已经 **10,599 行**（`python -X utf8 -c "print(len(open('p0/fish.py',encoding='utf-8').read().splitlines()))"`），距 93 §7-R5 记的棘轮 10,600 **只剩 1 行余量**。

## §1 数据面复核：我推翻了上游两条，新增了五条

### 1.1 推翻 96 的两条（都写在 96 §5.1 的"放什么"里）

**（一）"项目块"过滤会让 92% 的行为消失。** 实测 `SELECT project, COUNT(*) FROM tool_activity GROUP BY 1` → `(NULL) 25,391 / anyi-studio 1,996 / 大肥鱼生命系统 291`。24h 切片同理：未归属 1,829、`大肥鱼生命系统` 151、其余为 `anyi-studio`。96 §5.1 只写了"上 5 个项目"，没写"剩下 74.8% 归哪"。**这不是数据缺失，是这一刀本身稀疏**：`tool_activity` 的 `project` 列由采集侧按会话档期回填，而档期 `project` 有 217 条记成了"未分类"（`project_stints WHERE to_ts IS NULL GROUP BY project` 的第一名）。

**（二）"看板块"若按 post 过滤，等于给用户一个空屏。** 今日 `period_key='261123'` 的 open 板共 5 块，登记数分别是 `未分类 0 / root 0 / 大肥鱼生命系统 7 / anyi-studio 0 / CZHY 17`。而按会话反查动作：board 153 → 177 条、154 → 473 条、155 → **1,519 条**（24h）。**同一个点击，两种语义差 500 倍。**

### 1.2 新增五条（设计直接依赖）

**（三）"谁"这件事天然缺一半：`tool_activity.citizen_id` 84.5% 为空**（23,387 / 27,688），`session_key` 则一个不缺（0 空）。`push_log.citizen_id` 空 509 / 5,794；`board_posts.citizen_id` 一个不缺，但 `session_key` **整列为空串**（445/445）——所以"按板上会话反查登记"这条 join 走不通，板过滤只能反向（先有会话集，再取该板的 post）。首屏 40 条抽样：`citizen_id` 缺失 11 条（27.5%）。

> 结论：**主行不能只有"人名"一种身份。** 有公民 → 名字；没有 → **会话标识**（`dsh#88f9`），并且两者在视觉上必须能区分（不是"未命名"——那会让人以为真有个叫未命名的参与者）。

**（四）命名有两份实现，规则还不一样（K8 现场）。** `fish_ui.py:98 session_tag` 固定取会话键末 4 位，`:112 readable_name` 把它拼进人名 → `名字·dsh#88f9`；而 `fish_board.py:1150 citizen_labels` 的 docstring 写明自己是"**人类面的唯一取名入口**"，三条规则是 `名字` / `未命名·host` / `名字·host#2`，底层唯一实现是 `fish_naming.disambiguate:168` + `base_label:139`，并且"`citizen_id` 参数刻意保留但从不使用"（`fish_naming.py:142`，即**绝不吐 ID**）。`fish_naming.session_short:251` 才是会话短标识的唯一实现，还带 4→6→8 避撞阶梯（`:281`）。

**本文裁决：主行"人"用 `base_label` + 批消歧；"会话"用 `session_short` 单独一列。** 96 §7 表里"短署名 `名字·宿主#4位`"的说法废弃——它把"谁"和"哪个会话"粘成一个词，后果可判：同一公民开 3 个会话，96 方案渲染出 3 个不同的主行名，用户会当成 3 个人。

**（五）"在跑"的读数会自己变，别把它写成常量。** 同一台机器 12:34 → 12:41 之间，近 30 分钟活跃会话从 4 变 5，24h 内从 34 变 35。所以 A-5 的判据（"窗口 30 → 1440 数字必须变"）必须跑在**同一时刻的同一份结果**上，不能跨轮比。

**（六）`tool_activity.host` 这一列不能当"宿主"用——它和 `session_key` 前缀打架。** 实测交叉表：`host='workbuddy'` 而 `session_key` 前缀是 `codebuddy` 的有 **26,994 行**；`host='dsh'` 且前缀 `dsh` 只有 697 行；`host='codebuddy'` 1 行。**一致率 698 / 27,692 = 2.5%**。而按前缀统计恰恰是 `codebuddy: 26,995 / dsh: 697`——这正是 96 §四口径一说的"两个名字"，但它把来源记成了 `host` 列，而 `host` 列真实取值是 `workbuddy / dsh / codebuddy`。

> **裁决：宿主一律取 `session_key` 的前缀（机器证据），不取 `host` 列、不取 `citizens_all.host`（自报）。** 这条规则 `fish_ui.py:210-212` 已经写着并给了理由（"两者不同时以前者为准"），本文沿用它；`host` 列如需展示只作"账号归属"，且必须与宿主分开显示。不改这条的后果可判：同一行会同时出现 `workbuddy` 和 `codebuddy#958a`，用户会以为两套系统在打架。

**（七）推送效果今日"判不出"，必须能显示"判不出"。** 24h 内 618 次推送全部 `reaction IS NULL`（`fish.push_stats(days=1)` → `total=618 accepted=0 pending=618 accept_rate=None`）；30 天口径才有值（`accepted=87 / ignored=4,993 / pending=710 / accept_rate=1.72%`，`:8143` 用 `decided = accepted + ignored` 当分母，空时回 `None` 不回 0）。**这是应用自己的口径，UI 直接复用，不另算。**

## §A 信息架构

### A1 三栏为什么是这三栏

三栏分别锁住一件**互不重叠**的事，且对应三个不同的时间尺度：

| 栏 | 回答 | 时间尺度 | 不在这里会怎样 |
|---|---|---|---|
| 左 切片器 | 我按哪一刀看 | 无（元信息） | 项目/板的信息只能塞进中栏行内 → 每行重复，40 行重复 40 次 |
| 中 流水 | 刚才发生了什么 | 过去 24h | 只剩读数，用户无法验证任何一个数字 |
| 右 判断面 | 我该做什么 / 这条是谁 | 现在 / 那一条 | 读数与详情争主区（96 §5.3 已判：右栏加宽就抢中栏） |

**为什么三栏能覆盖"看见系统在动"**：主任务 A 要答三问——"几个会话在动"（右·页签一）、"最近一次动作何时、做了什么"（中）、"动在哪个项目"（左）。三问各落一栏，**没有一问需要跨两栏拼**；这是三栏而非两栏或四栏的判据。四栏就必然会有一栏"内容为空时也得占位"（96 §11-7 的减法理由）。

### A2 左栏：保留两块，改三件事

用户点名"上面项目块、下面看板块"，**位置与名字都不动**，只改内容与语义——这是可判的最小改动，不是重画。

**上块「项目」**：按 `lastTouchedAt` 降序取前 3，**外加一个"未归属"项**（当 `project IS NULL OR project=''` 的 24h 条数 > 0 时出现）。数据：`未归属 1,829 条`，这一项是左栏**最大的一格**，不加它用户永远点不到占 74.8% 的那部分行为。

**下块「今日板」**：只列 `period_key = 当日` 且 `status='open'` 的板，按"有登记或有人在跑"优先取前 3，其余折叠为"其余 N 块（展开）"（一层折叠，1 步，符合 `structure.md §2` 的"一层 ≤1 步"）。

**改的三件事**：

1. **加"未归属"**（理由见 §1.1一）。
2. **板的作用域从"登记"改成"板上会话的行为"**（理由见 §1.1二）。定义写死：`board b` 的作用域 = `{tool_activity | session_key ∈ sessions(b)} ∪ {push_log | 同上} ∪ {board_posts | board_id=b} ∪ {events | json_extract(payload,'$.session_key') ∈ sessions(b)}`，`sessions(b) = SELECT DISTINCT session_key FROM presence WHERE board_id=b`。代价必须说出来：events 只有 **846 / 2,978（28.4%）** 能按会话归属（仅 `session.opened 515 / git.commit 329 / session.closed 2` 三类带 `session_key`），所以板视角下的系统事件会明显少于全局视角，界面必须写"另有 N 条系统事件无法归属到会话，未显示"。
3. **加一行常驻"当前切片"状态行**（可点即取消）。96 §11-7 删掉了"全部/全部项目"入口，代价是用户筛完不知道在哪退出；这行是 0 记忆负担的出口，也是深链的可见回显。

**为什么不做"进行中的事 / 需要人的事 / 刚发生过的事"三分组**：这三组是**任务分类**，不是**作用域**；"需要人的事"是右栏页签一的职责（dsh-superagent 原则：需要人处理的东西只出现一次）。放进左栏的后果可判：同一件事在左右两栏各出现一次，用户每次都要判断"点哪个"，决策点 +2 而无一条任务变短。

**可报表（单位声明：决策点 = 需要做选择/判断的可点控件，列表行与正文不计——按 `structure.md §4.0/4.3` 同一口径重数）**：

| 版本 | 首屏决策点 | 明细 |
|---|---|---|
| 默认解（96 §三草图） | **16** | 4 张 KPI 卡 + 5 项目 + 5 板 + 1 "点开才出现"的页签 + 1 属性表面板 |
| 96 规格 | **12** | 5 项目 + 5 板 + 2 页签（KPI 已收进页签一） |
| 本文 | **9** | 1 状态行 + 3 项目（含未归属）+ 3 板（+1 折叠）+ 2 页签 |

96 写的"桌面 11 → 7"与上表不可比（它没有单位声明）。本文按同一口径重数：**默认解 16 → 本文 9，其中核心任务的决策点一个没少**（筛项目、筛板、切页签、切时间窗全在首屏）。

### A3 中栏五类：按"行为者与方向"分类，不按数据表分类

96 §六按来源表分五类（工具/看板/推送/记忆/系统），本文按**谁对谁做了什么**分五类。差别在于：同一个"记忆事件"，96 归"记忆"，本文归"他记了"——因为用户看到一行时先问"这是谁干的"，再问"这是哪张表"。

| # | 类 | 行为者 → 对象 | 图标语义 | 一句话模板 | 合并/折叠 | 点击后 |
|---|---|---|---|---|---|---|
| 1 | **他动了**（做了） | 会话 → 文件/命令 | 终端（exec 系）/ 铅笔（edit）/ 落笔（write） | `{谁} 改了 {pathLabel}`｜`{谁} 执行了命令` | 同会话 60 s 内连续 ≥3 条折 1 行 | 页签二 |
| 2 | **他记了**（说了） | 公民 → 板 | 便利贴 | `{谁} 在 {板} {kind 词}：{text 首行 60 字}` | 不折（全库仅 445 条） | 页签二 |
| 3 | **他记下了/取用了**（记忆） | 公民 → 记忆 | 方块 | `{谁} 记下/取用/退役了 {code}` | `memory.accessed` 只显示 `codes[0]` + `共 N 条`（实测 `codes[]` 可长达数十项） | 页签二 |
| 4 | **我们推了** | fish → 公民 | 信封 | `fish 推了 {code} 给 {谁}` | 同 code 连续推送折叠 `×N` | 页签二 |
| 5 | **发生了** | 系统/会话 | 点 | `{谁} 提交了 {sha8}「{subject 首 40}」`｜`开了一个会话`｜`登记了一个公民`｜未登记类型显示 `type` 原值 | 不折 | 页签二 |

**类 5 里只有 `git.commit` 有真内容**（payload 实测含 `sha/repo_id/subject/committed_at/author_email`，329 条），所以它单独给模板；`config.changed 129 / maintenance.pruned 20 / profile.proposed 18` 归"发生了"并按原值显示 `type`，**不翻译成看不见原文的"系统动作"**（96 §六同款纪律）。

**排序与去重（写死，不依赖字段遍历顺序）**：五源按 `sk` 单键降序（见 §C2），`sk = ts|(9-rk)|pad12(pk)`，其中 `rk` 是源优先级 `tool=0 / post=1 / push=2 / event=3`（输入→响应→结果）。实测 3 次重跑逐键完全一致；首屏 40 条里就有 **4 组同秒**并列，所以这不是理论问题。跨源二次去重**不做**（`git.commit` 与"某人跑了 git commit"无法用字段证明同源，猜着去重会删真行为）。

### A4 右栏页签一：改成"需要你的"优先

dsh-superagent 的原则是"面板只显示什么需要人"。落在这份数据上，**真正需要人的只有三件**，其余都是读数：

| 序 | 区块 | 回答 | 数据（实测） | 空的时候 |
|---|---|---|---|---|
| 1 | **要你收尾的** | 哪些档期开了没关 | `project_stints WHERE to_ts IS NULL`：305 条 / 18 项目，最老 **29 天**（未分类 217、CZHY 40、大肥鱼 24） | "没有开了没关的档期" |
| 2 | **要你确认的** | 说了在做但没动手的会话 | `presence.auto_source` 分布 `session_start 340 / remember 108 / activity 12 / null 67`；340 条 `doing` 全是同一句"（自动登记：会话开始，尚未声明在做什么）" | "所有在跑的会话都说清了在做什么" |
| 3 | **要你决定的** | 推的东西有人看吗 | `push_stats`：30 天 `accept 1.72%`、`pending 710`；今日 `pending 618`、率 `None` | "还没推过内容" / "今日推送都待回填，率判不到" |
| 4 | 现在有什么在动 | 在跑 / 最近来过 | 实测 12:41Z：在跑 **5** 个会话、24h 来过 **35** 个；量词固定"会话"（`presence` 是会话级，写"人"即口径造假） | "现在没有会话在动（最近一次动作：<时间>）" |
| 5 | 读数（默认折叠） | 工具用量 / 公民构成 / 热推 / 热搜 | 24h 工具：`edit 1,125 / bash 977 / write 262 / pwsh 84`；公民 `visitor 283 / role 48 / resident 7` | 各块自己的空态 |

**为什么把"在线"从第一挪到第四**：96 §7① 把它排第一的理由是"唯一不许撒谎的区块"——那条纪律保留（量词、窗口、三口文），但**位置由"是否构成决策"决定**：在跑 5 个会话不构成任何待办，而"217 个档期最老 29 天没关"构成待办。A-5 的判据（窗口改 → 数字变）与位置无关，改动不削弱它。

**热推必须带率**（用户/主理人硬要求）：最热 code 推了 **1,986 次**、采纳 **5 次**、`ignored 1,573`、`pending 408` → **0.3%**。只给次数的榜单会把"持续骚扰"排成"最受欢迎"。

**每块标题右侧的"来源 + 口径"入口保留**（A-12 落点），点开见表名与时间窗。

### A5 右栏页签二：从属性表变成三段账本（Tobs 原则）

Tobs 的启示是"记忆是一个可翻阅、可 diff 的仓库"。fish 没有 git 化的记忆，但**有能对上账的字段**，所以账本是三段，不是八行属性：

**段一 · 这一条**：类型 · 一句话（同中栏模板，**不另写一套措辞**）· `pathLabel`（渲染顺序 `path_dir → path_abs → path`；实测 `path IS NULL` 有 **5,555 行（20.1%）**，见 §F-R4）· `ok`（实测 `1: 26,911 / 0: 761 / NULL: 7`，`0` 显示"未成功"）· 时间（`HH:mm:ss` 等宽）。

**段二 · 这个人**：`base_label` 名字（无公民时显示"会话 `dsh#88f9`"并标"该条没有公民归属"）· 宿主（**一律取 `session_key` 前缀**，理由见 §1.2六；三个候选源口径全不同：`session_key` 前缀 `codebuddy 26,995 / dsh 697`、`tool_activity.host` 列 `workbuddy 26,993 / dsh 697 / codebuddy 1`、`citizens_all.host` `dsh 253 / cli 61 / workbuddy 11 / codebuddy 7`——并置任意两个都会自相矛盾）· 在不在跑（`presence` 三组）· **声明面 vs 实际面并列两行**（`surface` / `auto_surface`，不一致标"说的和做的不一样"；实测有一条 `surface='I:\app\fish\ui, I:\app\fish\p0'` 而 `auto_surface=''`、`session_surface='i:/app/fish/p0,_deploy,…'`——三种面都在）。

**段三 · 他的账本（按天分组，最近 5 天）**：每天一行摘要——"`11-23`：改 47 处、执行 12 条命令，涉及 8 个目录；2 条登记"；点开当天明细；**同一路径连续改动聚合成 `改了 N 次`**（这就是 fish 版的 diff 感，不需要 diff 引擎）；`git.commit` 的 `subject` 按天列在账本行尾（可翻阅感）。

## §B 交互模型

### B1 过滤：单选 · 点即筛 · 再点取消

状态机（写死为一个枚举，不是两个独立开关）：

```
scope = ALL | PROJECT(name | "__none__") | BOARD(id)
click(project p):  scope == PROJECT(p) ? ALL : PROJECT(p)
click(board b):    scope == BOARD(b)   ? ALL : BOARD(b)
click(statusline): ALL
```

**为什么单选而不是"项目 + 看板"可组合**：两者是两条不同的切片轴；组合后语义没人要（"大肥鱼项目里的 CZHY 板"），却要多一层状态与一组空集分支。判据：`scope` 的类型里**不出现两个条件同时成立**的分支——代码里出现 `if project and board` 即红。

### B2 选中与页签：返回是一步

`selected = null | {key}`。单击 → `selected` 置位 + 页签切二；**再点同一条不取消**（避免误点后右栏空白，96 §5.2）。手动点页签一 → **选中保留**（"选中是当前这条，页签是看它的哪个面"，96 §8）。`Esc` → 清选中 + 回页签一（**一步到底，不是两级返回**）。深链可复现（B6）。

### B3 时间范围：三档，服务端重查

默认 **24h**；可选 `7d` / `全部`。切换 = 服务端重查 + 游标重置，**不就地裁**：24h 是 3,404 行，全库 36,892 行（4 源合计），前端持有全量既无必要也不可能（虚拟滚动只留窗口内）。实测三档耗时：24h 27.3 ms、全库 12.7 ms（热缓存）。

### B4 轮询：不打断阅读

2 s 轮询 `?since=<栈顶 sk>`，只取"比栈顶更新"的条目。三条规则：① **绝不自动滚顶**；② 用户不在顶部时，顶部出现"N 条新行为（回到最新）"，点击才插入并滚顶；③ 缓冲上限 200 条，超出只更新计数（不无限堆内存）。空增量实测 0 条、耗时同首屏。

### B5 键盘

| 键 | 落点 | 说明 |
|---|---|---|
| `/` | 聚焦左栏切片器第一项 | **不是搜索**：96 §11-4 明确不做全局搜索框，任务书的"`/` 搜索"与上游减法冲突，本文按减法办（见 §G-D3） |
| `j` / `k` | 中栏下一/上一条（行内 `tabIndex=0`，焦点跟行走） | 到底不循环 |
| `Enter` | 等于单击：选中 + 切页签二 | |
| `Esc` | 清选中 + 回页签一 | 焦点回到中栏当前行 |
| `1` / `2` | 页签一 / 页签二 | 不改变选中 |
| `g` / `G` | 栈顶 / 栈底 | 栈底即已加载的最早一条 |

### B6 深链

`#/w?scope=project:anyi-studio&win=24h&sel=tool:40424&tab=detail`。用 hash 而非 path：生产由读口 `--dist` 同源发静态（93 §3.10.9），hash 不触发服务端请求，**静态服务不需要 rewrite 规则**。判据：刷新页面后"切片、窗口、选中、页签"四件事同时复现；把 `sel` 换成不存在的 key → 页签二显示"这条已不在当前窗口内"，不是白屏。

### C1 契约总则（沿用 93 §6，不另起一套）

信封 `{schema, asOf, availability:{state,detail}, data, error?, sources:[{source,ok,rows,error,ms}]}`；出参 camelCase；`capabilities[]` 发现能力；错误码 `200/400/403/404/405/503`；只读连接必须 `open_readonly()` + `assert_write_rejected()`（`fish_ui.py:66`、`:76`）。**新端点进 `p0/fish_ui/`（93 §3.2 包），不进 `fish.py`**——它只剩 1 行余量。

### C2 `GET /api/stream` —— 五源合流（实测 SQL 如下，照抄可跑）

| 项 | 值 |
|---|---|
| 入参 | `scope=all\|project:<name>\|project:__none__\|board:<id>`、`win=24h\|7d\|all`、`since=<sk>`、`limit`（默认 40，上限 500）、`types`（可选 CSV） |
| 出参 | `items[]`（每项 `key/src/rk/ts/sk/actor{name,labelKind,citizenId,host,sessionTag}/project/tool{name,action,ok}/path{dir,abs,raw,label}/text/meta`）、`cursor`（栈顶 `sk`）、`counts{total,inWindow}`、`fold{groups,covered}` |
| 游标 | 单键 `sk`，见下；`since` 给栈顶 = 取更新的；翻页给栈底 = 取更旧的 |
| 缓存 | 无（每请求一连接，`BoundedSemaphore(8)`，拿不到回 503） |
| 错误码 | `400`（scope/游标非法）、`503`（连接超限或库不可读） |
| 实测 | 24h **27.3 ms**（n=3，首调 103.1 ms）；全库 12.7 ms；`project` 14.9 ms；`board 155` 9.2 ms；`board 153` 7.8 ms |

```sql
WITH u AS (
  SELECT 'tool' src,0 rk,a.id pk,a.seen_at ts,a.host,a.session_key,a.citizen_id,a.project,
         a.tool_name,a.action,a.path,a.path_dir,a.path_abs,a.ok
    FROM tool_activity a WHERE a.seen_at >= :since
  UNION ALL
  SELECT 'post',1,p.id,p.created_at,NULL,p.session_key,p.citizen_id,NULL,NULL,NULL,NULL,NULL,NULL,NULL
    FROM board_posts p WHERE p.created_at >= :since
  UNION ALL
  SELECT 'push',2,l.id,l.pushed_at,NULL,l.session_key,l.citizen_id,l.project,NULL,NULL,NULL,NULL,NULL,NULL
    FROM push_log l WHERE l.pushed_at >= :since
  UNION ALL
  SELECT 'event',3,e.seq,e.ts,NULL,
         json_extract(COALESCE(e.payload,'{}'),'$.session_key'),
         json_extract(e.actor,'$.citizen_id'),
         json_extract(COALESCE(e.payload,'{}'),'$.project'),
         NULL,NULL,NULL,NULL,NULL,NULL
    FROM events e WHERE e.ts >= :since
)
SELECT src,rk,pk,ts, ts||'|'||printf('%d',9-rk)||'|'||printf('%012d',pk) AS sk,
       host,session_key,citizen_id,project,tool_name,action,path,path_dir,path_abs,ok
FROM u  __WHERE__  ORDER BY sk DESC LIMIT :limit;
-- 翻页：__WHERE__ = 'WHERE sk < :cur'   轮询：__WHERE__ = 'WHERE sk > :cur'
```

**为什么是单键 `sk` 而不是三键元组**：`ts` 只到秒且同秒真实存在（全库 1,017 个时间戳有多行，首屏 40 条里 4 组）。`rk` 在 SQL 里是**优先级升序**、`pk` 是**降序**，两个方向不同，用行值 `(ts,rk,pk)` 比较会有一个方向反掉——我第一次就写反了，实测 `sortKey != tuple 顺序`，改正后逐键一致。单键字符串把三个方向拍平：`sk` 越大越新，翻页 `sk <`、轮询 `sk >`，**一个比较符，没有组合条件**。

**为什么不是"五源各自拉再前端合并"**：那是第二份领域实现（93 §2.1 记的 K8 死法），且五个 `asOf` 会混进一屏。实测一条 SQL 的代价是 27 ms，没有理由拆。

zustand 五个切片，**互不越界**：`scope`（枚举 + 时间窗）、`facets`（10 s）、`stream`（2 s，含 `items/cursor/buffer`）、`selection`（`selectedKey` + 派生 `entry` 缓存）、`stats`（60 s）。轮询节拍：`stream` 2 s、`facets` 10 s、`stats` 60 s、`entry` 只在选中变化时拉（30 s 缓存）。**切后台标签页全部降到 30 s**（93 §4.3）。游标只放内存，不进 localStorage（清掉必须能重连）。

### D4 虚拟滚动与折叠

`VirtualList` 唯一封装，`estimateSize` 行高：单行 56 px、折叠行 56 px（同高，避免滚动抖动）。折叠在**后端算**（`fold` 字段），前端只渲染——理由：折叠要跨源比较"同会话是否连续"，前端算就是第二份实现。

**折叠实测（24h，工具源 2,444 行 / 35 会话）**：527 组，其中可折 **245 组覆盖 2,073 行**，折后剩 **616 行**；最大一组 **72 条**（同一会话 60 s 内连做 72 个动作）。不折叠的后果是那一个会话占首屏 57.6%。**展开后原地显示，不跳位**，折叠条按组内最新时间参与排序。

### D5 三态与四种空态落点

服务端给 `availability.state`，前端**不推断**（93 §4.4）：`ok` 正常｜`empty` 空库 + 写入命令｜`missing` 缺表/缺库 + `sources[].error` 原文｜`partial` 有数据的格正常 + 缺的格"缺 `<cap>`"｜`error` 三段（出了什么/为什么/你能做什么）｜`unreachable` **整屏**"读口未起 + 启动命令 + 重试，不显示任何数字**。

四种空态四句话不同（96 §九，判据 A-10）：① 读口未起（整屏）；② 库为空（每块）；③ 筛选后无结果（带"清除筛选"，且**必须回显筛选条件**）；④ 窗口内无行为（带"看更早"）。③ 与 ④ 之所以必须分开：一个是"我筛错了"，一个是"系统真没动静"，下一步动作完全相反。

### D6 设计令牌（Tailwind 4 `@theme`）

| 类 | 刻度 |
|---|---|
| 间距 | 4 / 8 / 12 / 16 / 24 / 32 / 48（px） |
| 字号 | 12（元信息/时间列）/ 13（副行）/ **14（正文与主行）** / 16（区块标题）/ 20（页标题） |
| 字重 | 400 正文 / 500 主行姓名与数字 / 600 区块标题 |
| 颜色 | 中性 9 阶（`--n0`…`--n8`）+ 1 强调（`--accent`）+ 3 状态（`--ok/--warn/--err`） |

**等宽只给机器标识**：时间列、`pathLabel`、`sha8`、`code`、会话短标识；中文正文无衬线（96 §一 已判）。同屏字号 ≤4 种、字重 ≤3 种、灰阶 ≤4 种（93 §4.5 的代理指标）；对比度用 WCAG 公式脚本逐对算，不靠眼。

### D7 动效表（只表达状态，≤4 条）

| 动效 | 表达什么状态 | 时长/曲线 |
|---|---|---|
