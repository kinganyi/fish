## 3 · 发现清单

### 🟡 警告（4）

#### 🟡1 [🟡] S3 的"坏值**一律**回落默认 + 一条诊断"不成立：`push.rerank_weights` 里的 NaN/Infinity 既不回落也不诊断，且会**静默清空注入**
- **位置**：`p0/fish_push_rerank.py:142-146`（`out[name] = float(value)` 没有 `math.isfinite` 守卫；而同一文件的 `_cfg_any:110-112` 对**数值默认值**是有这道守卫的）；`p0/fish_push_rerank.py:384`（`float(_cfg_any(...))` 在 `_breaker` 里裸转，无 try）
- **问题**：JSON 标准之外但 **Python `json` 接受**的 `NaN`/`Infinity`/`1e999` 会让权重变成非有限数 → `combine_features` 得 `nan` → `select_push_candidates` 的 `score > 0` 把**整池**过滤掉 → 注入包空；全程**无异常、无诊断**。这正是 D3/S3 想消灭的"配置写了没生效/整包消失"两种形态的合体。另：`_cfg_any` 在**已登记**键上直接返回 `get_config` 的结果（不做类型复核），若 A 把这 4 键登记成 `text` 而不是 §9 表里的 `bool/int/string(JSON)/float`，则 `bool("false")==True`（重排被误开）、`float("abc")` 会在 `_breaker` 抛出——**"坏值不抛"只对"登记类型与 §9 表一致"这一前提成立，而该前提没写进 §9**。
- **证据**：隔离副本探针（`project=TESTA`，2 条候选，config 写 `push.rerank_weights='{"relevance": NaN}'`）：
  ```
  [B] NaN 权重：scores=[nan, nan] nan数=2 诊断条数=0 选出=0
  [C] 已登记键坏值：top_k=50 breaker=3.0 select=no-raise selected=2 诊断=['push.rerank_top_k','push.breaker_seconds']
  [D] now='昨天下午' → dup_penalty=0.2 诊断=['now']
  ```
- **建议**（都很小）：`out[name]` 赋值后加 `if not math.isfinite(out[name]): _diag(...); out[name] = default[name]`；`_breaker` 的 `float(...)` 包一层 `(TypeError, ValueError)` → 默认值 + 诊断；交付 §9-1 补一句"**登记类型必须与下表逐字一致**（`text` 类型会让 `_cfg_any` 的转换失效）"，并补一条"NaN/Inf 权重 → 回落 + 诊断"的判据。
