# dsh-fish 减重清单（2026-11-09）

> 依据：用户 2026-11-09 拍板「DSH 侧插件降为**只读 + 本体能力补充**」+「DSH 更新频率高、破坏性大，插件侧要**轻**」。
> 分析基线：`dev/dsh-fish` @ `6e02c08`（架构师只读实测，未改任何文件）。
> 判据不是"文件大小"，而是：**① 是否服务于只读+UI 定位；② 是否增加跟随 DSH/fish 演进的耦合面。**

---

## 0 · 主理人裁决（先看这个，架构师把 5 个待决项交上来了）

| 待确认项 | 裁决 | 理由 |
|---|---|---|
| **面板（client）去留** | **留** | 用户明确定位「UI 是补充」。接受因此 A 组耦合点降不到 4（留 13→9） |
| **7 条 `proxy-readonly`**（`list`/`events`/`neighbors`/`citizen-list`/`push stats`/`push status`/`workspace seed`） | **留**（`ports/python.ts` 因此不砍） | 前三项是纯只读查询，面板与人都可能要；砍了体验倒退 |
| **`domain/inject.ts`（49.7 KB，连带 224 KB）** | **砍** | Python 的 `fish inject` 仍是权威；"面板展示模型看到什么"有价值，但 +224 KB 且是 fish 口径漂移最频繁的一块，与"轻"冲突 |
| **`.tmp/`（307 文件 / 4,715 KB）** | **先查归属，查不到就删** | 全在 gitignore；但 `.tmp/dsh021/`（225 文件）疑似另一个会话的 DSH 0.2.1 升级调查产物 |
| **`docs/面板架构设计.md`（62 KB）** | **留** | 面板是定位载体，它是下一期「接真数据」的唯一设计依据 |
| **`schemaTableHash` 预期值由谁生成** | **留 20 行 `dump-schema-names.mjs`** | 手写易腐；生成器可重跑、可 review |

**由裁决推出的"不做"清单**：砍掉 `inject` 后 `/fish shadow inject` 消失（改指 `fish inject`）；面板保留故 `client/index.ts` 与 `tsdown` 的 3 个最难点（`__ModuleLoader__` banner / `viewArea` 布局 / `provide('fishClient')`）**必须继续跟**。

## 2 · 逐目录裁决

### 2.1 `spec/`（9 → 1）

**最关键的事实：`spec/` 在运行时一处也不驱动行为**（`cutTokens` 用代码里的 `DEFAULT_CUT_RULES`、注入段名是常量、CLI 裁决在 `CLI_ANNOTATIONS`）。它唯一作用是"门禁自证"。

| 文件 | 裁决 |
|---|---|
| `contract.json` | **降级** → 只留 `contractVersion` + `minHostVersion` + `schemaTableHash` |
| `schema.fingerprint.json` | **降级** → 逐对象 DDL 摘要改为「业务表名集合 hash」；漂移从 fail 改 warn |
| `events.json` / `tools.json` / `injection.json` / `cli-map.json` / `corpus.schema.sql` / `schema.sql` | **砍** |
| `layout/cut.json` | **降级** → 只留 6 组向量当 smoke（规则已在代码里） |

⚠️ **必同步**：`loadSpec()` 是刚性失败路径（缺一个文件就抛）→ 砍 spec 必须同时改 `ports/spec.ts` 的 `SPEC_FILES`/`loadSpec` 与 `core/contract.ts` 的摘要校验。
